## 1. Not right (wrong behavior today)

### 1.1 Commit-window joins compare local-offset git timestamps against UTC transcript timestamps, lexicographically — **the v0.43 flagship is skewed on your own machine**
`cage/commitjoin.py:89` builds windows from `git log --format=%h|%cI` — `%cI` carries the **committer-local offset** (`2026-08-02T12:00:00+05:30` on your IST machine). `window_for` then does plain string comparison (`w.lo < ts <= w.hi`) against transcript/call timestamps that are UTC `...Z`. String order across different offset representations is meaningless:

- On IST, a commit at 09:00 IST renders `...T09:00:00+05:30` = 03:30Z; an edit at 05:00Z (10:30 IST, *after* the commit) string-compares **below** it and lands in the wrong window. Every edit and every window-joined call shifts by the offset.
- Even pure-UTC repos break at the boundary: `"…T10:00:00.000Z" <= "…T10:00:00+00:00"` is False (`.` sorts above `+`), so a same-second edit falls into the next window. The test only passes because it compares byte-identical `+00:00` strings.
- Mixed-offset histories (local commits + GitHub-web/CI `+00:00` merges) additionally mis-sort `pairs.sort`, producing out-of-order windows.

Same pattern at `commitjoin.py:99/291` and `authorcapture.py:107`. Fix: one normalization (`datetime.fromisoformat` → UTC) at window build and at every comparison — `commitview._iso` (line ~62) already does exactly this for `--since`. **Verified directly; high confidence. This is the most important finding in the range** — it corrupts agent-vs-human attribution for any non-UTC committer, which is you.

### 1.2 Copilot CLI: credit delta silently lost when the first-listed model has no token delta; multi-model shutdowns double-count
`cage/transcript.py` ~459–467: `if not (din or dout): continue` runs **before** `credits=cred_delta if i == 0 else None` — but `prev_cred` has already advanced. Scenario: shutdown 1 uses model A; the resume uses only model B. In shutdown 2, A is still index 0, has zero delta, gets `continue`d — the credit delta lands on **no row**, permanently, with no debug log. (Same latent hole drops the legacy `premium` delta.) Verified directly.

Second defect in the same loop: `totalPremiumRequests` is computed by GitHub over **all** models in the shutdown, but cage stamps the whole delta on row 0 while sibling rows re-price the same billed usage via the token rung — so the copilot total is credits + tokens for the *same* consumption, which is neither basis. The shipped fixture (`tests/fixtures/transcripts/copilot/cli/expected.json`) is exactly this shape. The v0.44 handoff's "totals correct" claim doesn't hold for the multi-model case.

### 1.3 `cage insights adoption --since` is only month-granular for half B
`cage/adoption.py:188`: half A row-filters (`ledger.since(usagelog.read(root), since)`, line 105) but half B does `ledger.receipts(root, since=since)` with **no row-level filter** — `ledger.receipts(since=…)` only skips whole month-shards. On Aug 30, `--since 7d` counts every savings row from Aug 1–23 in the coverage %, agent tables, and the NO_EVIDENCE/NOT_ATTRIBUTED decision, while half A correctly drops them — the two halves of one view describe different windows. On a legacy unpartitioned `receipts.jsonl`, `--since` has no effect on half B at all. The test (`test_since_windows_both_halves`) masks it: its stale row sits in a fully-skipped month (2020-01). Verified directly.

### 1.4 OTel export fabricates `cage.saved_usd: 0.0` for unpriced models — the $0 bug class again
`cage/otelout.py:85`: a token receipt linked to a call whose model has no price row bypasses the ladder and lands in `convert.saved_usd` → zeros row → exports `0.0`, which the module's own contract (lines 30–33: "omitted, never zero… when the ladder refuses") forbids — and this format has no UNPRICED ⚠ footer to correct it. Reproduced by the reviewer with a live call. This is the same silent-$0 family as the old policy-table exact-match bug.

### 1.5 Turning hooks off leaves `{"hooks": {}}` residue behind
`cage/claudewire.py:175`: plain `cage setup` (hooks off) routes through `_strip_stale_hooks`, which leaves `{"hooks": {}}` — and the cage-created file itself — behind, violating the documented "emptied table is dropped, file reduced to `{}` is removed" contract. `_wire_hooks(root, False)` implements the right behavior but is never called from the off path. Reproduced: install with hooks, then plain install → permanent committed-diff residue; the two-way-switch test only asserts `hook_status == 0`, so it passes.

### 1.6 `cage insights compare` labels credit-priced dollars "measured"
`cage/compare.py:129,160`: group USD now flows through the credit rung (`taskgroup` → `prices.call_usd`), which is `modeled` by the feature's own law (`creditprice.method_for`). Report and chats degrade to `modeled`; compare's header and CSV `method` column still say `measured` — a configured rate reading as an invoice, the exact failure the credits design names.

### 1.7 Edit context lines counted as agent "suggested" lines
`cage/transcript.py:223–238` (`_proposed_lines`) counts the whole `new_string` of an `Edit`/`MultiEdit`, but never reads `old_string` — so the unchanged context lines the agent quoted for match-uniqueness are counted as proposals. A one-line Edit with 3 context lines reports suggested=4, kept=1, kept_modified=3 — Edit-heavy sessions systematically read as "human modified most of it". Worse, the direction ADR 0008 claims impossible is open: if the same commit relocates those pre-existing lines, the human's lines match the agent's "proposal" and are credited as `agent_lines`. Subtracting `old_string ∩ new_string` normalized lines closes both.

### 1.8 Smaller confirmed items
- `cage/wiringscan.py:554` — `inventory()`'s `covered` set uses spec displays carrying " (L1 hooks)" suffixes that never match `committed_artifacts()`'s bare displays, so every wired L1 hook re-surfaces as a duplicate "leftover" row in `cage doctor --wiring`.
- `cage/otelout.py:59` — export emits `gen_ai.system`, deprecated/renamed to `gen_ai.provider.name` before the semconv version the doc itself pins (`cage.meta.semconv: "1.42.0"`) — the pin and the payload disagree at ship time. (Medium confidence on exact 1.42.0 contents.)
- `cage/wiringscan.py:313` — `interceptor_dead` is one cross-twin flag: a stale twin for the *other* OS makes doctor claim **this** machine is unmetered and paints both twins dead; `refresh_shim` swallowing per-twin `OSError` means `cage setup` can never clear it.

## 2. Going to break (fine today, breaks under a foreseeable condition)

### 2.1 Dogfood freshness is a calendar bomb for the whole suite
`tests/test_dogfood_freshness.py:110` compares the committed snapshot date (2026-08-02) to the real wall clock with a 60-day ceiling. On ~2026-10-02, `pytest -q`, `just test`, and CI (which sets no `CAGE_SKIP_DOGFOOD_FRESHNESS`) go red on **every machine with no code change** — and an outside contributor can't self-heal because the snapshot derives from your personal `~/.cage`. Combined with the "green, or no release" rule, releases block on a docs refresh. Gate it on an env only the canonical repo's CI sets, or skip-when-not-maintainer.

### 2.2 Session-end auto-close rides a throttled, switchable sweep
`cage/hookcmd.py:60–65,129`: the session-end sweep goes through `importcmd.ensure_captured`, which is throttled to 60s and disabled entirely by `[capture] on_read=false` / `CAGE_CAPTURE_ON_READ=0`. If any cage read ran in the session's last 60s (common — reads update `_last_import`), the end-of-session sweep no-ops and the final turns' calls are missing when `_open_tasks` runs — auto-close, L1's headline feature, silently skips them. With `on_read=false` it never works at all. A lifecycle hook should call the unthrottled `importcmd.run`.

### 2.3 Exit-code collision: a future `cage hook` argparse failure = a deliberate BLOCK
`cage/cli.py:686–693`: argparse failures exit 2 — the exact code claudewire wires as the PreToolUse block verdict (`hookcmd.BLOCK = 2`). Hook *event* names have no verbmap-style migration path, so a future event rename + stale committed wiring → invalid-choice → exit 2 → Claude Code refuses **every Bash call** in the session. That inverts the fail-open contract at a boundary before `hookcmd.run` ever executes — worse blast radius than the F1 silent-exit class the codebase is built around. Worth an argparse-level catch that forces exit 0 for the `hook` verb.

### 2.4 Short-sha exact-equality joins rot as the repo grows
`cage/commitjoin.py:273`, `cage/commitview.py:221/229/267`: task snapshots (`rev-parse --short`), provenance rows, and attested hours all join by exact string equality of independently-abbreviated short shas. When git's auto-abbreviation grows from 7 to 8 chars (object-count threshold, or `core.abbrev`), every historical task join silently degrades to `DANGLING_TASK`, provenance rows orphan into `unmatched`, and attested hours fall back to the `~` estimate — breaking "an attestation always wins" with no refusal, and unrepairably (append-only log). The sha *filter* already prefix-matches; the joins should too — or store full shas.

### 2.5 Copilot L1 hook wiring rests on unverified event names and Claude-shaped payloads
`cage/copilotwire.py:38` + `cage/agents.py:65–68`: `sessionStart`/`sessionEnd` are, per the module's own comment, cage's invented names from v0.10, and auto-close needs a `session_id` stdin key that is Claude Code's shape. On a real Copilot install, either the events never fire or `_session()` returns `""` and auto-close declines every time — while `cage setup --status` prints "L1 hooks ×2" and `HOOK_GAPS` asserts auto-close is wired. Overstated capability on the surface whose rule is "every gap is named in output".

### 2.6 Line-ending gap: the POSIX graphify twin isn't pinned
`.gitattributes` pins CRLF for `graphify.cmd` only. A Windows contributor with `core.autocrlf=true` (installer default) gets a CRLF `cage/data/shims/graphify` in the working tree; `cage setup` byte-copies it into users' projects → `#!/bin/sh\r` "bad interpreter" on POSIX teammates, silently killing graphify capture. The byte-identical test can't catch it — it compares against the same corrupted bytes. One `text eol=lf` line fixes it.

### 2.7 Kiro's committed L1 hook is POSIX-only
`cage/kirowire.py:89–91`: the hook command is a POSIX-sh one-liner, committed byte-identical with no Windows twin and no doctor mention. A Windows teammate's Kiro errors per turn instead of failing open — unlike graphify (twinned, ADR 0007) and unlike the Windows MCP limit (named in doctor). Either twin it or name the gap.

### 2.8 `cage insights commits` default scales with the whole history
`cage/commitview.py:216–221`: no default `--since`, one full-patch `git show` subprocess per commit (`--unified=0` whole patch) for **all** windows regardless of the 20-row render cap, plus `w not in wanted` over a list (O(n²)). At 5–10k commits: thousands of subprocesses, minutes of wall time on the flagship no-args invocation. `wanted` as a set + a bounded default window are cheap.

### 2.9 Rest of the confirmed tail
- `cage/transcript.py:445` — a `totalPremiumRequests` that ever decreases (store rewrite, counter reset on resume) yields a negative `cred_delta` stored verbatim → negative dollars silently shrinking totals; nothing clamps or flags (NaN/Inf would also pass `json.loads`).
- `cage/commitjoin.py:76–106` — windows linearize the whole reachable history by timestamp; parallel branches interleave, so an edit can bucket onto the other branch's commit, score `dropped`, and the cursor marks it covered — permanent misattribution the linear-history design never names.
- `cage/authorcapture.py:105–107` — `_uncovered` judges coverage over **all** edits in a transcript including other repos', while the claude glob feeds every project's transcripts into every sweep: a repo you report on but rarely commit to re-parses the entire machine's transcript corpus on every read, forever. Scope `_uncovered` to this repo's edits.
- `cage/linematch.py:213/269` — quoted paths (`core.quotePath`, non-ASCII filenames) and rename syntax key the three maps differently → a landed `café.py` proposal scores `DROPPED`. `-c core.quotePath=false` + rename handling.
- `cage/claudewire.py:116/189` and `cage/copilotwire.py:57–58,83` — non-dict entries in a hand-edited hooks file raise `AttributeError`; `cage setup` dies with a bare exit 1 (reproduced). Also copilotwire deletes a foreign file whose `hooks` value isn't a dict.
- `cage/originrecord.py:95` — a sweep can freeze an authorship row from a partially-flushed transcript; the late-flushed edit dedupes away permanently (`(sha, agent, session, method)` idempotency), under-reporting with no diagnostic.
- `cage/data/shims/graphify.cmd:56–80` — both resolution passes run under delayed expansion, so a literal `!` in PATH or the install path corrupts `_CAGE_GF_REAL` and breaks graphify outright (violates "broken is worse than unmetered"). Edge case.

## 3. Better approach

1. **One timestamp normal form.** Finding 1.1 is a symptom: the range compares ISO strings from three producers (git `%cI`, transcripts, wall clock) in at least four modules. Normalize to UTC `fromisoformat` at every ingest boundary (commitjoin windows, authorcapture cursor, linematch, commitview already does it) and make raw-string comparison a lint-able offense. One helper in one module ends this bug class.
2. **Let `convert` own the unpriced-vs-zero distinction.** otelout re-implements USD dispatch and already drifted (the credits rung exists in `call_usd_match` but not there — 1.4 is the result). An Optional-returning `convert.saved_usd_or_none` used by every renderer keeps "omitted, never zero" in exactly one place.
3. **Full shas in stored rows, prefix-match at joins.** Tasks, provenance, and attestations should record full shas (they're free at write time) and views should prefix-match with an ambiguity refusal — this fixes 2.4 and also `cage insights commit <prefix>` silently rendering the newest of several matches (`commitview.py:208/464`) where git itself would refuse. And apply the documented 8-hex `ids.new_id` widening — the finding doc exists, the fix hasn't landed, and dedupe still eats collisions.
4. **Lifecycle hooks get the unthrottled sweep.** `importcmd.run`, not `ensure_captured`, for session-end (2.2). The read-path throttle is a read-path concern.
5. **`chats.py:93–94` reads the full ledger twice** when `--since` is set (`ledger.calls(root)` just for the `any_calls` boolean, then a second partitioned read), defeating the month-partition skip the docstring claims. Read once; `any_calls` needs only a shard-existence probe.
6. **`_agent_span` "measured" gate** (`commitview.py:155–157`): a single library-metered call (2s latency) among 30 transcript calls spanning 2h makes the agent span "2s measured" and prints the whole gap as estimated human hours — the exact refused failure mode the module's comment names. "Measured" should require latency coverage of the joined calls, not `any latency > 0`.
7. **cigraphify checks should be non-vacuous.** `check_derivation_is_deterministic` (`tools/cigraphify.py:807`) never asserts exit 0 or non-empty output — a crashing `cage report` passes ("" == ""). And `check_bare_graphify_is_intercepted` diffs rows by positional slice over sorted shards instead of an id-set diff (`graphifymeter._graphify_receipt_ids` already exists). Both are the vacuous-green failure the module exists to prevent.
8. **Adoption's UNJOINED reason blurs two unknowns** (`adoption.py:206`): a genuinely ambiguous shared-session receipt renders as "a capture gap worth chasing" — a false fact in the view whose purpose is never blurring unknowns. Add an AMBIGUOUS reason code.
