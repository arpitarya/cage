**Model:** **Opus** — the rename touches `Footprint.policy`, the single

gets stamped on a ledger row. Both are Opus per cage's CLAUDE.md rubric.

**Standing constraint: DO NOT COMMIT in `cage/`.** Leave the tree dirty.

## Read this before you start (it changes what you'd otherwise build)

**`[sources]` already exists.** `paths.resolve_log_sources` resolves import
locations with precedence **env > policy `[sources]` > built-in**, supports
per-source `paths` / `glob` / `replace`, two schema shapes (`[sources.<x>]` table
and `[[sources.<x>]]` array-of-tables), and custom tools via
`format = "claude|copilot|kiro"`. **Do not rebuild it.**

What's actually missing is narrower: a source cannot declare its **`surface`**.
`LogSource` is `path · glob · provenance · agent · fmt` — no surface — while
`transcript.parse_kiro_calls` hardcodes `surface="ide"` on every row. So pointing
cage at a *non-IDE* Kiro store today would silently stamp those rows `ide`. That
mislabel is the gap this task closes, plus making the effective sources
**discoverable**.

## Task A — configurable + discoverable sources

1. **`surface` key**, supported in both schema shapes, validated against the
   closed set (`cli`, `vscode`, `ide`, `""`). Absent ⇒ today's parser-derived
   value, byte-identical output.
2. **`LogSource` gains `surface`**; `importcmd` restamps the parsed row's
   `surface` **only when the source declares one** — mirror the existing `agent`
   restamp used for custom tools (that's the established pattern; don't invent a
   second one).
3. **Expose the effective sources.** Print, per source: agent · fmt · surface ·
   path · glob · provenance (built-in / env / policy) · found or missing.
   Default to **extending `cage doctor --paths`** rather than adding a top-level
   verb; if the output gets crowded, add `cage data sources` instead and say why.
4. **Verify the scaffolded config still emits the built-in defaults as an inert
   commented block** (so a user edits rather than guesses). Fix if the rename
   breaks it.

**Explicitly out of scope:** adding a Kiro-CLI source path or parser. Kiro CLI is
real (`kiro-cli chat --no-interactive`, sessions under `~/.kiro`), but its usage
format is **unknown** — golden-set Phase 1 discovers it. Guessing the shape here
would repeat the `kind:0` title mistake. This task only builds the knob.
