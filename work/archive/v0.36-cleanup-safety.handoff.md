# Handoff — cleanup becomes advisory

**Three changes, one theme: cage stops deleting things on its own.**

| # | change | why |
|---|---|---|
| **1** | `CLEANUP_DEFAULT_DAYS` **30 → 90** | 30 days is tighter than a real usage gap |
| **2** | the auto sweep **warns, never deletes** | deletion is unrecoverable; a silent automatic delete is the wrong default |
| **3** | **never** a per-tool cleanup (graphify/fux savings) | already true structurally — make it explicit and tested |

Decision: Arpit, 2026-08-01. Deletion now happens **only** via an explicit
`cage data cleanup --apply`.

---

## 1. Retention 30 → 90 days

`constants.CLEANUP_DEFAULT_DAYS = 30` → `90`. **Update the justifying comment too** — it
currently argues *for* 30 ("comfortably outlives every consumer of the cleanable
classes"), so leaving it would make the constant and its own rationale disagree.

Policy `[cleanup] days` still wins (`policy.cleanup_days`, the `DEFAULT_CONFIDENCE`
policy-preferred pattern). The bundle's `[cleanup] days = 30` must move to `90` as well,
or a scaffolded project silently keeps the old window.

## 2. The auto sweep warns; it never deletes

**Today:** `cleanup.maybe_run` piggybacks on `importcmd.run` / session-end, throttled to
one real check per `CLEANUP_THROTTLE_HOURS` (24), and **deletes**.

**After:** `maybe_run` computes what *would* be removed and prints a reminder. It removes
nothing. `cage data cleanup --apply` remains the only path that deletes.

Requirements, each load-bearing:

- **stderr, never stdout.** stdout is the deterministic table surface; an advisory line
  there would change a reported view.
- **Silent when nothing is eligible.** A reminder saying "0 items" is noise and trains
  people to ignore it.
- **Honour the existing 24h throttle.** Otherwise it prints on every single command.
- **Actionable:** name the count, the window, and the exact runnable fix
  (`cage data cleanup` to preview, `--apply` to act).
- **Fail-open**, like everything on this path. A broken reminder must never break an
  import.

### The new switch

`[cleanup] warn`, **default `true`**, env `CAGE_CLEANUP_WARN` — use the existing
`policy._flag` pattern so precedence matches every other switch (env > policy > default).

### ⚠️ Decide: what `[cleanup] enabled` now means

`enabled` currently gates **both** the auto sweep and the manual `--apply`. Once auto
never deletes, its meaning is ambiguous. Pick one and document it:

- `enabled=false` ⇒ no reminder **and** `--apply` refuses (a full off switch), or
- `enabled=false` ⇒ no automatic *anything*, but an explicit `--apply` still works
  (an explicit command shouldn't be silently ignored)

**The second is the safer reading** — a user typing `--apply` has asked plainly — but say
which you chose and make `cage query` reflect it.

### ⚠️ The cost of this decision, and the mitigation

Nothing prunes `state/` automatically any more, so it **grows unbounded** for anyone who
ignores the notice. That is accepted (unrecoverable deletion is the worse failure), but
the reminder must not fire once and give up:

- keep reminding on every throttle interval while items remain eligible
- include the reclaimable **size**, so the line escalates naturally as it grows
- consider tying into the existing `LEDGER_WARN_BYTES` style hint if `state/` gets large

## 3. Never a per-tool cleanup

Tool savings live at `ledger/savings/<tool>/savings-<month>.jsonl`
(`paths.Footprint.savings_dir`), and `cleanup.NEVER` protects `"ledger/"` — so graphify
and fux savings are **already** unreachable.

**But only because of where the directory sits.** Move savings out of `ledger/` and the
protection disappears silently, with no test failing.

Required:

- a test asserting a `ledger/savings/<tool>/` file **survives** `prune`, including with
  an absurd `days=0`
- a comment at `cleanup.NEVER` stating that savings are covered *via* `ledger/`, and that
  a per-tool cleanup class must never be added — savings are unrecoverable
- the same sentence in `CLAUDE.md`'s cleanup paragraph as a standing invariant

## Definition of done

- [ ] Default retention is 90 days, in `constants.py` **and** the bundle, comment updated
- [ ] Auto sweep deletes nothing; a test proves eligible files **survive** a `maybe_run`
- [ ] `cage data cleanup --apply` still deletes; a test proves it
- [ ] Reminder: stderr · silent at zero · throttled · names count, size and the fix
- [ ] `[cleanup] warn` default true, env override, `policy._flag` precedence
- [ ] `enabled` semantics decided, documented, and reflected in `cage query`
- [ ] A `ledger/savings/<tool>/` file survives `prune` even at `days=0` — **tested**
- [ ] Determinism intact: no advisory text on stdout; derived views byte-identical
- [ ] `just test` green; goldens re-blessed; test count refreshed in README + CLAUDE.md
- [ ] CLAUDE.md / explain_data / example / CHANGELOG updated; IMPLEMENTATION / WORKLOG /
      DOC-REGISTRY / OPEN-WORK updated

## Out of scope

Changing what is *in* the cleanable allowlist. The classes stay exactly as they are —
only the schedule, the default window, and who pulls the trigger change.
