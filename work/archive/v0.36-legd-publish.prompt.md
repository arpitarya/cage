## Task 2 — four finding docs

Each dated `2026-08-01-finding-*.md`, each owning its own Status line.

1. **`copilot-path-glob`** — `importcmd.import_copilot`'s `--path` branch hardcodes
   `*/events.jsonl`, so it can never reach the VS Code `chatSessions/*.jsonl` store.
   The parser handles both shapes; only the glob is wrong. Claude's branch uses
   `**/*.jsonl` and works. Symptom: `matched 0 files — capture is off for this agent`
   while the files exist and parse. Workaround used: a `[sources.copilot]` override
   with explicit path + glob + `surface`. **Status: OPEN — real code bug.**
2. **`kiro-rows-double-count-across-ledgers`** — kiro's single global log is re-read by
   every ledger importing it. `workspace-off` 22 rows, `workspace-on` 28; 22 are the
   same turns. Within a ledger dedupe is correct (re-import = 0). **Across ledgers they
   double-count** — the two lab ledgers must never be summed for kiro. Structural: a
   global log meeting per-workspace ledgers. **Status: OPEN — document or warn.**
3. **`kiro-rows-carry-no-time-session-project`** — every row stamped at *import* time,
   `session = "kiro"` constant, no project. Deeper than the documented "credit-derived
   estimated / tokens_out = 0". Consequence: **the kiro A/B is not reconstructible from
   the ledger** — D5 and D6 rows are literally indistinguishable; only operator notes
   separate them. **No kiro ON/OFF delta may ever be reported.**
   **Status: HONEST-LIMIT — final unless kiro changes its log.**
4. **`surface-attribution-is-agent-dependent`** — copilot's CLI and VS Code stores are
   separate ⇒ `surface = vscode` correct (D3/D4). Claude's are **shared** ⇒ `surface`
   empty, unknowable (D1/D2). Per-surface attribution works for **one of three agents**.
   Note what survives for claude: `project` is correct on every row, so per-workspace
   attribution holds where per-surface does not. **Status: HONEST-LIMIT.**

## Task 2b — the gross-vs-net finding (BLOCKING for the benchmark)

Publish `2026-08-01-finding-saved-is-gross.md` from
`cage-lab/reports/cells/FINDING-gross-vs-net-savings.md`. **Severity HIGH — it
challenges cage's headline metric, not a capture gap.**

Leg D's own paired data: D2 (graphify ON) cost **~14% more** than D1 (OFF) — +37%
calls, +29% tokens in, +78% out — while cage recorded **18,456 tokens saved**. Both
true: `saved` is a per-query counterfactual that never nets the query turn, the hook
tax, or a re-read provoked by a truncated answer.

**Confidence discipline:** n = 1, so this is **UNPROVEN — a signal, not a measurement**.
Do not write it as FAIL, and do not soften it into a footnote either.

**The benchmark (Task 3) must carry this counterweight.** Printing "27,658 tokens
saved" without it would be the exact failure this lab exists to prevent.
