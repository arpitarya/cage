# SURFACE-CUT — the read surface shrinks; capture does not

**This was a read-surface deletion, not a capture change.** Every row cage recorded
before this change is still recorded, in the same shards, with the same fields. What is
gone is the set of commands that rendered them.

**Placement — ANSWERED 2026-08-14 (superseding the open question below).** SURFACE-CUT
is cross-cutting and per-*surface*, so it is **not** a per-agent ADR. Its decision record
is this file plus the v0.50.0 CHANGELOG entry; what survives of the surface it cut is
described by [ADR-CLI](../../docs/adr/0002_cli.md). The original note read:

> **Placement note (needs Arpit).** The prompt called for "a new ADR". The ADR set was
restructured the same day: the numeric records 0001–0011 became history in
[archive/adr/](adr/README.md), and the standing set is now **four per-agent
records** in [docs/adr/](../../docs/adr/README.md). SURFACE-CUT is cross-cutting and
per-*surface*, so it fits neither shape. It is filed here beside its handoff/prompt pair
until Arpit says where it belongs.

## The decisions, and why

- **`cleanup.py` kept, its verb deleted.** The module has two live importers
  (`importcmd.run`'s auto path, `doctor`'s state check). Deleting it would have broken
  `cage import`. Consequence: nothing prunes `.cage/state/` — filed as STATE-RETENTION.
- **`metercmd.py` deleted with `proxy.py`.** `cage data meter` was its only entry point;
  keeping it would have left a module importing a deleted one.
- **The overview died with `report`.** It was a rendered ledger view, and cage no longer
  ships one. Bare `cage` now prints the front door and exits 0.
- **`cage study export` was ADDED.** `study.export_bundle`'s only caller was the deleted
  `cage data export --study`, which would have left the P5 fleet study able to *import*
  bundles it could no longer *produce*. The refresh sweep moved with it.
- **`ledger-sync` and the team path deleted.** `--team` had no reader left, so the ref
  could be written and never displayed. Provenance `notes-sync` is untouched;
  `mergeutil.union_by_id` survives for it.
- **The graphify shim was left untouched** — deliberately, see below.

## The finding: six recorded-but-unread facts

The cut removed readers without removing writers. Capture still records all of these and
**no view reads any of them** (filed as UNREAD-FACTS):

| Fact | Still written by | Reader that died |
|---|---|---|
| `route_key` reclaim | `savings.record` | `report.read_receipts` |
| `state/attest.jsonl` | every wired L1 hook | `adoption` — this is L1 benefit *(a)* |
| `scope` (§3.6.2) | `schema.make_call` | `report`/`attrib --scope` |
| `project` (§3.7) | claude transcripts | `report --project` |
| task `label` / `outcome` | `cage task outcome` | `compare` / `calibration` |
| `[tools] order` | `cage.toml` | `attribution` — `policy.tool_order` now has **no** consumer |

None is a bug. Each is a standing choice: give the fact a view, or stop writing it.
`state/attest.jsonl` is the sharpest — L1 hooks exist partly to stamp agent identity for
`adoption`, and that consumer is gone while the write path and its cleanup class remain.

## The graphify shim: left alone on purpose

`bin/graphify` and its `.cmd` twin probe `cage data graphify`, which no longer exists.
**Arpit's call, 2026-08-14: leave the subsystem untouched this build.** The cost is 15
red tests (SHIM-DEAD-VERB); the reason it is safe is the contract itself —

- **B5** gates metering behind a `--help` capability probe, and
- **B6** requires transparent passthrough,

so an installed shim fails the probe and `exec`s the real binary unchanged: no breakage,
no metering. **`cage insights graphify` does not become a historical view** — receipts are
also filed at `cage import` by the transcript/store routes (`graphifytx.detect_and_file*`)
with no shim involved, and ADR-GRAPHIFY's content-key deferral means a query seen by both
routes files exactly one receipt. What is lost is invocation-time metering for runs those
routes cannot observe: **reduced coverage, not stopped capture.**

## Two gates that were wrong, and are now right

- **`test_cli_tiering._GROUPED` whitelisted `cage data …`** as a "grouped spelling". With
  the group deleted, that whitelist made every dead `cage data <x>` invisible to the
  stale-verb gate — the F1 class inside the detector itself. Removed from the list.
- **`just demo` had been broken since USAGE-ONLY**, calling `cage insights matrix`.
  Found by this sweep, not by anything that was watching. This is the second occurrence
  of the dev-tooling-drift class; `tests/test_cli_tiering.py` already gates it, and the
  gate did fire — nobody had run it.

## Verification

- **P3's rescue is proven, not asserted.** `_is_legacy_human` and `kiro_routed_line` moved
  to `chats.py`, `capture_warnings` to `doctorcmd.py`; both code versions were run against
  **one identical ledger** and `insights chats`, `insights graphify` and `doctor` are
  **byte-identical**. The kiro footer fired on both insight surfaces (proving the rewire)
  and doctor reached the capture-health gate — not a vacuous match.
- `tests/test_floor.py`'s `_VIEWS` **narrowed 8 → 3** and was not substituted (Arpit's
  call). Every assertion and `_WIRING_ARTIFACTS` is unchanged, but the floor no longer
  pins **any** CSV rendering — `report --csv` was its only CSV entry. Stated in the file.

## Veto condition (when to revisit)

- **Contingent — reopens on a measurement.** A deleted view returns when someone can name
  a question they actually asked that no surviving surface answers, *and* the data to
  answer it is already recorded (the table above lists six such facts). "It used to be
  there" is not a trigger.
- **Invariant — moves only by reversing this record.** Capture stays pull-based with no
  OS scheduler (archived ADR 0002, still binding). Cage still measures usage, never cost
  ([ADR 0011](adr/0011-cage-measures-usage-not-cost.md)) — nothing here reopens
  pricing, and a restored view would be tokens-and-credits only.
- **Deliberately not taken.** The graphify interceptor was *not* removed, and that is a
  choice rather than an oversight: it degrades safely and its removal is a 9-module
  cascade. Threshold to revisit: the first time a real user is confused by a shim that
  silently stops metering, or the first OS where passthrough is not clean.
