# Handoff: `cage doctor --wiring` — the installed-artifact inventory

**One-liner:** A read-only view that lists every cage-installed artifact across project **and**
global/user scope — location, type, and currency status (current / stale / dead / foreign /
partial) — so a user can see what was installed, what wasn't, and what's out of date, with no git
to track it.

**Owner / executor:** Claude Code
**Status:** Ready to build (Phase A). Design decided. Phase B (version-stamping) is a separate
later change, explicitly out of scope here.

**Stress-tested (proportional — additive read-only view, no contract surface):**
- *Devils-advocate — "this duplicates `wiringscan`/`cage doctor`."* It doesn't rebuild them — it
  **renders** them. `wiringscan` already enumerates + liveness-checks every artifact; doctor's
  wiring check is a pass/fail rollup. This is the *itemized inventory* view of the same data —
  the listing doctor's rollup summarizes. Reuse, don't reimplement.
- *Devils-advocate — "'version installed' is the ask, and you're not delivering it."* Correct and
  deliberate: artifacts are **stampless** (stale-wiring investigation confirmed — every field
  artifact carries no version). A per-artifact version is unknowable for what's already on disk.
  **Currency status** (current/stale/dead vs the running cage) answers the real question without
  inventing data. Version-stamping is Phase B (Arpit's "stamp later").
- *Pre-mortem — "'absent' warnings nag users who deliberately don't wire an agent."* Guarded:
  a fully-unwired agent is **informational** ("not wired"), never a warning. Only a **partially**
  wired agent (some artifacts present, some missing) flags the gap — that's a real
  half-finished install, not a choice.

## 1. Context & background

cage installs wiring artifacts (hooks, MCP configs, the graphify shim, skill/prompt/steering
assets, git hooks) at both project (`.claude/`, `.mcp.json`, `.kiro/…`) and global/user
(`~/.claude`, `~/.copilot/hooks`, `~/.codex/config.toml`, global skills) scope. None are
git-tracked at the global level and the project ones are easy to lose track of, so there's no
way today to answer "what did cage install here, and is it current?" — until a silent failure
(the F1 dead shim) surfaces it. `wiringscan.py` (v0.32.0) already enumerates and liveness-checks
all of it for the doctor *health* check; this exposes the same data as a browsable *inventory*.

## 2. Definition of done (Phase A)

- [ ] `cage doctor --wiring` prints a per-artifact inventory, grouped by **scope** (project vs
      global/user) and **agent** (claude / copilot / kiro — driven off `agents.SURFACES`, §7).
- [ ] Each row shows: **artifact** (display path, `~`-rendered), **type** (hook / mcp / shim /
      skill / prompt / steering / git-hook / policy / runshim), **scope**, and **status**.
- [ ] **Status taxonomy** (derived, no stamp):
  - `current` — a live verb / asset hash matches the bundle / shim bytes match the template.
  - `stale` — an asset differs from `paths.bundled_data()` (advisory `·`), or project
    `policy.toml [meta]` older than the bundle.
  - `dead` — a wiring command references a removed verb (`wiringscan` `Dead`) → `✗`, with the
    remediation from `wiringscan.remediation`.
  - `foreign` — a non-cage artifact at a cage location → shown, never actionable.
  - `absent` — an expected piece of a **partially**-wired agent is missing (see §5).
- [ ] Per-agent rollup line: `fully wired` / `partially wired (missing: …)` / `not wired` /
      `needs healing (N dead, M stale)`.
- [ ] A **version footer**: running `cage --version` (+ `(zipapp)` if applicable), the bundled
      `[meta]` versions (`prices_version`, `policy_version`), and the project `policy.toml
      [meta]` if present — the closest thing to "versions installed" that actually exists.
- [ ] **Read-only and side-effect-free** — no artifact executed, nothing healed, `~/.cage`
      untouched (mirrors `wiringscan`'s existing guarantee).
- [ ] `--json` output for the same data (cage's read views support it).
- [ ] Plain `cage doctor` is byte-unchanged (the flag is opt-in; the rollup stays in the health
      check).
- [ ] Docs + `cage query` entry updated (§9.5).

## 3. Scope

**In:** `cage/doctorcmd.py` (the `--wiring` flag + renderer), a small enumeration helper in
`cage/wiringscan.py` if needed (the "expected set" for partial detection, §5), CLI parser wiring
for the flag, `explain_data.py` concept entry, tests, docs.

**Out — do NOT build:**
- **Phase B: version-stamping artifacts.** Deferred by decision. Do not add a version marker to
  any artifact schema, and do not make the inventory claim a per-artifact version it can't know
  — show `current/stale/dead`, not a fabricated version.
- Any **healing** from this command — it's a viewer. Healing stays in `cage setup`. (The inventory
  may print the one-line fix, like doctor does, but it never acts.)
- A new top-level verb — it's a flag on `doctor` (decided).
- Any change to `wiringscan`'s liveness logic, the ledger, schema, or a derived number.

## 4. Current state — reuse, don't rebuild

`cage/wiringscan.py` (v0.32.0) already provides:
- `committed_artifacts(root)` → project-committed wired files `(display, command)`.
- `user_artifacts(root)` → user/global wired files `(display, command)`.
- `interceptor_verbs(root)` → `bin/graphify` cage verbs.
- asset scanning (hash vs `paths.bundled_data()`), `Scan`/`Dead`/`Stale`, `is_live_verb`,
  `is_dead_cage_command`, `remediation`, `heal_tail`.

`cage/doctorcmd.py` already has `_capture_timeline`, `_hooks`, `_bundled_prices` (the project-vs-
bundle `[meta]` compare — reuse for the version footer), and calls `wiringscan`. `paths` has the
scope resolvers (`resolve_root`, `active_ledger_source`, the agent-home helpers).

**The inventory is a new renderer over these** — it adds display/grouping + the partial-install
detection, not new enumeration.

## 5. Technical approach (decided)

- **Enumerate** via `wiringscan.committed_artifacts` + `user_artifacts` + `interceptor_verbs` +
  the asset scan. Tag each with scope (committed→project; user_artifacts→global/user).
- **Status** per artifact from the existing checks: dead (parser), stale (asset hash / policy
  `[meta]`), else current; foreign where `wiringscan` already marks non-cage.
- **Partial-install detection** ("what wasn't done"): compare the artifacts *present for an agent*
  against that agent's **expected set** (what a full `cage setup --<agent>` writes — derivable
  from the wire module's install targets, e.g. claude = settings.json hooks + `.mcp.json` +
  global skill). An agent with **some but not all** → `partially wired (missing: …)`. An agent
  with **none** → `not wired` (informational, never a warning). Keep the expected-set list in one
  place (a small map or a `wiringscan` helper) so it can't drift from what `install` actually
  writes — ideally derived from the wire modules, not hand-duplicated.
- **Version footer** reuses `_bundled_prices`'s project-vs-bundle `[meta]` comparison + the
  running `__version__`. This is the honest "versions" answer; per-artifact versions are Phase B.
- **Determinism:** doctor is already clock-exempt; but the inventory must not read/write the
  ledger or change any derived number — assert a derived view is byte-identical.

## 6. Non-negotiables
- `$0` / stdlib-only; read-only + side-effect-free (no execution, no heal, `~/.cage` untouched).
- Foreign artifacts shown, never judged/acted-on.
- No fabricated version — `current/stale/dead`, not a guessed version string.
- Plain `cage doctor` byte-unchanged; `--json` parity; counts/paths only, never content.
- Reuse `wiringscan`; do not fork its liveness logic.

## 7. Agent-set note
Codex removal shipped in v0.33.0 — the supported set is **Claude Code · Copilot · Kiro** (three
agents). Regardless: **never hand-enumerate agents in the inventory — drive it off
`agents.SURFACES` + `wiringscan`** so any future agent-set change updates the inventory
automatically. Do not add or reference codex anywhere.

## 8. Edge cases
- No project (`.cage/` absent) → show only global/user scope; don't error.
- An agent home absent → "not wired," not an error.
- Zipapp run → version footer notes `(zipapp)`.
- A partially-wired agent where the "missing" piece is intentionally gitignored (e.g. Kiro's
  `.kiro/settings/mcp.json`) → don't flag that as missing; respect the known exceptions
  `wiringscan`/portability already encode.
- `--json` must carry the same status taxonomy as the text view (one data structure, two
  renderers — the house pattern).

## 9. Testing
- `tests/` (extend `test_wiringscan`/doctor tests or new `test_wiring_inventory`): a `tmp_path`
  project with a mix — a current hook, a dead hook, a stale asset, a foreign artifact, a
  partially-wired agent, a fully-unwired agent — asserts each renders with the right
  scope+type+status, and the partial/not-wired distinction holds. Machine-independent (redirect
  agent homes via the conftest fixture, as the v0.32.0 tests do).
- `--json` parity test. Plain `cage doctor` byte-identical (golden). Determinism: a derived view
  byte-identical with/without the flag.
- Full suite green: `just test`, `dummyrepo`, `docgen --check`, `skillgen --check`, `just demo`.
  Re-bless the doctor golden only if the plain output legitimately changed (it shouldn't — the
  flag is additive).
