# Proposal — `cage insights adoption`

**PICKED UP 2026-08-02** — [handoff](v0.40-insights-adoption.handoff.md) ·
[prompt](v0.40-insights-adoption.prompt.md).
**⚠️ Review correction: the "per agent × tool" headline below is only half-derivable.**
Usage rows carry **no `agent` field** (`ts · op · args_hash · exit · ms · outcome ·
route`), and shim/native savings rows carry an **empty session** because a subprocess
cannot know which agent spawned it — only the *transcript* route yields a joinable
session. So per-agent attribution is transcript-route only; totals and outcomes are
exact for everything. Structural, not a gap to fix. (Corollary worth knowing: leg D's
per-agent claim was **operator-attributed** — one agent per lab cell — not derived from
the data.)

**Leg D's most differentiating finding has no product surface:** same workspace, same
six questions, same graphify install — claude invoked graphify unprompted; copilot and
kiro never did. Cage could tell **"never ran" from "ran and cage missed it"** because
usage rows (diagnostic breadcrumbs) exist independently of receipts. No dashboard
measures whether agents *adopt* the tools you bought. This makes it a view.

## The view

Per agent × tool: **invocations** (usage rows) · **receipted** (savings captured) ·
**missed** (usage row, no receipt — a capture gap, named as such) · **never invoked**
(the adoption gap, named as such). One honesty line: usage rows are diagnostic-only —
this view *counts* them but still never prices them.

## Design constraints (the ones that will bite)

- **Usage rows stay unpriced and outside money views** — this view reports *counts*,
  never dollars, or the diagnostic-only invariant (tested byte-identical) breaks.
- Distinguishing "missed" needs the usage-row ↔ receipt correlation — the same
  `usage rows ≥ receipts` check the lab runs manually (03-verify §3.8), productized.
- Per-agent attribution inherits K4's limit: claude CLI/VS Code indistinguishable —
  the caveat machinery already exists, reuse `Footer`.
- CSV parity per §3.9; MCP mirror like report/attrib/roi.

## Why now

It is the README's third capability claim ("which tools your agents actually adopt")
— currently backed by a regression doc, not a command. Small build: derived view only,
no new capture, no schema change.
