# Claude Code prompt: one report per run — split the layered validation report

**Model:** **Opus** — the retro-split partitions published, hashed evidence.
Attributing a number to the wrong run wouldn't just confuse a reader; it would
poison the corpus's credibility.

**Where to run:** Claude Code with `cage/` and `../cage-lab/`. Commit in
`cage-lab/` only. **The `cage/` tree stays uncommitted.** **No paid agent calls
in this task** — it is a restructure, not a re-run.

---

Arpit's directive: **a new report for every run.** Spec:
`cage/docs/report-per-run.plan.md` (phase index at top). DoD:
`cage/docs/report-per-run.handoff.md`.

## Why (so you don't "improve" it back)

The current report layers three answers in one file: the post-fix re-run at the
top, the pre-fix baseline at §1/§2, and findings whose lifecycles span both. So
line 92 says `227,298 · 189,788 ❌` while line 14 says `8/8 exactly 227,298`.
Both true — of *different runs*. Banners were added and still didn't fix it,
because **one document was answering three questions.**

Split the questions:

| artifact | answers | lifetime |
|---|---|---|
| **Run report** | "What happened in *this* run?" | **immutable** once published |
| **Finding doc** | "What is this defect's status *now*?" | mutable status, append-only history |
| **History index** | "What runs exist, how did numbers move?" | append-only, one row per run |

**The rule: a run report never mentions a later run.** Whether a run's numbers
are still current is answered by the history index, not by a banner inside the
report.

## Task

**1 — Generator.** Rework `publish_report.py` so it emits a per-run report from
**that run's data only**, and is structurally incapable of appending to an
existing report. Body: run id · timestamp · machine · cage + agent versions ·
**active config file** · cells executed · numbers (log · cage · lab recount) ·
findings observed (one line + link) · what wasn't covered and why. Keep the
existing sha256 mechanism (header hash + sidecar + documented byte range).

**Forbidden in a run report:** before/after columns · superseded banners · a
finding's status as of a later date.

**2 — History index.** `findings/HISTORY.md`, append-only, one row per run:
run · date · phase · cells · headline numbers · verdict · hash prefix. Mirror the
rows into `cage/work/regression/README.md`. This is where the pre-fix → post-fix
movement lives now — visible in one table, each row naming its run.

**3 — Extract findings.** Each cross-run finding gets/keeps its own dated doc
that owns its status: copilot undercount (RESOLVED) · shim recursion (open) ·
graphify A/B didn't fire (open, product-level) · kiro SQLite + credits (closed by
the P2 probe) · surface collision (RESOLVED). Run reports **link**; they don't
restate lifecycles.

**4 — Retro-split** the existing layered report into two self-contained reports:

- **run-002 (pre-fix, 2026-07-28 am):** V1/V2 green · V3/V4 red at 189,788 /
  191,414 · V5/V5b red · findings observed.
- **run-003 (post-fix, 2026-07-28 pm):** copilot exactly 227,298 / 233,675 ·
  kiro 12/15 credit rows · claude byte-identical · self-heal proof.

**Transcribe the numbers from the published text. Do not recompute, re-derive or
"tidy" them** — you are partitioning evidence, not regenerating it.

The existing layered file **stays** in `work/regression/`, marked
**SUPERSEDED — split into run-002 + run-003**. Never delete or rewrite published
evidence.

**5 — Verify.**

- Open each report at a random line — is it unambiguous which run it describes,
  **without** a banner? If not, the split isn't done.
- Grep the cross-run figures: no run report contains another run's numbers.
- **Every number in the original appears in exactly one split — none lost, none
  duplicated.** This is the check that proves the partition is faithful.
- Each finding's current status is answerable from its finding doc alone.
- Hashes recomputed and verified against sidecars; `latest-validation-report.md`
  points at the newest run report.

## Constraints (hard)

- **No paid agent calls.** Nothing is re-run.
- **Never rewrite or delete published evidence** — supersede, don't erase.
- **Transcribe, don't recompute**, in the retro-split.
- A published run report is **immutable**; a correction is a new dated doc.
- Append-only publishing; verify hashes, don't just write them.
- **DO NOT COMMIT in `cage/`**; append a `cage/docs/IMPLEMENTATION.md` entry per
  phase.

## Guardrails

- **STOP and ask if:** a number in the original can't be attributed to exactly
  one run · the split would require recomputing anything · a finding's status is
  ambiguous between the two runs.
- If you are tempted to add a banner to a run report to explain it, the split is
  wrong — fix the split instead. Banners are what this task exists to eliminate.
