on unmaterialized projects. Not a one-line fix.

## The bug

Three `--path` branches, three hardcoded globs. Copilot's is `*/events.jsonl` — the **CLI
shape only** — so `--path` can never reach the VS Code `chatSessions/*.jsonl` store, no
matter how files are staged. The parser handles both shapes already; only the glob is
wrong. Symptom: `matched 0 files — capture is off for this agent` while the files parse
fine.

## The design (decided — do not re-litigate)

**Two keys, two jobs:**

| key | anchoring | used by |
|---|---|---|
| `glob` (existing) | **anchored** to its declared root | normal imports |
| **`path_globs`** (new) | **root-agnostic** (`**/…`) | `--path` only |

Reusing `glob` for `--path` was considered and **rejected**: it is anchored, so pointing
`--path` at a `chatSessions` directory would still match nothing — the same bug, relocated.

**Seed → materialize → authority**, exactly as `[sources]` already works:

- code holds the **seed** (so a new agent store ships in a release, not in everyone's
  hand-edited toml)
- `cage setup` / `--sync-sources` **materializes** it into the project `cage.toml`
- import reads **`cage.toml`** — Directive A holds

**Seeds:** claude `["**/*.jsonl"]` · copilot `["**/events.jsonl",
"**/chatSessions/*.jsonl"]` · kiro `["*"]`.

Copilot names **both shapes explicitly** rather than `**/*.jsonl` — safe by construction,
not by the accident of a foreign file parsing to zero rows.

## Hard requirements

- **No glob string literal may remain in `importcmd.py`'s `--path` branches** —
  grep-gated by a test. This is what stops the fix silently regressing.
- **Absent `path_globs` ⇒ `--path` matches nothing, loudly** — naming the absence and the
  fix (`cage setup --sync-sources`). A silent code fallback recreates the two-places
  problem this change exists to close. This is a deliberate behaviour change; test it.
- **The zero-match message must name the patterns tried**, e.g.
  `matched 0 files (tried: **/events.jsonl, **/chatSessions/*.jsonl)`. A "0 files" message
  that hides its glob is the reason this bug cost 20 minutes.
- **Byte-identical behaviour when `--path` is not used.**
- Overlapping patterns must not parse a file twice — dedupe the file set.
- A hand-written `path_globs` is honoured verbatim, never silently merged with the seed.

## Tests

1. `--path` at `<dir>/<sid>/events.jsonl` → imports
2. `--path` at `<dir>/ws/chatSessions/*.jsonl` → imports, **`surface = "vscode"`**
   ← *the test that pins the real fix; untested today*
3. both shapes under one `--path` → both import, no double-count
4. foreign `.jsonl` under `--path` → **not matched** (not merely "parses to zero")
5. no `--path` → registry behaviour byte-identical
6. absent `path_globs` → zero files **and** the loud message
7. grep-gate: no glob literal in the `--path` branches
8. materializer round-trip: `--sync-sources` writes it, re-run is idempotent, a
   hand-edited value survives
