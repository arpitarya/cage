**One-liner:** Publish the three cage-lab artifacts into `work/regression/` (approved),
then build the **three** checks that make graphify metering gaps visible — `cage doctor`
must inspect the **PATH-winning** interceptor (B-fix-1), stale adopt-era shims must be
healed or named (B-fix-2), and a **graphify hook that invokes by absolute path** must be
reported as an observability gap (B-fix-3).

**Owner / executor:** Claude Code — **Model: Opus.** B-fix-1 changes what `doctor`
calls a *failure* (a wrong call here either cries wolf on every machine or keeps the
silence that hid this bug for nine days), and shim resolution has known recursion
traps. Not a mechanical change.

**Status:** Ready to build. **No paid LLM calls.**

**Stress-tested:** three challenges, two of which changed the spec.

1. **"Just heal every stale shim you find."** Rejected — a PATH-winning shim can live
   in **another project's** `bin/`, and silently rewriting another repo's files is
   exactly the class of action cage refuses. **Amended:** heal only within a
   cage-managed root; outside it, *name it with a runnable fix line*.
2. **"Report the dead shim as a warning."** Rejected — a dead cage shim means capture
   is **silently off**, indistinguishable from cage not being installed. That is a
   **failure**, not advice. The stale-*asset* tier (prose naming an old verb) stays
   advisory; the two tiers must not be blurred.
3. **"Scan every graphify on PATH."** Survived amended: resolve the way the shell
   does — **first executable wins** — because that is the only one that actually runs.
   Report the rest only as `shadowed` context.

**Residual risk:** `doctor` gains a check that can fail on machines where cage
previously reported OK. That is the point, but the message must name the exact file
and the exact fix, or it becomes noise people learn to ignore.

## 1. Context & background

Phase B probed the VS Code surface and found a real, live failure on a real machine:

- The `graphify` that **wins on PATH** was a cage interceptor written by the removed
  `cage adopt`, routing through **`cage graphify`** — a pre-rename verb that now
  **exits 1**.
- Its guard (`cage graphify --help >/dev/null 2>&1`) fails, so the shim falls through
  to `exec "$REAL"` and runs graphify **unmetered and silently**.
- `cage doctor` run inside cage could not see it: the winning shim belonged to a
  **different project's** `bin/`, outside every scanned root.

This is `wiringscan.py`'s documented failure mode reproduced in the wild — and the
best mechanical explanation yet for savings that never appear. Cage already has the
liveness concept; it is simply pointed at the wrong artifact.

### B-fix-3 — warn when a graphify hook bypasses the interceptor (decided 2026-07-30)

**The mirror image of B-fix-1.** There, the wrong shim wins on PATH. Here, **no shim is
consulted at all**: graphify ≥0.9.30's claude installer writes its PreToolUse hook with
an **absolute** exe path (`_resolve_graphify_exe()`), so the command never traverses
PATH. Cage's interceptor can't see it, and a hook isn't a Bash tool call, so the
transcript route can't either. Evidence: [OPEN-WORK.md](OPEN-WORK.md) §J.

**Detect:** an agent hook artifact whose command references `graphify` by a path that is
**not** the cage interceptor. Cover `.claude/settings.json` PreToolUse blocks and kiro's
`*.kiro.hook` files — the same artifact set `wiringscan` already reads, plus foreign
(non-cage-written) hooks, which it currently skips.

**Severity: ADVISORY, not a failure.** This distinction is load-bearing and must not be
blurred with B-fix-1:

| case | meaning | severity |
|---|---|---|
| **B-fix-1** dead cage shim | cage's own wiring is broken; capture is silently off | **FAILURE** |
| **B-fix-3** absolute-path graphify hook | graphify is working **as designed**; cage simply cannot observe that path | **advisory** |

Crying failure on a correctly-functioning third-party integration is how a check gets
ignored. Say what is true: *"graphify's hook invokes `<path>` directly — cage's PATH
interceptor is bypassed, so any saving on that path is invisible. Savings from an
explicit `graphify query` are unaffected."*

**Escalate on `--strict`.** If the hook command contains `--strict` (or the environment
sets `GRAPHIFY_HOOK_STRICT`), the read hook **denies** the first raw read per session and
redirects — the avoided read is a real saving that may never produce a metered query.
Cage can detect this from the command string, so the message should be stronger there:
*"strict mode — savings on this path are unmeterable by any current route."*

**Never modify the hook.** graphify owns that artifact. Report, explain, stop — the same
rule as `foreign` in B-fix-1.

## 5. Technical approach (decided)

- **The live parser is the detector, never `verbmap.REMOVED`.** A verb deleted
  outright (`cage adopt`) is absent from `REMOVED`, so a grep-based check would miss
  the very artifact this fix exists for. `REMOVED` supplies the fix-hint tail only.
- **Resolve like the shell:** walk `PATH`, first executable wins. Reuse the
  interceptor-detection predicate already in the shim/wiringscan (matches both the
  current `cage data graphify` form and the stale `cage graphify` / "graphify metering
  interceptor" form) so neither can be misclassified.
- **Two severity tiers, kept distinct** (existing law): a dead **wired** command is a
  doctor failure; a stale **asset** (prose) stays advisory and never gates a footer.
- **Heal only what cage owns.** In-root ⇒ refresh and print what changed. Out-of-root
  ⇒ name it, print the fix, change nothing.

## 8. Edge cases & risks

- **No `graphify` on PATH at all** → not a failure; report "not installed" and move on.
- **The winner is the real binary** (no interceptor anywhere) → advisory: metering is
  off by absence, which is a *different* message from a dead shim. Don't merge them.
- **Two stacked interceptors** → the existing recursion guard already skips all cage
  shims when resolving REAL; the *scan* must not re-introduce a loop.
- **Symlinks / uv-tool shims** → resolve, but report the path the shell would use.
- **Windows** → `PATHEXT`/`.cmd` forms; if unverifiable, label `UNVERIFIED-LAYOUT`
  rather than guessing (the standing pattern).
- **Doctor gets noisy** → each finding must name the exact file and a runnable fix;
  a finding without a fix line is worse than silence.
