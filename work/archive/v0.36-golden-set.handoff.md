# Handoff: golden set **Phase 1** — setup + capture validation across every surface

**One-liner:** Build `../cage-lab/golden/` and prove that **for every agent ×
surface × graphify state, capture happens and the numbers are right** — a
12-cell validation matrix at 2–4 questions per cell, each cell passing eight
checks, ending in `findings/VALIDATION-REPORT.md`. Phases 2–3 (the full sweep
and the manual VS Code sweep) do not start until Arpit signs this off.
**Owner / executor:** Claude Code (scripted cells) + Arpit (manual cells)
**Model:** **Opus** — the capture protocol is a diagnosis problem (does the
snapshot diff catch every file? do the numbers reconcile three ways? where does
Kiro CLI actually log?), and a flaw frozen into the corpus poisons every
downstream test.
**Status:** Ready to build — supersedes the earlier 4-question single-agent
pilot draft entirely.
**Stress-tested:** Challenged: one agent, four questions is enough to validate →
rejected by Arpit; the thing being validated is *breadth* (every surface ×
graphify state), so a narrow pilot proves the protocol but not the coverage.
Challenged: assert on model answers → no; answers vary, assert on capture
structure and token accounting only. Riskiest assumption: agent CLIs flush their
logs before the post-snapshot — mitigated by settle-and-retry plus check 1; if
buffering exceeds it, that is a protocol finding to report before Phase 2.
Residual: Kiro CLI's usage location is genuinely unknown — V5 is discovery, and
the plan deliberately does not pretend to know the answer.
**Standing constraint: DO NOT COMMIT in `cage/`.** Commit freely in `cage-lab/`.

## 1. Context

cage-lab runs on real files only ([cage-lab-plan.md](cage-lab-plan.md) §2.1 —
zero mock data). Ad-hoc logs don't reliably contain what cage needs to prove, so
the golden set **drives the real agents** with authored questions; because we
author the prompts, captures freeze **byte-exact, unstripped**. The full spec is
[cage-lab-golden-set.plan.md](cage-lab-golden-set.plan.md) — §2 driver protocol,
**§2.5 the phases and the checks**, §2.6 Kiro CLI, **§2.7 what v0.36 changed**,
§3 questions, §4 graphify A/B, §5 manual checklist, §6 the field matrix.

Two cage changes landed 2026-07-27 that this phase exercises (plan §2.7):
`[sources]` now accepts a **`surface`** key (restamps only when declared), and
the config file is **`cage.toml`** (`policy.toml` still read as a fallback).

## 5. Non-negotiables

- **Verbatim capture** — copy bytes; never edit, strip or reformat. Sources are
  read-only: sha256 before == after.
- **Real agents only.** No simulated CLI, no synthesized log, no fake graphify.
- **Assert on capture structure and token accounting, never on model answers.**
- **Three-way reconciliation** — a two-way check shares failure modes with the
  thing it checks.
- **Append-only corpus** — a new run never overwrites an old capture.
- **A gap is reported, never filled** (`NOT AVAILABLE` / `NO REAL DATA`).
- stdlib-only; never `import cage`; the real `~/.cage` is untouched.
- **DO NOT COMMIT in `cage/`.**

## 6. Testing & validation

The eight checks *are* the validation. Additionally: each capture re-imports to
identical rows (idempotent), and `drive.py --list` + the manifest schema check
stay green.
