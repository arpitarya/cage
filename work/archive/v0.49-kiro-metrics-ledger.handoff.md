# Handoff: kiro-metrics — `.cage/ledger/kiro/`, the per-chat Kiro metrics ledger

**One-liner:** a new append-only ledger kind — `<ledger>/kiro/chats-YYYY-MM.jsonl` —
capturing, for every Kiro chat, everything Kiro's stores actually persist: IDE per-call
tokens **with timestamps** (from `devdata.sqlite`, a store cage never read), CLI
per-conversation credits/context/turns, CLI **per-turn** metadata, and — the built-in
upgrade-watch — the CLI's token slots recorded verbatim the day Kiro starts filling
them. Capture-only: no derived view reads it, **no reported number moves, no golden
re-blesses**. The change map in §4 names every file and function — follow it and the
build is a zap.

**Owner / executor:** Claude Code
**Status:** Ready to build
**Stress-tested:** devils-advocate challenged (1) "the stores don't hold cache or
per-chat IDE credits — don't promise them" → **DoD rewritten store-verbatim**; the row
schema carries `cached_in`/`cached_out`/`credits` slots that stay honestly absent
today and auto-fill if Kiro ever persists them — never estimated (the kiro-usage
chars÷4 trio is named and banned); (2) "a project `.cage/ledger/kiro/` with IDE rows
re-creates the ADR 0006 double-count" → **fixed by routing**: IDE-source rows ride the
existing `_kiro_leg` sink resolution (machine ledger), CLI-source rows ride
`_ingest_credits`' workspace scoping — `kiro/` exists in *each* ledger holding only
the rows that ledger is entitled to; (3) "the ledger will be nearly empty today
(16 IDE calls)" → survives: mechanism is a clone of the just-specced COPILOT-METRICS
shape, devdata.sqlite timestamps are a genuinely new fact, and the upgrade-watch is
the point. **Residual risk:** `devdata.sqlite`'s exact column list is unverified on
the real machine (research §6 probe pending) — the parser is written to survive that
(explicit-column SELECT, fail-open), and doctor names the probe.

**Grounding:** [research/2026-08-13-kiro-per-chat-usage-fetch-spec.md](../research/2026-08-13-kiro-per-chat-usage-fetch-spec.md)
(wire vs disk: dir · file · row · prop, verified 2026-08-13). Where this handoff names

## 1. Context & background

- Kiro today: IDE calls captured from `tokens_generated.jsonl` (two numbers, no ts) ·
  CLI credits captured conversation-grain (`credits-YYYY-MM.jsonl`). Dropped on the
  floor: the IDE store's **timestamped sibling** (`dev_data/devdata.sqlite`, table
  `tokens_generated` — same counter WITH `timestamp` + a cursorable `id`), the CLI's
  per-turn `request_metadata` numerics (per-turn ts, model_id, prompt/response byte
  sizes, tool-use count, chunk count), and the CLI's token slots (NULL today, schema
  present — the fork plumbed `TokenUsage` in; the day they fill, cage should already
  be recording them).
- Widening `make_call`/`make_credit` is the wrong tool — these are kiro-native facts
  at three grains (IDE call / CLI conversation / CLI turn). Own kind, same as
  `credits` and the savings tree.
- Precedents to mirror, not reinvent: `_ingest_credits` (importcmd.py ~l. 479: own
  kind, own id namespace, own seen-set, workspace-scoped, fail-open per file) ·
  `Footprint.savings_shard` (paths.py ~l. 1075: ledger sub-dir) · `ledger.credits`
  (ledger.py ~l. 201: append-only + last-write-wins collapse) ·
  `parse_kiro_cli_credits` (transcript.py ~l. 883: `mode=ro&immutable=1`, key
  whitelist) · the COPILOT-METRICS handoff (the same design one agent over).

## 2. Definition of done

- [ ] `cage import --agent kiro` (and the all-agent sweep) writes
      `<ledger>/kiro/chats-YYYY-MM.jsonl` rows from every source present; a re-run
      appends **zero** rows (idempotent by id).
- [ ] Rows exist for: `devdata.sqlite` per-call rows (`source="ide"`) · CLI
      per-conversation rows (`source="cli-conv"`) · CLI per-turn rows
      (`source="cli-turn"`) — **store-verbatim**: a value absent in the store is
      absent in the row (cache and IDE credits stay absent today, by honesty not
      omission).
- [ ] **Routing obeys ADR 0006**: IDE-source rows land in the kiro sink's
      `kiro/` tree only (machine ledger via `_kiro_leg`); CLI-source rows land in the
      sweep root, workspace-scoped exactly like credits rows. A project ledger never
      gains an IDE-source metrics row.
- [ ] A grown conversation appends a fresh row; `ledger.kiro_metrics()` collapses to
      the latest per key. Re-import of an unchanged store appends nothing.
- [ ] **No derived view reads the new kind**: `cage report` and `cage insights chats`
      stdout byte-identical with the `kiro/` tree present vs deleted (tested).
- [ ] `cage doctor` gains an advisory `kiro-metrics` line (per-source found/absent;
      names the pending devdata-schema probe when the db is absent/unreadable) —
      advisory, never a failure.
- [ ] Counts-never-content holds on every new read path (§6 — the CLI store carries
      prompt bodies beside the metadata; `devdata.sqlite` columns beyond the
      whitelist are never SELECTed).
- [ ] Full suite green; `test_floor`, goldens, `test_cli_reference` untouched.

## 4. Change map (researched 2026-08-13 against HEAD — follow it; re-verify only what looks stale)

### 4.1 `cage/schema.py` — the row (substrate change ⇒ PLAN §3 update in same change)

- `KIRO_METRIC_SOURCES = ("ide", "cli-conv", "cli-turn")` — closed enum.
- `make_kiro_metric(*, source, session="", surface="", turn="", model="",
  provider="", tokens_in=0, tokens_out=0, cached_in=0, cached_out=0, credits=None,
  context_pct=0.0, turns=0, chunks=0, prompt_bytes=0, response_bytes=0,
  tool_uses=0, row_ref="", ts=None, project="", metric_id=None) -> dict`
  - `agent` fixed `"kiro"`. `source` validated against the enum. Place it next to
    `make_credit` (~l. 245) and mirror its docstring discipline.
  - Counts (`tokens_*`, `cached_*`, `chunks`, `prompt_bytes`, `response_bytes`,
    `tool_uses`, `turns`) **omit-at-zero** (house idiom). `context_pct` rounded like
    `make_credit`.
  - `credits` is **None-sentinel** — written only when the store recorded it
    (CLI conv rows); absence ≠ 0 (the `make_call.credits` precedent).
  - `cached_in`/`cached_out`/`tokens_*` on CLI rows: filled **only** from
    `request_metadata`'s own slots when non-NULL — the upgrade-watch. Today they'll
    be omitted; that is correct, not a bug. Never estimated (docstring names and bans
    the kiro-usage chars÷4 / cumulative / chunk-count trio as token *facts*; `chunks`
    is recorded as a chunk count, never as tokens_out).
  - `row_ref`: the store's own row key (`devdata.sqlite` `id`, or the CLI
    `message_id`) — provenance, and the dedupe anchor.
  - id default `ids.new_id("km")`; parsers always pass a deterministic `metric_id`
    (`"km_" + sha1(source|session|row_ref-or-turn|<sorted payload json>)[:16]` —
    values folded so a grown row appends fresh; the `make_credit` turns-fold idea).
- `KIRO_METRIC_FIELDS` tuple beside `CREDIT_FIELDS` (~l. 286).

## 5. Technical approach (decided — do not re-litigate)

- **Record store-verbatim facts, per grain; derive later.** No estimates, no unit
  conversions, no cross-store joins at capture. Absent-in-store ⇒ absent-in-row.
- **Own kind, own id namespace (`km_`), own seen-set** — metrics rows can never
  collide with calls or credits (the `credits` precedent).
- **Routing is inherited, never re-decided**: IDE rows via `_kiro_leg`'s sink, CLI
  rows via `_ingest_credits`' workspace — ADR 0006 holds by construction.
- **Grown-source correctness = id-folds-values + collapse-on-read.**
- **Ledger sub-dir via the savings mechanism**; mirror COPILOT-METRICS' shape so the
  two kinds stay twins.
- **The upgrade-watch is schema, not code**: CLI token slots map straight onto row
  fields; when Kiro fills them, capture works with zero diff and doctor announces it.

## 6. Non-negotiables / constraints

- **Counts-never-content, by whitelist**: CLI parser reads only
  `request_metadata`/`user_turn_metadata`/`model_info` keys; never
  `history[].user`/`.assistant`/`content`/`latest_summary` bodies; `auth_kv`/auth
  tables never touched. IDE parser SELECTs explicit whitelisted columns only.
  No chat titles anywhere.
- **Absence ≠ zero** for `credits` (None-sentinel). **Never sum** a conversation's
  own growth rows. **Never estimate tokens** (chars÷4 / cumulative / chunk-count
  banned as token facts; `chunks` is a chunk count).
- **Read-only stores**: `mode=ro&immutable=1`, never checkpoint, never lock
  (WAL-tail rows acceptably missed until the next sweep — same call as the OTel
  store in the copilot spec).
- **Fail-open everywhere** on the write path; per-file/per-db try-except with
  `CAGE_DEBUG` trace (test_debug_coverage checks the swallow sites).
- **No derived view reads the kind in this build** — byte-identity test is the gate.
- **$0 stdlib**; idempotent re-import; cleanup can never touch `ledger/`.

## 8. Edge cases & risks

- **`devdata.sqlite` columns differ from the assumption** (probe pending): explicit
  SELECT ⇒ `sqlite3.OperationalError` ⇒ `[]`, doctor says absent/unreadable — never
  a crash, never a guess. When Arpit runs the §6 probe, widen in a follow-up.
- **`timestamp` column format unknown** (epoch vs datetime text): parse defensively
  (try ISO text, try epoch ms/s), fail-open per row to a `ts`-less row (lands in the
  legacy unpartitioned shard — readable, not lost).
- **Mid-session import** records a partial conversation → healed by id-fold +
  collapse next sweep. Test it.
- **Both CLI tables present** (conversations_v2 + conversations): same conversation
  could appear in both → id folds `conversation_id`, seen-set dedupes exact
  duplicates; collapse keys on session so the grown copy wins. Test with a fixture
  carrying both tables.
- **Empty kiro machine** (no kiro at all): every source absent ⇒ zero rows, zero
  noise (gate 1 in `_agent_installed` already handles the leg).
- **Volume**: trivial today (16 IDE calls); `LEDGER_WARN_BYTES` covers growth.
