## 1. Context & background

Cage was hook-first (Stop/SessionStart/SessionEnd/PostToolUse + git hooks + rendered
skill/prompt/steering assets). Decision (2026-07-25, Arpit): remove **all hook
machinery** and **all agent-facing md assets + most docs** — capture is pull-based
only, MCP is the only wired surface; hooks/assets will be rebuilt later on a cleaner
base. The removal is **half-applied**: this handoff finishes it (Phase 0), then
builds the import-ledger plan on the simplified base (Phases 1–3). The plan doc
(`docs/cage-import-ledger-plan.md`) is the design of record for Phases 1–3; read it
in full before starting them.

## 3. Scope

**In scope:** everything in §4's "remaining" list; plan Phases 1–4. **Phase 4 is
gated, not optional-to-skip:** build the correlation pass (session-window join
against `tasks.jsonl`, its own `method`/confidence tags, `MIN_*`-style blocking
gate), but it activates only when validated against real correlated data — with
`tasks.jsonl` now fed solely by explicit `cage human outcome` (plan §5), if no
real data exists at build time it ships disabled-by-default with the activation
gate documented in the plan's decisions log.
**Out of scope (explicit):** rebuilding hooks/skills/steering in any form; new docs beyond the plan pair +
README/CHANGELOG; renaming `adoptcmd.run`'s `out["hooks"]` key (cosmetic, later);
deleting the authorship/provenance *read* surfaces (`origin.py`, `originrecord.py`,
`notessync.py`, `verifycmd.py` stay — their hook-era writers are gone, they read
existing data); touching `work/archive/`, `docs/adr/`, `work/regression/`.

## 5. Technical approach (decided — do not re-litigate)

- Capture is pull-only; `importcmd.run` is the single capture chokepoint. No hook
  files are ever written; wire installs only heal/remove.
- Removed verbs go through `verbmap.REMOVED` ("" tail = removed outright); heal
  never rewrites to an empty fix.
- Savings = per-source directory tree `savings/<tool>/savings-YYYY-MM.jsonl`
  (plan §3, decision resolved) — not a `kind` tag on receipts. `tool` is a validated
  closed token, safe as a dir name.
- Manifest = new `imports.jsonl` (plan §4); never overload the existing
  git-authorship `provenance.jsonl`.
- All new call-row fields additive-optional (absent ⇒ byte-identical legacy row),
  like `gap_ms`/`project` today.
- `surface`: derivable copilot (`cli`/`vscode` store split) and kiro (`ide`);
  claude stays `""` — honest, not a TODO (shared store, plan §5).
- Cost at import: reuse `prices.call_usd`; `copilot/auto` and kiro `agent` print
  `UNPRICED`, never `$0`.

## 6. Non-negotiables / constraints

- **$0 / stdlib only** (`dependencies = []`); **fail-open** on every write path;
  **determinism** (no clocks/random in derived views; kiro import-time `ts` stays
  the one honest exception, already labelled volatile); **`method` is sacred**;
  **three agents** (claude · copilot · kiro) stay first-class on every surface;
  **counts-never-content** PII law (no prompt text, no file paths on call rows,
  tilde-relative `source_path` in the manifest via `importcmd._tilde`).
- **Do not** reintroduce any hook writer, OS scheduler, or skill/steering renderer.
- **Do not touch:** `work/archive/`, `docs/adr/`, `work/regression/`,
  `samples/agent-artifacts/` inputs (expected-row fixtures may gain the new additive
  fields), `.github/workflows/publish.yml` (release flow unchanged).
- Keep the wire-module `install(root, *, python_launcher=False)` signature and the
  `_WIRE`/`SURFACES` dispatch convention.
- Exit codes / error regime unchanged: `CageError` → `error: <msg>` + exit 1.

## 7. Dependencies & prerequisites

None external. Python 3.10+ (CI matrix), `pytest`. No network, no new packages.

## 8. Edge cases & risks

- Pre-removal wiring on real machines: `.claude/settings.json` hooks →
  `cage hook-stop` (dead; direction via verbmap; healed on next setup);
  `~/.copilot/hooks/cage.json` and `.kiro/hooks/cage.kiro.hook` call `cage import…`
  (still live — harmless until healed; wiringscan shows them as leftovers).
- `.mcp.json` shim (`.cage/bin/cage-run`) must keep resolving — runshim stays.
- Kiro rows: no timestamps/model/session — manifest + `surface=ide` still work;
  never fabricate.
- A truncated ledger tail during import summary rollup: counts come from the rows
  appended this run (`_ingest` delta) — never a re-read.
- Two racing imports: the existing `_import_lock` + `seen` dedupe covers manifest
  double-write of *call* rows; manifest rows are per-run audit rows and may
  legitimately record two sweeps.
