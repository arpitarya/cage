# Cage — import ledger, graphify-savings file & capture provenance

**Plan / analysis** · derived from `samples/agent-artifacts/**` and the live code
(`schema.py`, `ledger.py`, `importcmd.py`, `transcript.py`, `graphifymeter.py`,
`paths.py`). Written against three agents: **claude · copilot · kiro**.

> **Context (2026-07-25): cage is now hookless.** The hook machinery (`hooks.py`,
> `gitcommithook.py`, agent hook wiring, the rendered skill/prompt/steering assets,
> `tools/skillgen`/`tools/docgen`, and most of `docs/`) is being removed — capture is
> **pull-based only**: `cage import` + capture-on-read, with MCP as the sole wired
> read surface. The removal is mid-flight; finishing it is **Phase 0** of the build
> order (§6) and is fully specced in `docs/hookless-rebuild.handoff.md`. Everything
> below assumes the pull-only world: the import path (`importcmd.run`) is now the
> *only* capture chokepoint, which makes §2.2's summary and §4's manifest strictly
> more valuable — every captured row passes through one door.

## 0. TL;DR

You asked for three things:

1. `cage import` should ingest the sample logs and **give us the numbers** —
   tokens, cached, timestamp, session id, agent type, CLI-vs-VS-Code, model, task,
   plus anything else useful.
2. A **separate ledger file** dedicated to graphify savings.
3. A **provenance / manifest file** for every import and every graphify run —
   session id, session name, date, and the source path it was captured from.

The good news: the ledger row schema already carries **most** of #1 today
(`schema.make_call` → `calls.jsonl`). Two things are genuinely missing and one is
half-built:

- **Missing:** a `surface` field (`cli` vs `vscode`) on each row. No parser emits it.
- **Missing:** `cage import` printing token/cost **totals** — it currently only
  prints `"✔ claude: imported N call(s) from M file(s)."`
- **Half-built / a known bug:** `est_cost_usd` is written as `0.0` at import for
  every row and only re-priced at read time. The `copilot/auto` and kiro `agent`
  rows never price at all (memory: *cage-pricing-zero-bug*, *cage-real-capture-findings*).

For #2 and #3 there is **nothing today** — graphify savings land in the shared
`receipts.jsonl`, and the only `provenance.jsonl` that exists is the *git-authorship*
one (who edited which files), which is a different thing entirely. Both are new files.

**Is the sample data sufficient?** For #1: yes for tokens/cached/timestamp/session/
agent/model/surface/cost. It is **not** sufficient for a real `task` name, for kiro
timestamps/model, or for CLI-vs-VS-Code on *claude*. Those are format limits, not
parse gaps — see §5. You do **not** need to generate more CLI data to build this;
the current samples exercise every code path. More real data only helps if you want
to validate the `task`-correlation heuristic (§3.1), which the samples can't.

Mapping your requested fields:

| You asked for | Field today | State |
|---|---|---|
| token (in/out) | `tokens_in`, `tokens_out` | ✅ present |

### 2.1 Additions worth making while we're here

- **`surface`** — `cli` \| `vscode` \| `ide` \| `""`. The headline gap. Derivable
  for copilot (store split) and kiro (`ide`); `""` for claude by necessity.
- **`cache_write_in`** — claude reports `cache_creation_input_tokens` separately;
  today it's folded into `tokens_in` and lost. Splitting it out makes cache-hit-rate
  and cache-write cost exact without changing `tokens_in` semantics.
- **`premium`** (copilot CLI `totalPremiumRequests`) — the one billing-relevant
  signal copilot exposes that we currently drop.
- **`import_id`** — a foreign key linking each row to the capture-manifest row that
  produced it (§4). Cheap, and it makes "where did this row come from?" answerable.
- **`priced` / real `est_cost_usd`** — price at import (or at least surface the
  priced total in the summary) and mark rows the price table can't match (`copilot/auto`,
  kiro `agent`) as `UNPRICED` rather than silently `$0`. This is the existing
  pricing-zero bug; the import summary is the natural place to make it loud.

All additions are **additive-optional** exactly like `gap_ms`/`project` today: absent
⇒ byte-identical to the legacy row, so old ledgers and the fixture corpus still parse.

Right now `run_agent` returns `"✔ claude: imported N call(s) from M file(s)."`

Counts come from the rows this run appended (already in hand — `_ingest` returns the
delta); cost reuses `prices.call_usd` (the same function `report`/`explain` call).
No new ledger read.

## 3. Separate graphify-savings file (#2)

**Today:** `graphifymeter._meter` files a `make_receipt` row into the shared
`receipts.jsonl` (with everything else — proxy, fux, human attestations). There is
no dedicated savings ledger.

**Proposal:** a dedicated **`savings/` directory** under the ledger dir, with **one
sub-directory per savings source** and **one month-partitioned file per source**,
written through a thin `savings.record(tool, row)` wrapper. Schema is tuned for tool
savings rather than the generic receipt:

```
.cage/ledger/
  calls-YYYY-MM.jsonl          # unchanged
  receipts-YYYY-MM.jsonl       # unchanged
  tasks-YYYY-MM.jsonl          # unchanged
  savings/                     # NEW — dedicated savings tree
    graphify/
      savings-2026-07.jsonl    # one file per month, per source
      savings-2026-08.jsonl
    human/                     # LATER — same layout, when the human axis emits savings
      savings-2026-07.jsonl
    <tool>/                    # LATER — one dir per integrated tool
      savings-YYYY-MM.jsonl
```

Rationale for the tree (your ask): savings are **per-source** by nature — graphify
first, then the human axis, then any other integrated tool — and isolating each source
in its own directory keeps a tool's whole savings history diffable/scannable/prunable
without touching the others, and lets a new tool light up by creating a directory
rather than reworking a shared file. The month partition inside each source matches the
existing `calls`/`receipts`/`tasks` sharding convention (writers append to the shard
chosen from the row's own `ts`; readers glob `savings/*/savings-*.jsonl`).

A `savings/graphify/savings-2026-07.jsonl` row:

```jsonc
{
  "id": "s_…",
  "ts": "2026-07-25T…Z",
  "import_id": "",             // blank for graphify (live), set when a saving is imported
  "tool": "graphify",
  "op": "explain",             // query | path | explain
  "session": "…",              // the session/task the tool ran under
  "task": "cage",
  "unit": "tokens",
  "raw_alternative": 41800,    // whole cited source files (the counterfactual)
  "actual": 512,               // the answer graphify actually returned
  "saved": 41288,              // derived — can never disagree
  "method": "modeled",
  "confidence": 0.6,
  "source_files": 3,           // COUNT only — never the paths (PII guard)
  "route_key": ""              // optional non-PII routing key, as receipts have today
}
```

Design notes:

- **`saved` stays derived** (`raw_alternative − actual`) exactly as `make_receipt`
  does today, so the number can never be edited into disagreement.
- Add `Footprint.savings_dir → ledger/savings/` (a directory, not a single shard),
  and route writes through the same month-sharding + `machine.stamp` path via
  `ledger.append_row(root, ("savings", tool), row)` — the writer resolves
  `savings/<tool>/savings-<month>.jsonl` from the row's `tool` + `ts`. Reads glob
  `savings/*/savings-*.jsonl` and concatenate, exactly like every other kind. The
  `tool` sub-directory is the one new axis; everything else reuses the existing
  partition/read/stamp machinery. `tool` is a closed, validated token (never a path)
  so it's safe as a directory name — same PII discipline as `scope`/`label`.
- **Native-shim dedupe is preserved.** graphify ≥0.5.0 files its own cage receipt;
  `graphifymeter.run` already snapshots receipt ids before the child runs and defers
  if the child self-metered. That logic moves to snapshot `savings` ids (globbed
  across the tree) instead — one saving, one row, unchanged behaviour.
- **Migration (REVISED by Arpit, 2026-07-25 — consolidate into the tree, numbers
  precise: never wrong, never duplicated):** a one-shot idempotent migrator,
  `cage data migrate-savings` (dry-run by default, `--apply` to execute), **copies**
  historical `tool=="graphify"` receipt rows into `savings/graphify/` — each row
  lands in the shard chosen from its **own `ts`**, keeping its **original row id**.
  `receipts.jsonl` is never rewritten (append-only law; the only ledger mutation is
  append). Correctness is read-side: `ledger.receipts()` changes from concatenation
  to an **id-deduped union** (`mergeutil.union_by_id` — ids carry the only entropy,
  so identity dedupe is exact; tree wins on a duplicate id). Consequences, all
  load-bearing: re-running the migrator is a no-op; a half-completed migration still
  reads correct totals; derived views are **byte-identical before/after** (the
  migrator prints row count + Σ`saved` per tool for both stores and refuses `--apply`
  if the dry-run totals don't reconcile; a test pins attrib/report equality). The
  native-shim dedupe snapshot reads `receipts()` and so inherits the same guarantee.

Decision resolved: **dedicated file(s), not a `kind` tag on receipts** — and refined
to a **per-source directory** (`savings/<tool>/savings-<month>.jsonl`) so graphify,
human, and future tools each own an isolated, month-partitioned history. The cost is a
second reader union in `report` plus a glob across sub-dirs; both are cheap and match
the append-only, one-file-per-kind convention.

## 4. Capture-provenance / manifest file (#3)

**Naming:** the existing `provenance.jsonl` is **git-authorship** provenance
(`schema.make_provenance`: sha, files, origin=human/agent). To avoid overloading it,
the new file should be **`imports.jsonl`** (or `capture-manifest.jsonl`) — a capture
audit log, one row per import run and per graphify run. (I'll call it the *manifest*
below.)

One manifest row per **import sweep, per agent, per source**:

```jsonc
{
  "kind": "import",
  "import_id": "i_…",              // FK stamped onto every call row this sweep wrote
  "ts": "2026-07-25T18:04:11Z",    // the date/time captured — your "date"
  "agent": "copilot",
  "surface": "vscode",
  "session_id": "20236884-4f14-…", // your "session id"
  "session_name": "chat: cage-testbed", // your "session name" (best-effort, see below)
  "source_path": "~/.../chatSessions/2023…jsonl", // tilde-relative — PII-safe, your "path"
  "files_scanned": 1,
  "rows_parsed": 1,
  "rows_appended": 1,
  "rows_deduped": 0,
  "tokens_in": 25343,
  "tokens_out": 95,
  "cached_in": 0,
  "est_cost_usd": 0.0,             // priced total (or 0 + unpriced flag)
  "unpriced_rows": 1,
  "cage_version": "0.33.0",
  "machine": "…"                    // when the ledger is fleet-enrolled (machine.stamp)
}
```

And one manifest row per **graphify run**:

```jsonc
{
  "kind": "graphify",
  "import_id": "g_…",
  "ts": "…",
  "tool": "graphify",
  "op": "explain",
  "session_id": "",                // graphify has no session id — task stands in
  "session_name": "cage",          // = task (cwd basename today)
  "source_path": "graphify-out/…", // the out dir / cited-file root (count-safe)
  "saving_id": "s_…",              // FK to the savings.jsonl row
  "saved": 41288,
  "source_files": 3,
  "cage_version": "0.33.0"
}
```

Design notes:

- **`source_path` is tilde-relative and count-safe.** Reuse `importcmd._tilde`
  (already strips `$HOME`/username). Never store absolute paths or file *contents* —
  same PII discipline the rest of cage holds (counts-never-content).
- **`session_name` — always captured (Arpit, 2026-07-25; the earlier opt-in flag is
  removed).** Per-source name lifting:
  - claude — the `summary` record (`{"type":"summary","summary":"…"}` exists in the
    store, previously unused by the parser); fallback the `cwd` basename (`project`).
  - copilot VS Code — **CORRECTED 2026-07-25 against 143 real chat sessions** (the
    original "title on the `kind:0` record" was wrong): the title is a `customTitle`
    **patch record** (`kind:1` with `k:["customTitle"]`) or `kind:0.v.customTitle`;
    auto fallback is the first request's `generatedTitle` (88/143 sessions named,
    so an empty name is a normal state, not a parse failure). The parser follows
    this verified shape — implementation is right, this line was stale.
  - copilot CLI / kiro — no title exists in the log; store `""` — honest empty,
    never fabricated, never a session-id-as-name.
  Deliberate posture (recorded in §7): a title is user-authored prose — a conscious
  widening for this **local, audit-only** file; row stores stay counts-never-content.
  Granularity (Arpit): one manifest row **per (agent, surface, session)**, each with
  a cage-minted `session_uid` (`n_…`) — not one row per sweep.
- **Write point:** `importcmd.run` already has the perfect chokepoint — it holds the
  import lock, has `health` (files/rows per agent), and computes `imported` per agent.
  Emit one manifest row per `(agent, source)` there, minting `import_id` once per
  sweep and threading it into `schema.make_call` so every call row back-references it.
  Fail-open, like every other write on that path.
- graphify's manifest row is written from `graphifymeter._meter` right after the
  saving row, carrying the same `saving_id`.

This gives you a single append-only file answering "what did cage capture, when, from
where, and how much" for both import and graphify — which is exactly the audit trail
the request describes.

## 5. Honest limits (so the plan doesn't over-promise)

These are **format** limits of the source logs, not things a better parser fixes:

- **`task` name on imports** — the raw logs carry no task id. `task` can only be
  filled by correlating an import against `tasks.jsonl` by session/time window, which
  is a heuristic. **Weaker still in the hookless world:** the SessionEnd/post-commit
  writers that auto-snapshotted task rows are gone, so `tasks.jsonl` now only gains
  rows from explicit `cage human outcome` — correlation has less to correlate against
  until task capture is rebuilt. Recommend shipping `task` as `""` for imports in
  phase 1 and adding correlation as a later, clearly-labelled `method`-tagged pass.
  This is the one place where **more real CLI data would help** — to validate that
  correlation.
- **kiro** — no timestamps (import-time `ts`), no real model (`agent`), no session
  boundary (constant `"kiro"`), no cache. Manifest/`surface=ide` still work; the token
  counts are the only trustworthy signal.
- **claude CLI vs VS Code** — genuinely indistinguishable from the shared store;
  `surface=""` is the correct, honest value, not a TODO.
- **copilot VS Code cost** — `copilot/auto` matches no price row; it must read
  `UNPRICED`, never `$0`.

**Phase 3 — capture manifest**
6. Add `Footprint.imports` (→ `imports.jsonl`); a `manifest.record_import()` /

**Phase 4 — task correlation (optional, needs real data)**

Every phase is independently shippable and additive — no existing row, file, or the
pinned fixture corpus changes shape. Tests: extend each `derived-rows.json` fixture
with the new fields (they're byte-checked), add a `savings.jsonl` and `imports.jsonl`
fixture per agent, and assert the import summary totals against a hand-derived
reference (same discipline as the cage-lab regression repo).

## 7. Decisions

- **§3 (resolved):** dedicated **`savings/<tool>/savings-<month>.jsonl`** tree — a
  per-source directory, month-partitioned — not a `kind` tag on `receipts.jsonl`.
  graphify first; human and other tools get their own sibling directory as they're
  integrated. Cost: a reader union with legacy receipts + a sub-dir glob, both cheap.

- **§4 session-name (REVISED by Arpit, 2026-07-25 — supersedes the opt-in default):**
  session names are **always captured**. The `[capture] session_names` flag and
  `policy.session_names_enabled` are removed; the manifest stores the best available
  name unconditionally — claude: the transcript `summary` record (fallback: the `cwd`
  basename / `project`); copilot VS Code: the chat-session title on the `kind:0`
  record; copilot CLI / kiro: no name exists → `""` (honest empty, never fabricated).
  The session **count** per sweep stays alongside (a sweep spans many sessions).
  Deliberate PII posture: a title is user-authored prose — this is a conscious,
  recorded widening for the **manifest only** (`imports.jsonl` is a local audit file,
  never read by a derived view, never synced to refs/notes); call/receipt/savings rows
  stay counts-never-content.

- **§3 savings migration (REVISED by Arpit, 2026-07-25):** consolidate historical
  graphify receipts into the tree via `cage data migrate-savings` — copy rows (own-`ts`
  shard, **original ids**), never rewrite `receipts.jsonl`, and make `ledger.receipts()`
  an **id-deduped union** (`mergeutil.union_by_id`) so a duplicate id can never count
  twice. Precision contract: idempotent re-run, dry-run-first with reconciled totals
  (row count + Σ`saved` per tool), derived views byte-identical before/after — NOT
  WRONG, NOT DUPLICATED is the acceptance bar, tested.

- **Release (Arpit, 2026-07-25):** nothing is committed or tagged yet — more work is
  landing in the same tree before any release; the v0.36.0 changelog entry rides along
  uncommitted until then.

- **§4 task-correlation activation gate (resolved, 2026-07-25):** the Phase 4
  best-effort `task` backfill (`cage/taskcorr.py`) ships **built, tested, and disabled
  by default** — `policy.task_correlation_enabled` (`[capture] task_correlation`,
  default **false** / `CAGE_TASK_CORRELATION`). It is **derive-time only** (never
  mutates a call row's `task`, which would read as ground truth and break append-only +
  the method law) and its output is tagged `method="estimated"` at
  `constants.TASK_CORRELATION_CONFIDENCE` (0.5) — the softest signal in the ledger. Two
  guards, both load-bearing: the policy flag (off until validated) and a **blocking**
  `constants.MIN_TASK_CORRELATION_N` (5) min-n gate below which it returns nothing.
  **Activation trigger:** flip the flag to `true` only after the correlation has been
  validated against **real** correlated data (a run where imported calls and closed
  `tasks.jsonl` rows are known to belong together, so the session-window join's hit-rate
  can be measured) — with `tasks.jsonl` now fed solely by explicit `cage human outcome`
  (§5), that data does not exist at build time, hence disabled-by-default. No live view
  consumes the correlation yet; wiring it into a surface is a separate, post-activation
  change.
