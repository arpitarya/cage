# Proposal — Windows-native graphify interceptor (WIN-GF)

**IMPLEMENTED 2026-08-01 for v0.38 (unreleased).** All five phases shipped in one pass.
The living spec is the behaviour contract [../shim-contract.md](../../docs/shim-contract.md);
this proposal stays as the rationale, and the archived pair
([handoff](../archive/v0.38-win-graphify-shim.handoff.md) ·
[prompt](../archive/v0.38-win-graphify-shim.prompt.md)) is history.

**Two things this proposal and its pair got wrong**, corrected in the contract: graphify
is a **PyPI** distribution (`graphifyy`), not npm — on Windows it installs as
`Scripts\graphify.exe`, so the twin never shares a *filename* with the real binary, but
`.EXE` precedes `.CMD` in the default PATHEXT so it must never share a *directory*. And
the re-entry guard skips *metering* only, never the PATH scan or the 127 rule.

**Artifact as decided: `graphify.cmd`** — no `.exe`, nothing compiled. PowerShell was
ruled out on a hard fact: `.ps1` is absent from default PATHEXT, so it could never be
found by a bare `graphify`, which is the bug itself.

**The gap:** `cage/data/shims/graphify` is a bash script with no extension. Windows
PATH lookup for a bare `graphify` requires a PATHEXT-recognized extension
(`.exe`/`.cmd`/`.bat`/…), so cage's interceptor can never be *found* via PATH on
Windows — the shim capture route is structurally absent there, stated honestly in the
README's Platforms line.

**What v0.37.1 already fixed (narrower):** the `subprocess.run` WinError-193 crash —
`graphifymeter._resolve_argv` now shebang-resolves a non-native-exe target. That helps
only once something has located the shim by exact path; bare PATH invocation remains
unreachable.

## Shape of the fix (feature-sized, not a patch)

- A **Windows-native twin** (`.cmd` or PowerShell) with the same PATH-scan +
  recursion-guard logic as the bash shim — two artifacts, one behaviour contract.
- Wired into `cage setup`'s Windows install path (and the launcher mode).
- A `wiringscan.py` liveness check for the new artifact (the F1 lesson: existence ≠
  liveness).
- The CI `present` leg's WIN-GF assertion ([ci-graphify-matrix.handoff.md](../archive/v0.38-ci-graphify-matrix.handoff.md)
  §3) is written to **flip loudly** when this ships — building this turns that test
  from "asserts the gap" into "asserts the fix".

## The plan (phased — each ships alone)

| phase | what | gate |
|---|---|---|
| **1. Contract** | Extract the bash shim's behaviour into a written contract: PATH-scan-past-self · recursion guard (`CAGE_SHIM_ACTIVE`) · fail-open exec of the real binary · receipt push via `cage data graphify`. One doc both twins are tested against | contract reviewed |
| **2. Twin** | `graphify.cmd` (cmd, not PowerShell — no execution-policy variance) implementing the contract; generated beside the bash shim from one template if feasible (`runshim.py` pattern), hand-paired if not | contract tests pass on Windows CI |
| **3. Wire** | `cage setup` installs the twin on Windows (and under `--python-launcher`); `paths.cage_command_tail` recognizes it; `verbmap`/asset sweep for any hardcoded `bin/graphify` | `cage setup --status` shows it; dummyrepo S-scenario green |
| **4. Liveness** | `wiringscan.py` + `pathshim.py` learn the twin: PATHEXT-aware resolution (`live`/`dead`/`shadowed`/`foreign` on Windows); doctor names it | deliberate kill ⇒ doctor `dead` |
| **5. Flip** | The CI `present` leg's WIN-GF assertion ([ci-graphify-matrix.handoff.md](../archive/v0.38-ci-graphify-matrix.handoff.md) §3) flips from asserts-the-gap to asserts-the-fix; README Platforms line updated — the "planned" clause comes out | CI green both legs; README truthful |

**Order matters:** 1 before 2 (two implementations of an unwritten contract will drift),
4 before 5 (a twin without liveness detection recreates F1's 9-day silent failure on a
new OS).

**Model tier when picked up:** Opus for phases 1–2 (behaviour-contract extraction from
a bash script with a recursion guard is diagnosis-grade); Sonnet for 3–5.

## Risks to design around

Duplicated interception logic drifting between the twins (consider generating both
from one template, the `runshim.py` pattern); PATHEXT and PowerShell execution-policy
variance across locked-down endpoints (the restricted-environments tier already maps
this terrain).
