# Handoff: METRICS-PRIMARY — `ledger/{claude,copilot,kiro}/` become the source for everything

**One-liner:** flip cage's derive layer off the `calls` ledger and onto the three
per-agent metric ledgers, forward-only from a pinned cutover instant.

**Owner / executor:** Claude Code · **Model:** Opus (substrate contract change — CLAUDE.md rubric)

**Status:** Ready to build, **gated on P0's STOP check** (§2).

**Stress-tested:** the literal "rewire everything" was challenged on four counts —
grain mismatch (26 modules read `ledger.calls`; 7 join by call id), history loss (52,296
calls rows over 6 months vs 10 claude chats = 3.2% coverage, unbackfillable past
Claude Code's ~30d `cleanupPeriodDays`), no cost denominator (`make_claude_metric` has
no credits field by design), and a 2-function alternative (port `_fold_claude_chat`
into `parse_calls`). **Arpit overrode the gate: the metric ledgers are the source from
here onwards.** What survived the override, and is now binding design: the cutover is
**forward-only** (§5.1), capture stays **dual-write** so the flip is reversible (§5.2),
and claude gains **request-grain rows** so the id joins survive (§5.3). Residual risks
in §8 — the empty-ledger gate and the `--usd` semantics change are the two that bite.

## 1. Context & background

- Three capture-only ledger kinds shipped 2026-08-14 (PLAN §3.11–3.13): `ledger/copilot/`,
  `ledger/kiro/`, `ledger/claude/`. Each shipped with a DoD requiring **byte-identical**
  stdout with its tree present vs deleted. Nothing reads them.
- They exist because `calls` structurally can't hold vendor-native facts at three grains —
  copilot's `nano_aiu`/`session_credits`/timing, kiro's `context_pct`/`turns`,
  claude's `sidechain_*` split and `model_totals`.
- Measured on this repo's own ledger: `calls` and `ledger/claude/` **disagree by
  1.58–2.47×** on identical sessions (CLAUDE-DEDUP). The metric ledger is the correct one.
- This build makes the correct one authoritative instead of decorative.

## 5. Technical approach (decided)

### 5.1 Forward-only cutover, one resolver

- A single pinned constant `CUTOVER` (UTC instant, recorded in an ADR). Not "now" at
  runtime — a literal, so the same ledger always resolves the same way.
- `ledger.spend(root, since=None) -> list[dict]` = pre-cutover `calls` rows **+**
  post-cutover metric rows, normalized to one shape. Every derive site calls this.
- Rationale: "from here onwards" is Arpit's phrasing and it is also the only design where
  6 months of history survives and the 43 goldens stay frozen.

### 5.2 Capture stays dual-write

- `parse_calls` and the three metric parsers both keep running. Nothing about capture
  changes in this build.
- Rationale: the flip becomes a one-constant rollback instead of a data-loss event.

### 5.3 Claude gains request-grain rows

- The one genuine grain gap: copilot metric rows already carry `request`/`call`, kiro
  carries `turn`/`row_ref`, **claude has chat grain only**.
- Extend `parse_claude_chat_metrics` to also emit one row per folded
  `(requestId, message.id)` — id derived from `requestId`, session from the row's own
  `sessionId`. This *is* the CLAUDE-DEDUP + CLAUDE-SUBAGENT-KEY fix, expressed in the new
  ledger rather than in `parse_calls`. Reuse `_fold_claude_chat`; do not write a second fold.

### 5.4 Cost

- **Decided: stamp `est_cost_usd` at capture into metric rows**, mirroring `make_call` and
  PLAN §3.1's ground-truth-spend law. Derive-at-read was rejected — it would make historical
  $ figures move when `cage.toml` prices change.
- Claude metric rows have no credits field and must not gain one; cost comes from
  `model_totals` × policy, same ladder `calls` uses.

## 6. Non-negotiables

- **stdlib only** — `dependencies = []`. No new imports outside the stdlib.
- **Fail-open capture** — a malformed/absent store never fails a command; every new
  swallow site logs under `CAGE_DEBUG` (`tests/test_debug_coverage.py` enforces).
- **Counts-never-content** — never read message bodies, `summary`, or `tool-results/`.
- **Append-only** — no rewriting or deleting ledger rows, ever.
- **None-sentinel credits** preserved: a recorded `0.0` and an absent value are different
  facts and must not collapse.
- **Do not touch:** `tests/test_floor.py`, `tests/fixtures/goldens/*`, historical ledger files.
- **`CLAUDE.md` edits are PROPOSED, never applied** — surface the diff for Arpit's review.
- **No concurrent session** — if another Cowork/Claude Code session is in this repo, STOP.

| `--usd` totals shift at the cutover boundary (~2× drop for claude) | Expected and correct. Assert it; footnote it in `report`'s render so it doesn't read as a bug. |
| `ledgersync.py:71` merges only `calls` + `receipts` into `refs/notes/cage-ledger` | Team aggregation would **silently drop the new spine**. Must be extended in P4. |
| A row straddling the cutover (session starts before, grows after) | Resolve by row `ts`, not session start. Fixture-pinned. |
| `explain_data.py` / `cage query` entries still describe the kinds as capture-only | Update in P5 or they become lies. |
