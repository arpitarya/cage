# Handoff: capture-precision fixes + Phase 1 re-validation

**One-liner:** Fix what golden-set Phase 1 found (Copilot undercount, Kiro CLI
invisibility, silent surface loss), implement two standing directives
(`cage.toml` as the **only** source of log paths; hashed validation reports
copied into cage), then **re-run Phase 1** and prove the red cells went green
without regressing the green ones.
**Owner / executor:** Claude Code
**Model:** **Opus** — the Copilot fix changes id derivation on a dedupe path
where a wrong choice double-counts money; §3.6 changes how *every* capture path
resolves; and the re-validation is a diagnosis exercise, not a rerun.
**Status:** Ready to build
**Stress-tested:** Challenged: "mutate the row to the latest cumulative" (the
report's suggestion) → **rejected**, it breaks append-only, determinism,
crash-safety and concurrent-import safety, *and* is less precise (it collapses
per-turn increments into one moving number). Delta rows are exact and keep the
breakdown. Challenged: separate ledgers per agent → rejected; separation is
justified by **schema**, not by source — which is why Kiro *credits* do warrant
their own row shape while Copilot does not. Riskiest item: §3.6 freezes default
paths into user files, reintroducing silent staleness — mitigated by a doctor
drift check + `--sync-sources`, both mandatory, not optional. Residual: Kiro
token recoverability is still unproven; #0 gates three items and may delete them.
**Standing constraint: DO NOT COMMIT in `cage/`.** Commit in `cage-lab/` only.

## 1. Context

Golden-set Phase 1 (report: `../cage-lab/golden/findings/VALIDATION-REPORT.md`)
validated capture across every scripted surface. Claude reconciled to the token;
Copilot undercounts resumed sessions by 16–18%; Kiro CLI usage is entirely
invisible to cage. Full reasoning and the change list:
[capture-precision.plan.md](capture-precision.plan.md). The governing principle:
**cage can never be more precise than its source** — exact where the source
carries counts, honestly tagged where it doesn't.

## 2. Definition of done

**Step 0 — the probe that gates three items**

- [ ] Kiro tokens: run an **explicit non-`auto` model** and check
      `kiro-cli settings list --all` for a usage/telemetry flag. Record the
      result. If tokens populate, **stop and report** — items 2/3/5 change shape

**Fixes**

- [ ] **Copilot delta-id** — shutdown ordinal in the id; **ord 0 byte-identical
      to today's id**; row value = per-shutdown **delta**. Tests: (a) a grown
      two-shutdown session totals exactly the last cumulative; (b) re-import adds
      0 rows; (c) an **already-imported legacy** session re-imports to the exact
      total with **no double count** (the self-heal case); (d) premium is not
      multi-counted
- [ ] **Kiro SQLite parser** (only if step 0 says tokens are unavailable but the
      store is otherwise useful) — stdlib `sqlite3`, opened **read-only**; yields
      `conversation_id`, ms timestamps (kiro's first real `gap_ms` source),
      `model_id`
- [ ] **Counts-never-content guard** — parser never reads the `value` transcript
      body or `auth_kv`; a test asserts no prompt/response text can reach a row
- [ ] **Kiro credits** are **not** a call row with `tokens_in=0` — a distinct row
      shape / `unit="credits"`, tagged `estimated`; never `measured`
- [ ] **Surface-restamp collision** — a declared `surface` is no longer silently
      lost; either it wins or the loss is loud
- [ ] **Graphify shim recursion** — stacked shims can no longer resolve to each
      other and hang

**Directive A — ADDITIVE PARTS ONLY (scoped 2026-07-28)**

- [ ] `cage setup` / `initcmd` materialize the defaults as an **active
      `[sources]` table** (project **and** global `~/.cage`)
- [ ] `cage doctor` **diffs the project table against the bundled defaults** and
      reports drift
- [ ] `cage setup --sync-sources` refreshes explicitly without clobbering
      user-added entries
- [ ] **Resolution semantics UNCHANGED** — no exclusive authority, no env
      removal, no test migration. Those move to
      [config-authority.plan.md](config-authority.plan.md) Part 2, so the re-run
      can attribute a red cell to exactly one change and V1/V2 stay
      byte-identical by construction

**Directive B — hashed validation reports, copied into cage**

- [ ] `VALIDATION-REPORT.md.sha256` written beside the report; the hash printed
      in the report header, with the hashed byte-range documented
- [ ] Copied to `cage/work/regression/<YYYY-MM-DD>-validation-report.md` (+
      `.sha256`, + `latest-validation-report.md`), **append-only** (same-day
      re-run gets a `-2` suffix), with the index row (date · phase · cells ·
      headline · hash prefix)

**Re-validation — failures first (plan §4.1)**

- [ ] **Run order is: V3/V4 copilot → V5/V5b kiro → V1/V2 claude.** The cells the
      fixes targeted run **first**; the previously-green claude cells run **last**

- [ ] **Gate between groups:** a previously-failing cell that still fails ⇒
      **stop and report** before running the rest (re-running green cells proves

      a failure provably unrelated to the fix — note it and continue
- [ ] V3/V4 **8/8**, tokens_in exactly **227,298** / **233,675**
- [ ] V5/V5b rows present, or an honest written limit
- [ ] V1/V2 **8/8 with byte-identical numbers** — anything else means a fix leaked
      into a path it had no business touching
- [ ] The **self-heal proof** executed and recorded
- [ ] `pytest -q` green; append-only / determinism / idempotency tests unchanged
      in shape
- [ ] ADR written (#9); `work/regression/` entries for the HIGH findings (#10)
- [ ] `docs/IMPLEMENTATION.md` per milestone; **cage tree uncommitted**

## 5. Non-negotiables

Append-only · determinism · idempotency · the `method` law · counts-never-content
(hardest in §3.2, where content shares the row) · `$0`/stdlib (`sqlite3` is
stdlib) · fail-open write paths · `CageError` at the CLI boundary · **no commits
in `cage/`**.

Also: **never make a red cell green by loosening a check.** The re-validation
must fail if the fix didn't work.
