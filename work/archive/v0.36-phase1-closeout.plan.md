### P5.1 A third artifact type

`report-per-run` gave us two: **run report** (one run) and **finding doc** (one
defect). The benchmark is the third:

| artifact | answers | spans |
|---|---|---|
| run report | what happened in this run | one run |
| finding doc | this defect's status now | one defect, many runs |
| **phase benchmark** | **what does cage capture, and how correct is it?** | **one phase, all runs** |

It is **derived, not observed** — every cell cites a run report or finding doc.
It carries no new numbers of its own.

### P5.2 What the benchmark must state, per agent × surface

For each of claude/copilot/kiro × CLI/VS Code:

1. **Captured** — which fields land, with the method tag (`measured` /
   `estimated` / absent).
2. **Accuracy verdict** — one of:
   - **EXACT** — reconciled three ways (log = cage = independent recount), with
     the run and figures cited;
   - **HONEST-LIMIT** — the source carries no such number; cage records what
     exists, tagged, and says so (kiro tokens);
   - **UNPROVEN** — not yet tested (the VS Code surfaces until P3);
   - **WRONG** — a known open defect, linked.
3. **Evidence** — the run id + the exact figures, or the finding doc.
4. **Permanence** — is a limit *final* (vendor design) or *pending* (untested)?
   These must not be blurred: kiro tokens are final; VS Code is merely unproven.

### P5.3 The honest coverage statement

The benchmark must be explicit that Phase 1 covered **scripted CLI surfaces
only**. Six of twelve cells ran. Anything claimed about VS Code is UNPROVEN, not
assumed-good — and the benchmark says which questions P3 will answer.
