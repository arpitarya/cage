## The third rule: everything is committed, and must work for a teammate

**Every layer's wiring is committed to git and must work for every teammate on every
machine.** **Every piece of wiring is committed; only the *records* are not** —
`ledger/`, `out/`, `state/` stay gitignored. Team numbers come from
`refs/notes/cage-ledger` (ADR 0001), never committed records.

**Kiro's MCP — use the path-free form (P1).** A repo-relative `command` does **not**
work: Kiro resolves it against its *install directory*, not the workspace
(kirodotdev/Kiro #6525), and there is no variable substitution (#5659). **But
`kirowire.install` already writes a path-free form** under `--python-launcher`:
`{"command": "python3", "args": ["-m","cage","mcp"]}` (Windows: `py -3 -m cage mcp`).
**Make that the committed default for Kiro**, not a launcher special case — `python3`
resolves via PATH, so nothing machine-specific is committed.

**Then add the honesty check this creates:** the path-free form depends on *which*
`python3` resolves; if cage lives in a venv that interpreter isn't in, MCP silently
won't start. **`cage doctor` must check whether the resolved `python3` can import cage
and name it with the fix if not.** A silent no-MCP is exactly the failure class this
project keeps paying for.

Also, every phase: **idempotent byte-identical writes** (two teammates running
`cage setup` must not churn a diff), **never touch foreign entries** in shared files, and
**a teammate without cage installed gets silence, not breakage**.

## The second rule that outranks every phase: three agents, always

**`agents.SURFACES = ("claude", "copilot", "kiro")`.** A phase is not done until all
three have the layer — or the gap is **named as a limit in the output**, never left
silent. Per-agent shapes differ and the differences are load-bearing:

- **Copilot hooks CAN be committed** — `.github/hooks/*.json` is repo-level and
  portable, so it *does* ride the `.cage/bin/cage-run` shim. (User-level
  `~/.copilot/hooks` also exists and **both sources load and combine** — wiring both
  double-fires the same event, so **pick one and justify it**. Repo hooks apply to the
  coding agent only from the **default branch**.) An earlier draft of this prompt said
  Copilot hooks were user-level-only; that was wrong — `copilotwire._strip_legacy_hooks`
  cleans `.github/hooks/cage.json`, which cage itself once wrote.
- **Kiro's hook file is one hook per file** (`{name,version,description,when,then}`, not
  a `hooks[]` container) and **Kiro has no session-start trigger** — `agentStop`
  self-backfills.
- **Kiro's MCP config becomes path-free and committed** (`python3 -m cage mcp`) — see
  above; the old absolute-path/gitignore exception goes away.

### ⚠️ Hooks are CLI-only — they do not fire under a VS Code extension

So L1's agent identity and auto task-close are **CLI-session only**; VS Code falls back
to L0. **Never present a hook-derived agent as "cage knows which agent ran"** — it is
*"for CLI sessions"*, and every view built on it must carry that caveat. A field silently
absent for every VS Code user is the ADOPT half-B problem again, one layer up.

## The rule that outranks every phase

**L0 must work perfectly, alone, forever.** Every layer above is opt-in and degrades to
absent. **If removing a layer changes a number, the phase is wrong** — stop and report
rather than adjusting the number.

## P2 — L1: hooks + steering (**OPUS**)

**Build for the two things L0 structurally cannot do**, not for real-time capture:

1. **Agent identity at capture** — a hook knows which agent fired it. **Stamp it; never
   infer it.** This is what ADOPT-COV cannot get from a shim subprocess.
2. **Auto task-close on session boundary** — unblocks `compare`/`estimate`/`calibration`/
   NET-1 at once.

Plus: give `budget.check` its first real caller — block *before* a paid call when
`on_exceed = "block"`.

All three agents (`agents.SURFACES`), reusing `<agent>wire.py` — and honour each one's
shape (copilot repo-level `.github/hooks`, kiro one-hook-per-file with no session-start). **Committed files
reference `.cage/bin/cage-run`, never an absolute path** — `tests/test_portable_wiring.py`
greps for this. Every wired verb must be visible to `wiringscan`, or a future rename
silently kills capture (F1, twice burned).

**Hard gates:**
- **Opt-in** — `cage setup` stays hookless by default.
- **A test proves the same ledger yields identical derived output with hooks present and
  absent.** This is the phase's real acceptance criterion.
- **No double capture** — hooks and pull must not both record a turn; prove the id
  dedupe holds.
- Fail-open: a hook error never breaks the agent's turn.

**Gate:** hooks change no number; no double capture; portable-wiring test green;
**every hook file committed and machine-portable** (use Copilot's repo-level
`.github/hooks`, not the user-level path).
**Parity:** installed and tested on **all three** — and the CLI-only limit stated wherever
a hook-derived fact is shown. If one agent cannot support a behaviour (kiro's missing
session-start), **name it in output**; do not ship two-of-three silently.

## P3 — L3: skills (Sonnet)

**Governing rule, in every skill: a skill never computes a number — it runs cage and
quotes it.** Method tags verbatim, refusals relayed never smoothed, no arithmetic.

Build order: **task-closer** (needs P1's write tool) → **analyst** → **doctor-triage** →
**honesty-reviewer** → **release** → **lab-runner** → **windows-shim**.

**One source text per skill, three deliveries** (Claude skill · Copilot prompt · Kiro
steering). **A skill on one agent and not the others is not done.** Never hand-write
three copies — that is the drift the shim contract exists to prevent, in prose.

**Gate:** no skill computes a number; **all three deliveries render from one source**,
verified per agent (`cage setup --status`), and **all three are committed** — a teammate
gets them on clone.
