# `prices.toml` — model prices get their own file

**Plan of record.** Split the model price table out of `cage.toml` into
`.cage/prices.toml`. Supersedes the deleted `config-authority.plan.md`, whose
other half (the `[sources]` exclusive-authority flip) **already shipped** in the
capture-precision cycle at 846 tests green — this plan covers only the prices
split.

**Scope: model prices only.** Nothing else moves.

## 1. Why

`cage.toml` currently mixes two things with opposite lifecycles:

| | **your policy** | **model prices** |
|---|---|---|
| authored by | you / your team | vendors; researched at build time, shipped in the bundle |
| changes when | you change budgets, tool order, human rate, sources | a vendor changes a rate |
| on upgrade wants to be | **preserved** | **replaced wholesale** |
| update path | hand-edited, committed | `cage prices sync` |

The bundled `cage/data/cage.toml` is **568 lines, of which ~400 (70%) are price
rows.** So today the file a user opens to change their budget is dominated by
vendor data they never edit, and `cage prices sync` has to perform **text
surgery inside a file full of user policy** to update it.

Three things get better with the split:

1. **`cage prices sync` becomes a file replacement**, not surgery. Your policy
   can't be damaged by a price update, and a price table can't be left
   half-merged.
2. **`cage prices sync` vs `cage policy sync` stop overlapping.** Today both
   edit the same file, distinguished only by which keys they touch and two
   different version counters in one `[meta]`. After the split each owns a file.
3. **`cage.toml` becomes readable** — the config you actually edit drops to
   ~170 lines.

## 2. Exactly what moves

**The rule (Arpit, 2026-07-28): vendor facts move; routing decisions stay.**
That is what separates the two lifecycles cleanly, and it settles every border
case below without further argument.

**To `.cage/prices.toml`** — vendor facts:

- every `[prices.<provider>.<model>]` table — the model rate rows;
- `[credits]` — credit-to-USD rates;
- from `[meta]`: **`prices_version` and `prices_date` only**.

**Stays in `cage.toml`** — your decisions: `[capture]`, `[display]`,
`[cleanup]`, `[debug]`, `[tools]`, `[budgets]`, `[quality]`, `[human]`
(+ `[human.tasks.*]`, `[human.confidence]`), `[sources]`, `[wiring]`, from
`[meta]` **`cage_version` + `policy_version`**, and — decided against the
original draft — **`[alias]`**.

### 2.1 The two subtleties

**`[meta]` splits per key, not wholesale.** It carries *both* provenance
counters today: `prices_version`/`prices_date` (the price research date, drives
the staleness nag and `cage prices sync`) and `cage_version`/`policy_version`
(the non-pricing tunables, drives `cage policy sync`). Each follows its own
file. Getting this wrong silently breaks a staleness check — which fails *quiet*,
the worst failure mode cage has.

**Two routing decisions stay, though the `prices` CLI writes both.**

- **`[tools.<tool>] price_at`** (`cage prices route-tool`) — routes *your tool's*
  receipts to a model for pricing.
- **`[alias]`** (`cage prices alias`) — **REVISED 2026-07-28 (Arpit): stays in
  `cage.toml`.** The original draft moved it. It's the wrong side of the line:
  an alias says "*this* router id in *my* setup means that model" — a mapping the
  user hand-edits more than anything else in pricing, and one that describes
  their environment rather than a vendor's rate card. A vendor rate change never
  touches it, so it must not be wiped by a wholesale price sync.

Consequence to accept deliberately: **`cage prices` is a two-file writer** —
`set` writes `prices.toml`; `alias` and `route-tool` write `cage.toml`.

**Resolution is unaffected.** `policy.price_match` walks exact → alias → family
over the *merged* dict `policy.load` returns, so alias-in-one-file and
prices-in-another resolve exactly as today. The split is physical, not semantic.

## 3. Resolution + migration

The `policy.toml → cage.toml` rename already proved this shape. Copy it exactly;
do not invent a second pattern.

- **One resolution point** — `Footprint.prices`, resolving
  `prices.toml` → else the legacy in-`cage.toml` tables → else the bundled
  default. Never a second filename literal anywhere.
- **Both present ⇒ `prices.toml` wins**, and a one-line warning names the
  ignored in-`cage.toml` block (mirror `Footprint.shadowed_config`).
- **`cage setup` migrates:** move the tables listed in §2 out of `cage.toml`
  into `prices.toml`, leaving a one-line pointer comment behind. Idempotent,
  non-destructive when both exist, fail-open.
- **`policy.load` still returns one merged dict** — the split is a *file* change,
  not an API change. Every consumer (`prices.call_usd`, `policy.price_match`,
  `convert`, `receiptprice`) keeps reading the same shape. This is what makes the
  byte-identical acceptance test achievable.
- **Bundled data splits:** `cage/data/cage.toml` → `cage/data/cage.toml` +
  `cage/data/prices.toml`; update `pyproject.toml` package-data; **verify the
  zipapp** still resolves both via `paths.bundled_data()`.
- **`cleanup.NEVER`** protects `prices.toml` alongside `cage.toml` and the legacy
  `policy.toml`.
- **`cage doctor`** names the active prices file and flags a shadowed legacy
  block; the existing staleness recommendation points at the new file.

## 4. Command surfaces

| command | after the split |
|---|---|
| `cage prices list` / `unpriced` | read through `Footprint.prices` (unchanged output) |
| `cage prices set` | writes **`prices.toml`** (a vendor rate) |
| `cage prices alias` | writes **`cage.toml`** (`[alias]` — a routing decision, §2.1) |
| `cage prices route-tool` | writes **`cage.toml`** (`[tools.<tool>] price_at` — §2.1) |
| `cage prices sync` | **replaces the cage-managed region of `prices.toml`**; rows marked `# cage:custom` still survive |
| `cage policy sync` | unchanged, now unambiguously `cage.toml`-only |

## 5. The risk, and the acceptance bar

Pricing is the money path. A split that silently drops a row does **not** crash —
it reprices those calls to **UNPRICED**, or worse to a family match that looks
plausible. So acceptance is numerical, not structural:

> **On a real ledger, `cage report`, `cage insights attrib` and `cage insights
> roi` must be byte-identical before and after the split, and the UNPRICED row
> count must not change by one.**

Supporting checks:

- every `[prices.*]` table present before the split resolves after it (count
  them, don't eyeball);
- `policy.price_match` still returns the same `exact | alias | family | none`
  kind for a sampled set of real model ids — a match that silently degrades from
  `exact` to `family` is a wrong number wearing a plausible tag;
- a legacy project (prices still in `cage.toml`) reads identically via the
  fallback;
- both-present ⇒ `prices.toml` wins, with the warning;
- `cage setup` migration is idempotent; running it twice changes nothing;
- zipapp (`cage.pyz`) finds both bundled files.

## 7. Decisions (Arpit, 2026-07-28 — all three settled)

- **Committed**, like `cage.toml` — a team that shares numbers must share a price
  table. Machine-local deviations stay possible via `# cage:custom` rows.
- **`[credits]` moves; `[alias]` stays.** This is what produced the *vendor facts
  move, routing decisions stay* rule in §2 — a sharper line than "anything the
  prices CLI touches".
- **Yes, split the global `~/.cage` config too** — same shape. A global ledger
  prices calls exactly like a project one, so it needs the same two files.

## 8. Why there is a global `~/.cage` at all (asked 2026-07-28)

Short answer: **it is the sink for work that happens outside any project, and
after the hookless rebuild it matters more, not less.**

- **Capture must work with no project.** `paths.resolve_root` resolves
  `--ledger`/`CAGE_BASE` → nearest project `.cage/` from cwd → **global
  `~/.cage`**. Without the last tier, any agent session run outside a
  cage-enabled repo emits usage that lands nowhere. That was the reasoning in
  [ADR 0002](adr/0002-universal-capture-global-ledger-explicit-import-export.md),
  which also removed the old cwd-`.cage` guard for the same reason.
- **Pull-based capture is machine-wide by nature.** `cage import` sweeps the
  agents' own logs, and those logs span every directory you worked in — not just
  cage-enabled ones. The global ledger is the honest home for "everything this
  machine did"; a project ledger only holds a slice you deliberately scoped.
- **Per-project attribution doesn't require per-project ledgers.** Rows carry
  `project` and `scope`, and `cage report --project` / `--scope` slice the global
  ledger. That was a deliberate ADR-0002 call: *project is a derived view*, not a
  separate store — which avoids N ledgers drifting apart.

**The question worth asking, though, is the sharper one underneath:** if every
import lands globally anyway, is a project `.cage/` still a *ledger*, or is it
now really just **config + wiring**? A cleaner model might be **project =
config, global = ledger** — one store, many views. That would remove a whole
precedence tier and a class of "which ledger did this land in?" confusion (the
kind that produced the 2026-07-24 finding where 5 real receipts sat in a project
ledger while 36k calls sat in the global one).

That is a real simplification, but it is an **ADR-level change to the capture
model, not a prices question** — it would need its own compare doc and would
revisit ADR 0002. Recorded here so it isn't lost; explicitly out of scope for
this plan.
