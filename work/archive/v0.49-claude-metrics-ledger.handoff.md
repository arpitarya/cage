# Handoff: claude-metrics — `.cage/ledger/claude/`, the per-chat Claude metrics ledger

**One-liner:** a new append-only ledger kind — `.cage/ledger/claude/chats-YYYY-MM.jsonl`
— one row per **chat** (Claude Code session) per growth, carrying the correctly-folded
per-chat numbers the transcript store persists: tokens in/out, cached in (read), cached
out (write, with the 5m/1h TTL split), thinking tokens, server-tool call counts,
per-model totals, sidechain (subagent) split, request/row counts, and timing.
**Owner / executor:** Claude Code.
**Status:** Ready to build.
**Stress-tested:** challenged "fix the calls parser instead" (doesn't cover the values
the closed call schema drops — new kind survives, same §1 argument as COPILOT-METRICS)
and "aggregates violate record-verbatim" (the chat IS the store's unit — one file = one
chat; the fold is deterministic from file bytes; kiro-credits precedent). Riskiest
assumption — partial totals when only a subagent file changed — is killed by the
session-fileset regroup (§4.5). Residual: resumed-session `sessionId`-vs-filename drift
is UNVERIFIED (handled: key on the row's own `sessionId`; id-folds-values keeps any
drift append-safe) · COPILOT-METRICS may build concurrently in another session —
**never run the two prompts at the same time** (both touch schema/paths/ledger/importcmd).

**Grounding:** [research/2026-08-13-claude-per-chat-usage-fetch-spec.md](../research/2026-08-13-claude-per-chat-usage-fetch-spec.md)
— the store layout (dir · file · row · prop), THE DEDUP LAW, the subagent layout, and
the firm no on credits, all verified on a live 2.1.229 store. Where this handoff names
a store prop, that doc is the evidence. Twin of
[copilot-metrics-ledger.handoff.md](v0.49-copilot-metrics-ledger.handoff.md)
(shipped 2026-08-14, archived on implement — the link now points at its history) —
same shape, one store instead of five.

## 1. Context & background

- Cage's `calls` rows for claude carry tokens in/out/cached and nothing else — they
  **drop** the cache-TTL split (a real 1.6× price spread), `thinking_tokens`,
  `server_tool_use` counts, the sidechain split, and the request/row counts. Worse,
  the calls parser has two known defects (OPEN-WORK: **CLAUDE-DEDUP**,
  **CLAUDE-SUBAGENT-KEY**) that this build must NOT inherit — and must not fix either
  (they live in the *calls* path; separate items).
- Per-chat is the natural grain: one transcript file IS one chat, and the user-facing
  unit (`cage insights chats`) is the chat. The kiro precedent (`credits` kind:
  conversation-grain rows, id folds turns, last-write-wins collapse) is the exact
  mechanism, already tested at HEAD.
- **Credits: none, by evidence.** No credit unit exists for Claude Code anywhere on
  disk (research doc §Credits; `costUSD` died in v1.0.9). The row shape carries **no
  credits field at all** — nothing could ever fill it. Never derive one from tokens.

## 2. Definition of done

- [ ] `cage import --agent claude` (and the all-agent sweep / capture-on-read) writes
      `.cage/ledger/claude/chats-YYYY-MM.jsonl` rows for every chat with usage; a
      re-run appends **zero** rows (idempotent by id).
- [ ] The fold is correct by construction: duplicate assistant rows per
      `(requestId, message.id)` counted **once** (last occurrence wins); subagent
      transcripts join their **parent** chat via the row's own `sessionId`.
- [ ] A grown chat appends a fresh row; `ledger.claude_metrics()` collapses to the
      latest per session (never summed).
- [ ] **No derived view reads the new kind**: `cage report` and `cage insights chats`
      stdout byte-identical with the `claude/` tree present vs deleted (tested).
- [ ] `cage doctor` gains an advisory `claude-metrics` line (store found · chats
      seen · a retention nudge when the newest transcript is >25 days old — the
      30-day default sweep). Advisory, never a failure.
- [ ] Counts-never-content holds: no chat titles, no prompt/response text, no
      `tool-results/` reads; `project` is the cwd **basename** only.
- [ ] Full suite green; `test_floor`, goldens, `test_cli_reference` untouched.
- [ ] Documentation updated to match (§9.5) — none skipped.

## 4. Change map (researched 2026-08-13 against HEAD — follow it; re-verify only what looks stale. If COPILOT-METRICS has landed by build time, mirror ITS functions instead of the older precedents named here — the shapes are designed as twins.)

### 4.1 `cage/schema.py` — the row (after `make_credit`, l. 245; substrate change ⇒ PLAN §3 note in same change)

- `make_claude_metric(*, session, project="", surface="", model_totals=None,
  tokens_in=0, tokens_out=0, cached_in=0, cache_write_in=0, ttl_5m=0, ttl_1h=0,
  thinking=0, web_search=0, web_fetch=0, requests=0, raw_rows=0,
  sidechain_tokens_in=0, sidechain_tokens_out=0, ts=None, metric_id=None) -> dict`
  - `agent` fixed `"claude-code"`, `source` fixed `"transcript"` (one store; the
    constant keeps cross-kind symmetry with copilot's source enum).
  - Token semantics **match `make_call`**: `tokens_in` = uncached + cache-read +
    cache-write; `cached_in` = read; `cache_write_in` = write. `ttl_5m + ttl_1h ==
    cache_write_in` when the store carries the split (older rows may not — then omit).
  - All counts **omit-at-zero** (house idiom). **No credits field** (§1).
  - `model_totals`: list of `{model, tokens_in, tokens_out, cached_in,
    cache_write_in}`, keys whitelisted; omitted when empty.
  - `raw_rows` = usage-bearing assistant rows seen; `requests` = distinct folded
    keys. The pair IS the inflation evidence (raw_rows/requests ≈ 2–3× today).
  - id default `ids.new_id("clm")`; the parser always passes a deterministic
    `metric_id`. `CLAUDE_METRIC_FIELDS` tuple beside `CREDIT_FIELDS` (l. 287).

### 4.2 `cage/paths.py` — shard routing (beside `savings_dir`/`savings_shard`, l. 1069–1092)

- `Footprint.claude_dir` property → `self.ledger / "claude"`.
- `Footprint.claude_shard(ts)` → `claude/chats-<YYYY-MM>.jsonl` (no-month fallback
  `chats.jsonl`) — copy `savings_shard`'s month parse exactly.
- `Footprint.shard()` (l. 1094): route plain kind `"claude"` → `claude_shard` (beside
  the `("savings", tool)` tuple branch).
- `Footprint.claude_shards()` → `sorted(claude_dir.glob("chats*.jsonl"))` —
  `chats-2026-08.jsonl` matches `ledger._SHARD_MONTH`, so `--since` month-skipping
  is free.
- **No new sources**: the claude store is already swept
  (`agent_log_sources("claude")` → `~/.claude/projects` + `**/*.jsonl`, l. 485–486 —
  the recursive glob already matches `<sessionId>/subagents/agent-*.jsonl`).

### 4.3 `cage/ledger.py` — the readers (beside `credits`, l. 201)

- `claude_metrics_raw(root)` — concatenated read over `Footprint.claude_shards()`
  (feeds the import seen-set; mirror the `savings()` shape incl.
  `_month_entirely_below`).
- `claude_metrics(root, since=None)` — raw rows collapsed **last-write-wins per
  `session`**, winner = max by `(requests, tokens_in + tokens_out, id)` — the
  `credits()` collapse with `turns` generalized. Docstring states **never sum** a
  session's rows (each row is the chat's whole-life total at capture time; a long
  chat's rows span month shards and the collapse must still win across them).

### 4.4 `cage/transcript.py` — the fold + parser (beside `parse_calls`, l. 67)

- `_fold_claude_chat(files: list[Path]) -> dict[str, dict]` — THE DEDUP LAW as code.
  Stream every file in the session fileset (main first, then `subagents/*` sorted);
  per `type=="assistant"` row with non-empty `message.usage`:
  - fold key = `(requestId, message.id)`; **both empty** (legacy rows) ⇒ key on the
    row `uuid` (no fold possible, none needed). **Last occurrence wins** — later
    duplicates carry the final `output_tokens` (research doc; ccusage #888).
  - chat key = row `sessionId`, else the main file's stem (a fileset may emit >1
    chat key on resume-drift; that is correct, not a bug).
  - per surviving request accumulate into the chat: `input_tokens` +
    `cache_read_input_tokens` + `cache_creation_input_tokens` → `tokens_in`;
    `output_tokens` → `tokens_out`; `cache_read…` → `cached_in`;
    `cache_creation…` → `cache_write_in`; `cache_creation.ephemeral_5m/1h…` →
    `ttl_5m`/`ttl_1h`; `output_tokens_details.thinking_tokens` → `thinking`;
    `server_tool_use.web_search_requests`/`web_fetch_requests` → `web_search`/
    `web_fetch`; `isSidechain` rows also add to `sidechain_tokens_in/out`;
    per-model sums → `model_totals`; `requests += 1`; `raw_rows` counts pre-fold.
  - `ts` = max row `timestamp`; `project` = basename of the last seen `cwd`
    (counts-never-content: basename only). Read NOTHING else — no `summary` titles,
    no content blocks, no `tool-results/`.
- `parse_claude_chat_metrics(fileset: list[Path], session_hint: str = "") ->
  list[dict]` — `_fold_claude_chat` → one `make_claude_metric` per chat key,
  `metric_id = "clm_" + sha1(session + "|" + <canonical sorted-json payload>)
  .hexdigest()[:16]` — **values folded into the id** so a grown chat appends a fresh
  row and an unchanged one dedupes (the `make_credit` turns-fold idea, generalized —
  same as copilot §4.4). Fail-open per file (bad line skipped; unreadable file
  skipped with `CAGE_DEBUG` trace).

### 4.5 `cage/importcmd.py` — wiring (inside `import_claude`, l. 383–433)

- `_claude_session_filesets(files: list[Path]) -> list[list[Path]]` — regroup the
  sweep's changed files into **whole session filesets** so a chat's totals are never
  computed from a partial view:
  - a subagent path (`…/<sessionId>/subagents/agent-*.jsonl`) maps to its parent
    main file `…/<sessionId>.jsonl` (i.e. `f.parent.parent.parent /
    (f.parent.parent.name + ".jsonl")`);
  - each distinct main file expands to `[main] + sorted((main.parent /
    main.stem / "subagents").glob("agent-*.jsonl"))` — **even the unchanged
    members**, because the row is a whole-chat total;
  - a main file whose path doesn't exist (subagent orphan) keeps the fileset without
    it — fold still keys on row `sessionId`.
- `_ingest_claude_metrics(root, files, *, pol=None) -> int` — mirror
  `_ingest_credits` (l. 480): `seen = {r["id"] for r in
  ledger.claude_metrics_raw(root)}` built once per sweep; for each fileset →
  `transcript.parse_claude_chat_metrics(fileset)` → `ledger.append_row(root,
  "claude", row)` per unseen row; fail-open per fileset;
  `debuglog.event(... kind="claude-metrics", appended=n)`. **No own cursor** — it
  rides the calls sweep's `files` (a changed file re-triggers its whole fileset).
- Call site: in `import_claude`'s per-source loop, after `_ingest(...)`
  (l. 417–420): `total_metric_rows += _ingest_claude_metrics(root, files, pol=pol)`
  — the **same `files` list**, no rescan. Metrics rows never enter the call `seen`
  set or the stderr call rollup (they are not calls).

## 5. Technical approach (decided — do not re-litigate)

- **Chat grain, whole-life totals, id-folds-values + collapse-on-read.** The store's
  unit is the chat; each import appends the chat's current totals under a
  value-folded id; the reader keeps the latest per session. Append-only past never
  rewritten.
- **THE DEDUP LAW at capture** — `(requestId, message.id)` last-wins — is reading
  the store correctly (N rows = 1 response is vendor serialization, not N facts),
  not a derivation. It is this build's whole reason to exist.
- **Own kind, own id namespace (`clm_`), own seen-set** — metrics rows can never
  collide with or leak into call views (the `credits` precedent).
- **Session filesets before parsing** — correctness against partial sweeps.
- **No credits field** — absence at schema level, per the research doc's firm no.

## 6. Non-negotiables / constraints

- **Counts-never-content**: assistant-row envelope + `usage` only. Never read
  `message.content`, `summary` titles, user rows' text, or `tool-results/`.
  `project` = basename only.
- **Never fix the calls parser here** — CLAUDE-DEDUP / CLAUDE-SUBAGENT-KEY are
  separate OPEN-WORK items; `parse_calls` and `_usage_to_row` are **do-not-touch**
  in this build (byte-identical calls output is a test gate).
- **No derived view reads the kind in this build** — `report` + `insights chats`
  byte-identity test is the gate; goldens and `test_floor` pass untouched.
- **Absence ≠ zero** where the store lacks a prop (old rows without the TTL split /
  `thinking_tokens`: omit, don't write 0)... except plain token counts, which are
  omit-at-zero by the house idiom anyway.
- **Fail-open everywhere** on the write path; every swallow site logs under
  `CAGE_DEBUG` (`test_debug_coverage` will check).
- **$0 stdlib** · idempotent re-import · append-only (never rewrite a shard) ·
  no cleanup class for the dir (`ledger/` protected by construction).

## 8. Edge cases & risks

- **Mid-chat import** records the partial-so-far totals → healed by id-fold +
  collapse on the next sweep. Test it.
- **Only a subagent file changed** → fileset regroup re-reads the whole session;
  without it the row would be a partial lie. Test it (the §4.5 rationale).
- **Resume drift** (row `sessionId` ≠ filename stem — UNVERIFIED whether resumes
  copy rows): fold keys on row `sessionId`; a fileset emitting two chat keys is
  correct behavior. Never assert stem == sessionId.
- **Legacy rows without `requestId`/`message.id`** → uuid-keyed, no fold (matches
  the pre-2.x store where duplication may differ). Never crash on absent props.
- **A chat spanning months**: rows land in different shards; `claude_metrics`
  collapse wins across shards; a `--since` window that skips the early shard still
  returns the latest row (it lives in the newest month). Note it in the docstring.
- **30-day retention**: a chat older than the sweep vanishes with its transcript —
  its last captured row IS the record (the point of capturing). Doctor nudges.
- **Volume**: one row per changed chat per sweep, single-line rows —
  `LEDGER_WARN_BYTES` already covers runaway growth; no new mechanism.
