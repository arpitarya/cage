# Claude Code prompt — kiro capture routing (K2)

**Model: Opus.** The routing rule is a few lines; the work is breaking a documented
invariant (`importcmd.run`: *"one active sink per run — never a double-write"*) without
breaking the two agents that depend on it. No test pins that invariant today, so a
regression here is silent — which is the exact class this repo keeps paying for.

**No paid LLM calls. The cage tree stays uncommitted** (commits in `cage-lab` only).

## Read first

- [kiro-routing.handoff.md](kiro-routing.handoff.md) — full scope, the per-root table,
  the nested-leg approach
- [ADR 0006](adr/0006-kiro-rows-are-machine-facts-not-project-facts.md) — the decision,
  what was rejected, and the veto condition
- `CLAUDE.md` — capture architecture, fail-open write paths, determinism, method law
- `importcmd.run` and `run_agent` — **read them fully before editing**

## The thing that must not go wrong

**Kiro has two stores and they get opposite fixes.**

- **IDE** `tokens_generated.jsonl` (`parse_kiro_calls`, built-in adapter) — no project,
  no session, no ts ⇒ **route to the global ledger**.
- **CLI** `conversations_v2` SQLite (`parse_kiro_cli_credits`, a **custom tool source**
  with `fmt="kiro-cli"`) — **keyed by cwd**, real conversation id, real timestamp ⇒
  **scope by cwd and stamp `project`**. Routing this one to global destroys attribution
  the source actually supports, and credits are the billed unit.

## Approach

1. **Map before editing.** List every per-root object in `run()` (`seen`, cursors,
   `_import_lock`, `_write_manifest`, `_record_health`, `_record_capture_log`,
   `_import_rollup`) and state what each must do when the kiro sink differs. The
   handoff has a first pass; verify it against the code rather than trusting it.
2. **One resolver** in `paths.py`, beside `canonical_ledger`, deciding kiro's sink from
   `active_ledger_source()`. No caller re-derives the rule.
3. **A contained nested leg** for kiro — its own `seen`, cursors, lock, manifest,
   health — not a rewrite of the sweep. Never hold both locks simultaneously; if
   nesting is unavoidable, fix the order and document it.
4. **Then the CLI half.** Verify how `conversations_v2.key` is normalized against a real
   store *before* filtering on it — a near-miss returns zero rows, which is
   indistinguishable from "no usage".
5. **Then the read-side honesty**, together with **K3/K4**'s wording.

## Hard constraints

- **claude and copilot capture must be byte-identical.** Assert it with a test; do not
  reason that it is unchanged.
- **Explicit `--ledger`/`CAGE_BASE` always wins** — cage-lab's isolation depends on it.
- **Append-only.** Existing project ledgers keep their duplicated kiro rows; never
  rewrite or prune them.
- Fail-open write paths stay fail-open; typed `CageError` only at the CLI boundary.
- Determinism: same ledger + same policy ⇒ same tables. Routing changes *where rows
  land*, never what a derived view computes from a given ledger.
- stdlib only. Do not touch `work/regression/**`. No commits in `cage`.

## Decide and state (not pre-decided)

1. **Whose capture switch governs the global leg?** `policy.capture_enabled` is read
   from the *project* policy, but the write now targets the global ledger. Project's
   switch, global's, or both? Pick one, justify it, make it visible in `--debug`.
2. **What the summary line reports** when a sweep writes to two ledgers. It must never
   imply project rows that landed globally.
