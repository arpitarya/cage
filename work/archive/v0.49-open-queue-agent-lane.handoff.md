## 5. Technical approach (decided)

**P0 — finish the migration in the law.** Mechanical. `docs/README.md` gains a
`docs/open/` entry under the maintained set; `work/DOC-REGISTRY.md` gains a row with an
owner-trigger (*"an item opens, closes, or changes gate"*). The `CLAUDE.md` edit is
**drafted as a diff in the response, not applied** — steering files steer every future
run, so one wrong silent edit poisons every later session.

**P1 — `tests/test_queue_honesty.py`, the staleness gate.** The design the pre-mortem
forced:

- Parse only **positive, checkable claims** out of `docs/OPEN-WORK.md`: a version string
  (`0.48.0`-shaped), a tag (`vX.Y.Z`), and any assertion matching
  *HEAD (is|==) origin/main* / *nothing is unreleased* / *tree is clean*.
- Compare each against ground truth: `cage/__init__.py.__version__`,
  `git tag --sort=-v:refname`, `git status --porcelain`, `git log origin/main..HEAD`.
- **Fail ONLY on contradiction.** A header that states no claim passes. A header that
  says "8 commits ahead" while git agrees passes. A header claiming clean-and-pushed
  against a dirty tree **fails, naming both sides.**
- **Skip, never fail, when ground truth is unavailable** — no git binary, no `origin`
  remote, a shallow CI clone. An unanswerable question is not a failure; this is the same
  fail-open discipline the write path uses.
- Keep it **under ~40 lines of matching logic.** If it needs more, the gate is too clever:
  fall back to **P1-minimal** — assert only that the version and tag named in the header
  match `__init__.py` and `git tag`, and drop the tree-state claims entirely. A narrow
  gate that always tells the truth beats a broad one that cries wolf.

**P2 — the L1 attestation diagnosis.** `cage insights adoption` prints a populated
per-agent table (7 of 9 rows, joined by *session*) and an **empty** "attested by an L1
hook" table, while `.cage/state/attest.jsonl` is non-empty (~4.8 KB). Find the cause.
The join is documented as `args_hash`, an **exact** key, between the attestation store and
the usage breadcrumb — start there and check whether the two sides compute it over the
same input. **Diagnosis is the deliverable.** A fix only lands if the cause is a plain
defect on a path that already exists; anything requiring a new captured field is a
**capture change needing its own proposal** (`docs/proposals/`), not a drive-by.

**P3 — commit hygiene, read-only.** Report what the 47 staged files and 8 unpushed
commits contain, grouped, with a proposed commit split and messages. **Staging and
reporting only.** Arpit runs the push.

## 6. Non-negotiables / constraints

- **`dependencies = []`** — stdlib only. No test helper, no parsing library, nothing new
  in `pyproject.toml`.
- **Determinism law** — no clock, no randomness in a derived view. P1 is a test, so it may
  shell to git; a *view* may not.
- **`method` is sacred** — never let a projection read as `measured`.
- **Fail-open on write paths; typed `CageError` at the read/CLI boundary.** Do not convert
  one regime into the other.
- **Every fix ships with a test that fails before it.** The suite is green now, so "green
  after" proves nothing. For P1, write the falsified-header case first and watch it fail.
- **Three agents always** — claude · copilot · kiro. Any new surface fans out to all
  three, or the gap is *named in output*.
- **Use:** existing helpers — `mergeutil.union_by_id`, `taskgroup.join_rows`,
  `lockutil` for any locking. **Avoid:** hand-rolled `fcntl`, a second join, a parallel
  cleanup class.
- **Do not touch:** `.cage/ledger/**` · `cage/data/**` at runtime · any `_WIRING_ARTIFACTS`
  assertion in `tests/test_floor.py` (wire new artifacts *in*, never relax it).
- **Docs law:** every change updates docs in the same change; a completed item's file is
  **deleted, not ticked**, and only after its outcome is in `IMPLEMENTATION.md`.

## 8. Edge cases & risks

- **P1 on a detached HEAD or a branch with no upstream** → skip, do not fail.
- **P1 in a shallow CI clone** where `origin/main` is absent → skip. Verify against the
  repo's own CI config before assuming which legs have full history.
- **P1 regex over-matching** prose that merely *quotes* a stale claim — the current header
  deliberately narrates its own past errors ("this header previously said…"). **The gate
  must not fire on a past-tense recital of a correction.** This is the single most likely
  false positive; test it explicitly.
- **P2 finds the cause is structural** (attestation genuinely cannot join under transcript
  capture) → that is a *result*. Publish it and update Q3; do not invent a fix.
- **P3 discovering the staged set contains something unintended** → stop and report; do
  not `git checkout` or discard anything.
