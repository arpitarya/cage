## Standing laws

1. **ZERO dummy data.** Real files, used as they are. Nothing simulated, ever. A step
   that can't complete is reported, never faked.
2. **Isolated ledger.** Everything writes to `cage-lab/labledger/`. **`~/.cage` is
   never written** — capture its mtime before and after and assert it didn't move.
3. **The cage tree stays uncommitted.** Commits happen in `cage-lab` only.
4. **`cage/work/regression/**` is never touched.** The old lab's published results
   already live there and are permanent.
5. **Never hand-write a steering block.** Use each tool's own installer.

## The task

`../cage-lab` is being deleted. Rebuild it from `work/cage-lab/01-setup.md`, recording
every command as you go.

### 1. Structure + `.venv` (01-setup §1–2)

- Create the tree from §1.
- `python3 -m venv .venv`; install **cage from local source** (`-e ../cage` — v0.36 is
  unreleased) and a **pinned** `graphifyy`.
- **Record the declared deviation**: cage-lab is black-box by rule and `-e` breaks
  that; note it in `SETUP.md` with its exit condition (switch to the wheel at release).
- **PATH is set explicitly in `drive.sh`/`rebuild.sh`**, never by activation:
  `export PATH="$LAB/bin:$LAB/.venv/bin:$PATH"`.
- Record cage + graphify versions.

### 2. The fixture `_src/` (01-setup §3)

- A small fixed Python package with **one deliberately large module (~8–9k tokens)** —
  without it a graph answer isn't measurably cheaper than reading the file and the A/B
  has nothing to measure.
- Plus several small modules with **real cross-module calls**, so "how does X relate to
  Y" is a genuine question.
- **Hash every fixture file into `SETUP.md`.** These bytes are the control variable.

### 3. The questions (01-setup §4)

Author `questions.txt` — **6 lines, one prompt per line**, split by purpose:

- **~3 graphify-sensitive** — architecture / cross-module / "which module owns X",
  where a graph answer beats grep. These are where the ON/OFF delta gets measured.
- **~3 capture-correctness** — anything that produces turns to meter; content barely
  matters, the metering does.
- **Content-free by construction** (we author them) — that is what lets captures be
  stored byte-exact with no sanitizing.
- Print the six lines in your handback so Arpit can approve or swap them **before** he
  spends anything.

### 4. The two workspaces (01-setup §5)

Both copied from the **same `_src` bytes**.

- **`workspace-off/`** — `git init`, `cage setup --claude`, `cage doctor`. Then assert
  it is *genuinely* off: no `graphify-out/`, no graphify steering in any agent file.
- **`workspace-on/`** — `git init`, `graphify update .`, `graphify claude install`,
  `graphify copilot install`, then `cage setup --claude`, `cage doctor`.
- **Skip `graphify hook install`** — commit-time graph rebuilds add noise to the one
  thing the ON arm measures.
- **Snapshot `CLAUDE.md` after the graphify installers and again after `cage setup`,
  and diff.** Both tools write that file; if one clobbers the other's block, that is a
  finding — record it and find the order that preserves both.

### 5. `drive.sh` (02-run §3) — build it, don't run it

Wire the protocol so Arpit can drive: explicit PATH → prove PATH → pre-snapshot the
agent log dir → ask a question → post-snapshot + diff → copy new logs verbatim →
`cage --ledger labledger import` → write `transcript-map.json`. Leave it ready and
unrun.

### 6. Verification gate — all must pass (01-setup §6)

`rebuild.sh` must exit non-zero if any fails:

- [ ] `command -v graphify` resolves **inside `$LAB`** — not to a machine-global shim
- [ ] that shim routes through **`cage data graphify`** (live), **not `cage graphify`**
      (dead: exits 1, falls through, runs unmetered and silent)
- [ ] `cage doctor` reports the interceptor **live**, not merely present
- [ ] `workspace-on/CLAUDE.md` has **both** a cage block and an installer-written
      graphify block
- [ ] `workspace-off/` has **no** graphify artifacts
- [ ] fixture hashes match `SETUP.md`
- [ ] **one** smoke prompt (cheapest model, ~$0.03) captures into `labledger/` — and
      `~/.cage` mtime is unchanged

⚠️ **The machine has a known stale interceptor** at `anton/bin/graphify` routing to the
dead `cage graphify` verb, reachable via a `.zshrc` PATH append. If it wins over the
lab's, the explicit PATH order in §1 is wrong — **fix the ordering, do not edit
anton.** Healing that file is out of scope by Arpit's direction.

### 7. Record

`SETUP.md`: every command in order · real output summaries · cage + graphify versions
and **which cage build** · the `CLAUDE.md` ownership observation · fixture hashes · the
proven PATH · the declared `-e` deviation. `rebuild.sh`: the same, re-runnable,
self-verifying.

Then update `docs/IMPLEMENTATION.md`, `docs/WORKLOG.md`, and OPEN-WORK §I (foundation
