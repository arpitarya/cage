# Claude Code prompt — the Windows graphify interceptor (`.cmd` twin)

**Model: Opus** for phases 1–2 (extracting a behaviour contract from a shell script with
a recursion guard is diagnosis-grade, and a wrong call re-creates a silent-unmetering
class on a new OS), **Sonnet** for phases 3–5 once the contract exists.

**No paid LLM calls. The cage tree stays uncommitted** (commits in `cage-lab` only).

## The decision, already made

Ship **`graphify.cmd`** — plain text bundled data, no `.exe`, nothing compiled.
**Not PowerShell:** `.ps1` is absent from default PATHEXT, so `graphify.ps1` would never
be found by a bare `graphify` — the exact bug being fixed.

## Approach

1. **Phase 1 — write the contract before writing any batch.** Six behaviours are listed
   in the handoff; verify each against the bash source and correct the list if it is
   wrong. Two implementations of an unwritten contract will drift.
2. **Phase 2 — implement `graphify.cmd`.** Expect these, all real:
   - **no `exec` in cmd** ⇒ `call "%REAL%" %* & exit /b %ERRORLEVEL%`. Nested process;
     Ctrl-C prompts `Terminate batch job (Y/N)?`. **Document the divergence** — do not
     claim parity you don't have.
   - **npm's graphify on Windows is also `graphify.cmd`** — skip cage's own copy by
     **content** (`findstr` for the marker strings), never by filename.
   - `pathshim._INTERCEPTOR` must match the twin — keep the marker strings verbatim.
   - Paths with spaces must survive `%*`.
3. **Phase 3 — wire** (`_install_shim` on Windows, `refresh_shim` heal, launcher mode,
   `cage_command_tail`).
4. **Phase 4 — liveness before the flip.** `pathshim`/`wiringscan`/`doctor` learn PATHEXT
   resolution. A twin with no liveness detection recreates F1 on Windows.
5. **Phase 5 — flip** CI-GF's Windows assertion and drop the README "planned" clause.

## Hard constraints

- **No `.exe`, no compilation, no new dependency.** stdlib + bundled text only; must work
  from `cage.pyz` via `paths.bundled_data()`.
- **Recursion is the failure that already cost this project.** Stacked shims must be
  provably unable to loop — test bash+cmd and cmd+cmd.
- **Passthrough is sacred:** stdout, stderr and exit code identical to direct invocation,
  including the no-real-binary `127`.
- POSIX behaviour must be **byte-identical** afterwards — assert it, don't assume it.
- Fail-open: shim problems degrade to unmetered passthrough, never a broken `graphify`.
- No commits in `cage`; don't touch `work/regression/**`.

## Decide and state

- **Where the twin installs** — `<root>/bin/graphify.cmd` alongside the bash copy, or
  Windows-only? Coexistence matters for Git Bash/WSL users on the same machine.
- **Whether one template renders both twins** (the `runshim.py` pattern) or they are
  hand-paired. TOOL-SDK wants the template; say which you did and why.

## Handback

the install/coexistence decision · template-vs-hand-paired and why · proof POSIX is
unchanged · the CI output showing bare `graphify` metered on Windows.
