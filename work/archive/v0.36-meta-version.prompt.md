# Claude Code prompt — `[meta] cage_version` must derive from the package version

**Model: Sonnet.** The diagnosis is done and the change-map is explicit. Escalate to
Opus only if removing the literal turns out to break the `[meta]` per-key split in
`policy.load` in a way this prompt doesn't cover.

**No paid LLM calls. The cage tree stays uncommitted.**

## The bug

`cage/data/cage.toml` ships:

```toml
[meta]
cage_version = "0.25.0"
policy_version = "0.26.0"
```

`cage/__init__.py` says `__version__ = "0.36.0"`. **Eleven releases stale**, and it is
not decorative:

- `pricescmd.py:150` **prints it** — users see `prices — bundled … (cage 0.25.0)`
- `pricescmd._POLICY_META_KEYS` **copies it into every newly created project**
  `cage.toml`

Meanwhile `manifest.py:54` already does it right — `row.setdefault("cage_version",
__version__)` — derived, cannot drift. And `docs/example/toml-config.md:45` already
shows `0.36.0`: **the doc asserts the invariant the shipped data file violates.**

It drifted because the tests assert the key *exists* and that project meta matches
bundled meta, but **nothing asserts it equals `__version__`**, and nothing in the
release flow mentions it.

## ⚠️ `policy_version` is NOT part of this change

**Do not tie `policy_version` to the package version.** It is a **content counter**:
`freshness.py` and `doctorcmd._policy_version` compare bundled vs project to decide
whether to recommend `cage policy sync`. Tying it to the release would tell **every
project on every release** that its policy defaults are behind, even when nothing
changed — destroying the signal. `prices_version` is date-based and independent for the
same reason.

`policy_version` bumps when the policy defaults actually change. Leave it alone.

## Task

**1. Derive, don't store.** Remove the `cage_version` literal from
`cage/data/cage.toml` and source it from `cage.__version__` at the two places it
surfaces:

- the `prices` header (`pricescmd.py:150`)
- the project-file stamp on create

If removing the key from the bundle breaks `policy.load`'s per-key `[meta]` split or a
schema assumption, **stop and report** rather than working around it — the fallback is
to keep the key and gate it with the test in step 3, but prefer derivation.

**2. Settle the semantics, and write them down.** `cage_version` means two things today:

| where | meaning | correct behaviour |
|---|---|---|
| `manifest.py` row | the version that **produced this row** | historical — never rewritten |
| **project** `cage.toml` | the version that **scaffolded this project** | historical — stamped at create from `__version__`, **not** rewritten on every read |
| **bundled** `data/cage.toml` | *undefined* — which is why nobody bumped it | derive, or delete |

Pick and document: a project's stamp is a **historical fact** and stays put; the
displayed/bundled value is **always the running package version**.

**3. Make the drift impossible.** A test asserting the value cage prints/stamps equals
`cage.__version__`. Same class as the README test-count and changelog rules. If the
bundled key survives step 1, assert `bundled["meta"]["cage_version"] == __version__`.

**4. Release checklist.** Add a line to `CLAUDE.md`'s release rules beside the
changelog / README "what's new" / test-count items. It drifted for eleven versions
because **nothing in the release flow mentioned it** — the checklist entry is the real
fix, the code change is the cleanup.

## Constraints (hard)

- **`policy_version` unchanged.** No new coupling to `__version__`, no bump.
- `prices_version` / `prices_date` unchanged — vendor facts, their own cadence.
- Existing project `cage.toml` files are **not rewritten**; their stamp is history.
- stdlib only; fail-open write path; typed `CageError` only at the CLI boundary.
- Do not touch `work/regression/**`. No commits in the cage tree.
- Update tests that hardcode `"0.25.0"` (`test_prices_split.py` L101) — but do **not**
  weaken an assertion just to make it pass; if a test was pinning the wrong thing, say so.

## Acceptance criteria

- [ ] `cage prices list` header shows **0.36.0**, not 0.25.0
- [ ] A newly scaffolded project's `cage.toml` stamps `cage_version = "0.36.0"`
- [ ] No `cage_version` literal remains as a maintained value (derived, or gated by test)
- [ ] `policy_version` untouched; `cage policy sync` recommendation behaviour unchanged
- [ ] A test fails if `cage_version` and `__version__` ever diverge
- [ ] CLAUDE.md release checklist names it
- [ ] `just test` green; re-blessed goldens named (the `prices`/`doctor` header lines are
      the likely ones)
- [ ] Docs: `example/toml-config.md` verified consistent, GLOSSARY if it defines the key,
      IMPLEMENTATION / WORKLOG / DOC-REGISTRY updated

## Guardrails

- If any behaviour depends on the bundled `cage_version` being *older* than the package
  (e.g. a staleness comparison), **stop and report** — that would make it a real counter
  rather than a stale literal, and this whole change would be wrong.
- Ask before changing `[meta]` parsing or the per-key split in `policy.load`.
