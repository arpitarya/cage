## Step 1 — DISCOVERY (do this before any capture logic)

Nobody knows where Kiro CLI writes usage. Cage knows exactly one Kiro location:
the IDE's `kiro.kiroagent/dev_data/tokens_generated.jsonl`. Find the truth.

1. **Snapshot before** across all three candidate roots:
   - `~/.kiro/**` (docs: `KIRO_HOME` holds "agents, prompts, skills, steering,
     settings, **and sessions**")
   - the IDE globalStorage path cage already knows
   - `$TMPDIR/kiro-log/` (documented as debug logging — expect diagnostics, not
     usage; confirm rather than assume)
2. Run **one** real turn: `kiro-cli chat --no-interactive "<Q1 prompt>"` inside
   `golden/workspace/`.
3. **Snapshot after → diff.** List *every* file created or changed. Cheap
   cross-check: `kiro-cli chat --list-sessions` in that directory — sessions are
   per-directory, so this often points straight at the store.
4. **Record the shape verbatim** in the report: does the written file carry token
   counts? a session id (docs say UUID)? a model? timestamps? Quote real lines.

This step's output is valuable **whatever it finds** — including "usage is not
recorded anywhere", which would be a first-class finding.

## Step 2 — does cage see it?

## Step 3 — attempt the config-only fix (the payoff)

In the run's `cage.toml`:

```toml
[sources.kiro]
paths   = ["<the path discovered in step 1>"]
surface = "cli"     # v0.36 — without this the row inherits the parser's "ide"
```

Re-import; verify with `cage doctor --paths` (prints
`surface=<declared|parser>`).

- **Rows land with `surface="cli"` and correct tokens ⇒ the whole gap was
  configuration.** Put the exact working stanza in the report as *the fix*, and
  say so plainly — that's a config win, not a code change.
- **Rows don't parse (empty, or wrong numbers) ⇒ the fourth-parser finding.**
  Capture the shape verbatim, file it, and **do not write a parser here.** Note
  what a parser would need to read (token fields, session id, timestamps, model).
