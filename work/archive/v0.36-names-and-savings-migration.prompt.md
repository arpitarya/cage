## Task

**A — session names always captured.** Remove `[capture] session_names` +
`policy.session_names_enabled` (pre-release, no compat needed). Lift names in the
parsers: claude = transcript `summary` record, fallback cwd-basename/`project`;
copilot VS Code = the `kind:0` chat title; copilot CLI / kiro = `""` (honest
empty — never a session id, never invented). Thread them to the manifest write
point (`importcmd.run` — unchanged as the chokepoint). The name exists **only**
in `imports.jsonl`: never on call/receipt/savings rows, never in a derived view
or CSV.

**B — precise savings migration.** New `cage data migrate-savings`:
- Dry-run by default: per-tool row count + Σ`saved` in `receipts.jsonl` vs the
  `savings/` tree, and exactly what would copy. `--apply` executes; **refuse** to
  apply if the dry-run totals don't reconcile.
- Copies historical `tool=="graphify"` rows into `savings/graphify/`, each into
  the shard from its **own `ts`**, keeping its **original row id**. graphify
  only — human/fux rows stay put until their sources get tree dirs.
- `receipts.jsonl` is NEVER rewritten — byte-identical after `--apply`.
- `ledger.receipts()` becomes `union_by_id(legacy, tree)`, tree wins on a
  duplicate id, stable deterministic order. This is what makes the number exact:
  idempotent re-runs, half-completed migration, or a crash mid-copy all still
  read each row exactly once.
