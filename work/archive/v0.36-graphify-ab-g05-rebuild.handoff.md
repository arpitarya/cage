# Handoff: G0.5 — rebuild the golden workspace's config layer, with provenance

**One-liner:** Re-derive `cage-lab/golden/workspace/`'s tooling layer using the
tools' **own** installers (`graphify claude install`, `cage setup --claude`) while
preserving the fixture bytes exactly, and record every command so the workspace is
reproducible evidence rather than archaeology.

**Owner / executor:** Claude Code — **Model: Sonnet** (the decisions are made and
the change-map is explicit; this is a recorded rebuild, not a diagnosis). Escalate
to Opus only if verification fails in a way §8 doesn't cover.

**Status:** Ready to build. **No paid LLM calls.** Gates G1 (~2 paid calls).

**Stress-tested:** The debate gate challenged three things and **blocked the first
version of this plan.**

1. **"Dump the workspace and recreate it" would have destroyed the A/B.** Arm A's
   captures were taken against a specific toy codebase. A freshly-authored fixture
   makes the A−B token delta measure *"different repo"* as much as *"graphify
   installed"*. **Survived only in amended form:** rebuild the **config layer**,
   preserve the **fixture bytes** (hash-asserted). Recorded as plan §1.2.0 —
   *rebuild the configuration, never the corpus.*
2. **"Why rebuild at all — just run `graphify claude install` on the existing
   workspace?"** Cheaper and perfectly comparable. **Partly survived:** that is
   effectively what the amended plan does; the rebuild adds only the removal of
   unknown-provenance tooling artifacts and the writing of `SETUP.md`. The
   expensive interpretation was dropped.
3. **`graphify hook install` was in the original step list.** It rebuilds the graph
   on commit — freshness, not usage — and a mid-capture rebuild adds noise to the
   one thing arm B measures. **Cut from scope.**

**Residual risk to watch:** the installed graphify CLI may not match the
documented verbs in plan §1.1 (that table came from docs, not from `--help`), and
`graphify claude install` may clobber cage's `CLAUDE.md` block or vice versa.
Both are *observations to record*, not blockers — but they must be reported, not
worked around silently.

## 1. Context & background

The golden set's graphify A/B ([finding
`2026-07-28-finding-graphify-ab-no-fire.md`](regression/)) concluded "agents don't
invoke graphify unprompted." Inspection showed the workspace had the cage
interceptor shim, a real `graphify-out/` graph, and graphify first in `[tools]
order` — but **zero graphify steering in its `CLAUDE.md`**, and no record of how
any of it was installed. The experiment measured a half-configured condition
nobody can reproduce.

`graphify` ships its own installer — `graphify claude install`, which writes
CLAUDE.md steering **and a PreToolUse hook**. Arm B must use it, because the point
is to reproduce what a real user gets, not what we guessed they'd get.

Plan of record: [graphify-ab-steering.plan.md](graphify-ab-steering.plan.md)
§1.1–§1.2.2. Standing rule this establishes:
[cage-lab-golden-set.plan.md](cage-lab-golden-set.plan.md) §2.4a.

  on PATH — hence §2's requirement to record the hook's invocation form.

## 5. Technical approach (decided)

- **Layered rebuild** (plan §1.2.0): fixture preserved byte-for-byte; tooling
  layer deleted and re-derived. *Rebuild the configuration, never the corpus.*
- **Installers only.** `graphify claude install` and `cage setup --claude`. Never a
  hand-written steering block — that would measure our guess, not the product.
- **Discovery before execution.** `graphify --help` / `graphify claude install
  --help` on the **installed** binary are ground truth; plan §1.1's table came from
  docs and gets corrected on contact (the same rule that caught the `kind:0` claim).
- **Move-aside, don't delete.** Old workspace → `workspace.pre-g05/`; removed only
  after verification is green. Cheap insurance on the one irreplaceable input.
- **Step order is data.** graphify and cage both write `CLAUDE.md`. Snapshot after
  each and diff — which tool clobbers which is the shim-vs-steering ownership gap
  (plan §4) seen from the install side.

## 8. Edge cases & risks

- **`graphify claude install` doesn't exist / is named differently** → record the
  real surface from `--help`, correct plan §1.1, proceed with the real verb. If no
  claude installer exists at all, **stop and report** — arm B's premise is void.
- **The installer clobbers cage's `CLAUDE.md` block (or vice versa)** → record it,
  find the order that preserves both, and note it as a finding. Do not hand-patch
  the file into the state you wish it were in.
- **`cage doctor` reports the interceptor present but not live** → that is the
  known dead-shim failure mode; report it as a blocker for G1 rather than a nit.
- **The PreToolUse hook invokes graphify by absolute path** → do **not** fix it.
  Record it. It is the single most valuable observation available here: it predicts
  the PATH-bypass outcome (plan §1.1a) before G1 spends a call.
- **Fixture hash mismatch at step 7** → the A/B is void. Restore from
  `workspace.pre-g05/` and report; do not proceed to G1.

## 9. Testing & validation

Assert, don't assume. `rebuild.sh` must exit non-zero if any of these fail:

- `sha256` manifest of fixture sources, before vs after → identical.
- `sha256` manifest of `golden/captures/**` and `cage/work/regression/**`, before
  vs after → identical.
- `CLAUDE.md` contains a cage block **and** an installer-written graphify block.
- `cage doctor` → graphify interceptor **live**.
- `graphify-out/` regenerated and non-empty.
- The Claude settings file in the workspace registers the PreToolUse hook.

No unit tests apply (cage-lab is black-box; no cage code changes). `just test` in
cage is untouched and need not run.
