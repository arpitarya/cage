# Handoff: session names always-on + precise savings migration

**One-liner:** Two revisions to the shipped-but-uncommitted v0.36 work (Arpit,
2026-07-25): (A) the capture manifest **always** records a session name (opt-in flag
removed, title lifting implemented), and (B) historical graphify receipts
**consolidate into `savings/graphify/`** via a one-shot migrator whose numbers are
precise — **not wrong, not duplicated** — backed by an id-deduped `receipts()` union.
**Owner / executor:** Claude Code
**Model:** **Opus** — (B) changes ledger reader semantics (union → id-dedupe) where a
wrong call double-counts or drops money quietly; precision is the whole requirement.
**Status:** Ready to build
**Stress-tested:** Challenged: rewrite `receipts.jsonl` instead (simpler end state) →
rejected, breaks the append-only law. Challenged: copy without read-side dedupe →
rejected, double-counts on any partial/repeated run. Survived: copy-with-original-ids
+ `union_by_id` — idempotent, half-migration-safe, byte-identical derived views.
Residual: none identified; the reconciliation gate makes a silent mismatch loud.
**Standing constraint: DO NOT COMMIT** — more work lands in this tree before any
commit/tag/release (Arpit's direction). Leave everything uncommitted.

## 1. Context

v0.36 (uncommitted) shipped the manifest with `session_name` gated behind
`[capture] session_names` (default off, no titles lifted) and savings migration as
read-union-only. Arpit reversed both: names always on; legacy graphify rows move
into the tree with a hard precision bar. Decisions are recorded in
`docs/cage-import-ledger-plan.md` §3 (migration block), §4 (`session_name` note),
and §7 (decisions log) — read those three sections first; they are the spec's
source of truth.

## 2. Definition of done

- [ ] A: `[capture] session_names` flag + `policy.session_names_enabled` removed
      (pre-release — nothing shipped, no compat shim needed); manifest stores the
      best available name unconditionally
- [ ] A: names lifted — claude: transcript `summary` record, fallback `cwd`
      basename/`project`; copilot VS Code: `kind:0` title; copilot CLI / kiro: `""`
      (honest empty — never a session id, never fabricated)
- [ ] A: the name appears **only** in `imports.jsonl` — never on call/receipt/
      savings rows, never in any derived view or CSV (grep-tested)
- [ ] B: `cage data migrate-savings` — dry-run default (prints per-tool row count +
      Σ`saved` for both stores + what would copy), `--apply` executes, refuses to
      apply if dry-run totals don't reconcile
- [ ] B: migrated rows keep **original ids** and land in the shard from their own
      `ts`; `receipts.jsonl` byte-identical after `--apply` (never rewritten)
- [ ] B: `ledger.receipts()` = `union_by_id(legacy, tree)` (tree wins on duplicate
      id); a row present in both stores counts exactly once everywhere
- [ ] B: `attrib`/`report`/`roi` outputs **byte-identical** before vs after
      migration (test-pinned); migrator idempotent (second `--apply` copies 0);
      interrupted-halfway state still reads correct totals (test simulates)
- [ ] `pytest -q` green; docs updated (§9.5); `docs/IMPLEMENTATION.md` entry per
      milestone; **nothing committed**

## 3. Scope

**In:** the two features above + their tests + doc updates.
**Out:** migrating any tool other than graphify (`human`/fux rows stay in
`receipts.jsonl` until those sources get their own tree dirs); any commit, tag, or
release; touching `taskcorr` defaults; cage-lab suite code (its plan doc is already
corrected — R6 asserts names now).

## 4. Key files

`cage/manifest.py` (drop the gate; name param stays), `cage/policy.py` (remove
accessor), `cage/importcmd.py` (thread names from the parsers; write point
unchanged), `cage/transcript.py` (lift claude `summary` + copilot VS Code `kind:0`
title — parse-only, additive), `cage/ledger.py` (`receipts()` → `union_by_id`),
`cage/mergeutil.py` (reuse, don't fork), new `cage/migratecmd.py` (or extend
`exportcmd`-adjacent data group) + `cage/cli.py` wiring under `data`, tests:
`test_manifest`, `test_savings`, new `test_migrate_savings`, fixture corpus
(names now expected in manifest fixtures).

## 5. Non-negotiables

Append-only (no ledger file is ever rewritten); determinism (union order stable —
sort as today, dedupe by id first-seen with tree precedence); `method` untouched on
migrated rows (they keep their original method/confidence); stdlib only; fail-open
on the write path, `CageError` at the CLI boundary; PII — the name widening is
manifest-only and deliberate (plan §7), row stores stay counts-never-content;
**do not commit**.

## 6. Testing

Unit per DoD box, plus: duplicate-id-in-both-stores counts once in every money
view; dry-run/apply reconciliation mismatch path (corrupt a copy target, assert
refusal); claude summary-record parsing on the samples corpus shapes; VS Code
title lifting; kiro/CLI honest-empty. `pytest -q` + a scratch-repo smoke:
import → manifest has names; seed legacy graphify receipts → migrate → attrib
unchanged byte-for-byte.
