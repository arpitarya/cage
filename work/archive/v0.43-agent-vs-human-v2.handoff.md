# Handoff: agent-vs-human v2 — per-commit tokens, authorship, suggested-vs-kept, time

**One-liner:** rebuild the agent-vs-human axis per-commit — tokens, line-level
authorship via transcript line-matching, suggested-vs-kept counts, and guarded time
columns — with **no USD anywhere** on these surfaces.
**Owner / executor:** Claude Code
**Status:** IMPLEMENTED — P1–P4 all built and green (2026-08-02, 1354 tests)
**Stress-tested:** line-match fragility → survives via normalization + min-content
gate + unknown-never-redistributed · `~`-hours reopening the v1 veto → survives as an
amendment under five guards (no rate/USD; method named in output; gap guard; attested
wins; kill-switch) · riskiest assumption = late imports still window-join edits to the
right commits → P1 ends with a dogfood run on cage's own repo reporting match/unknown
rates before views harden. Residual risk: the % split will be read as a productivity
score — the caveat lines in the output are load-bearing, not decoration.

## 1. Context & background

v1 (the Tier-1 human axis) was removed in v0.36 for inventing precision. The v2
proposal was accepted-amended 2026-08-02: per-commit grain, tokens + authorship +
suggested/kept + time. Two audit findings shape everything:

- **Provenance capture is orphaned** — `transcript.parse_provenance` and
  `originrecord.record_transcript` have zero callers. The read surface
  (`origin.explain`, `--attest`, notes-sync) is live; nothing writes automated rows.
- **`latency_ms` only exists on lib-metered calls** — transcript-imported rows carry 0.

## 5. Technical approach (decided) — the detailed implementation analysis

### P1 — capture re-wire + line-match (substrate; no new views)

**New parsing.** Extend `transcript.py` with `parse_edits(transcript_path)` →
per-edit records `{file, ts, lines}` where `lines` are whitespace-normalized
proposed lines from `Edit`/`Write`/`MultiEdit`/`NotebookEdit` blocks (`new_string` /
`content` / notebook `new_source`). **The `lines` never leave process memory** — the
matcher consumes them during import; only counts are written. Lines whose
normalized length < `MIN_MATCH_CHARS` (constant, 4 non-ws chars — tune in review)
are excluded from matching and counted toward `unknown`.

**Commit resolution (the design decision).** For the repo being imported, read
`git log --format=%h|%cI` (same `_git` idiom, fail-open). Each commit owns the
window `(prev_commit_ts, commit_ts]`. An edit belongs to the commit whose window
contains its turn `ts`. Edits after the last commit stay unrecorded this sweep —
idempotency (dedupe key + deterministic ids) makes the next import pick them up
once their commit exists. Never resolve against bare HEAD-at-import.

**Matching.** Per (commit, session): added lines from `git show --format= <sha>`
(transient, in-memory), normalized identically. `kept` = exact matches;
`suggested` = proposed count; per-file enum: `kept` / `landed-modified` /
`dropped` / `not-proposed`. Residual added lines = `human~`; sub-gate lines and
binary/`-` numstat files = `unknown`.

**Persistence.** One provenance row per (sha, agent, session), `method="transcript"`,
`origin="agent"`, existing `files`/`lines_added`/`lines_removed`, plus
additive-optional counts: `suggested`, `kept`, `kept_modified`, `dropped`,
`agent_lines`. Omitted-when-absent so old rows stay byte-identical (the
`scope`/`surface` precedent). `schema_ver` stays 1 (additive). Existing dedupe and
corroboration logic apply unchanged.

**Config.** New `[authorship]` table: `estimate_hours` (bool, default true),
`max_est_gap` (default `"4h"`). Bundle ships it commented, like `[budgets]`.

**Phase gate:** dogfood run on cage's own repo; report rows written, match rate,
unknown rate in the phase notes. If the window join misassigns on the real repo,
stop and revisit before P2.

### P2 — commit-window join for calls (`cage/commitjoin.py`, new)

`commit_windows(root)` → ordered `(sha, ts_lo, ts_hi]` from git log.
`join_calls(calls, windows, tasks)`: **task-id join first** — a call joined to a
closed task whose snapshot `commit` is known lands on that commit (reuse
`taskgroup.join_rows`; do not build a second task join). Fallback: window join —
`call.project == basename(root)` and `ts` in window. Label every joined call
`task` | `window`; a commit with no joinable calls is **unattributed**.
**Per-agent joinability is a stated table:** claude (per-turn ts) and
copilot-vscode (per-request ts) join; copilot-CLI (one shutdown ts per session) and
kiro (import-time / absent ts) never window-join — excluded and counted, the
`legacy_human` footnote pattern. Basename collision (two repos, same name) is a
named caveat in the view, not solved.

### P3 — the views (`cage/commitview.py`, new + cli wiring)

List `cage insights commits [--since]` and detail `cage insights commit <sha>`,
rendered per the mocks below. `cage authorship summary [--since]` ships here too —
pure aggregation over provenance rows (unknown-rate first, `unmatched` shas second).
All three: `--json` envelope, CSV parity, deterministic bytes, refusals rendered.

### P4 — time

`cage task time <duration> [--task id]` → additive task fields `human_minutes`
(int) + `human_minutes_method="attested"` (last-write-wins per task id, as all task
fields). Commit view maps task→commit via the snapshot sha. Columns: wall
(commit-ts delta) · agent (`Σ latency_ms` where >0, labeled measured; else
turn-span with `~`) · human (`*` attested → `~` estimator → `—`). Estimator:
`max(0, wall − agent_span)`, refused when wall gap > `max_est_gap` or
`estimate_hours=false`.

## 6. Non-negotiables / constraints

- **stdlib only**; `dependencies = []` unchanged.
- **Counts-never-content:** no line body, no line hash, no commit message, no
  author identity in any persisted row — transient memory only, and the plant-string
  test (§2) enforces it.
- **Append-only ledger; additive-optional fields omitted at default** so old rows
  stay byte-identical. No new row kinds. `CALL_FIELDS` untouched.
- **Determinism:** same ledger + policy ⇒ same bytes; clocks only in advice lines
  (`render.ago` carve-out). No `Date.now`-style reads inside derived tables.
- **Refusals render** — `—` with the reason named, never omitted, never 0. Unknown
  is never redistributed. `origin="human"` unmarked only via attestation.
- **No USD, no rate, no valuation** on any of these surfaces.
- **Git access:** shell out read-only, 5s timeout, fail-open — `tasks._git` idiom.
- **Do not touch:** `verbmap` tombstones, `_is_legacy_human` guards, `test_floor.py`
  assertions (add views to *new* tests, don't relax the floor), price/policy code.

## 7. Dependencies & prerequisites

None external. Local: a repo with Claude transcripts for the P1 dogfood gate (the

## 8. Edge cases & risks

- Formatter runs (black) after agent edits → lines to `unknown`; expected, documented.
- Squash/rebase/amend → recorded shas dangle → `unmatched` count in `authorship
  summary`; commit views skip wall-clock across rewritten history.
- Multi-agent same file → residual computed after **all** joined agents; both-proposed
  files render `contested` in per-agent breakdowns.
- Session spanning two repos with the same basename → window join caveat, footnoted.
- Task closed on a dirty tree (commit lands after close) → snapshot sha is the *prior*
  commit; task-join must verify snapshot diff counts before trusting, else fall to
  window join.
- Empty diffs / merge commits / binary-only commits → tokens may join, lines refuse.
- Huge transcripts: matching is per (commit, session) set-intersection on normalized
  strings — O(lines); no quadratic pass.

## 9. Testing & validation

- Unit: normalization + min-gate; window assignment (edits at boundary ts, inclusive
  upper); enum classification incl. `not-proposed` and `contested`; estimator guard
  (gap > cap ⇒ `—`; attested beats estimate; kill-switch).
- Idempotency: same transcript imported twice ⇒ zero new provenance rows; commit
  arriving later ⇒ edits recorded exactly once.
- PII plant test (§2): fixture transcript with sentinel strings; grep all shards.
- Goldens: both views + summary, incl. refusal lines and Σ counted-exclusions;
  determinism sweep (run twice, byte-compare).
- Run: `just test` (expect current 1059+ pass, 0 fail baseline maintained each phase).
