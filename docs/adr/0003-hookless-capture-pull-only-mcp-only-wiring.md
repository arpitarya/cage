# ADR 0003 — Hookless capture: pull-only, MCP the only wired surface

- **Status:** Accepted (v0.36.0)
- **Date:** 2026-07-25
- **Deciders:** Arpit (ratifier), Claude Code (executor)
- **Supersedes:** the "hooks are an optional real-time add-on" stance of
  [ADR 0002](0002-universal-capture-global-ledger-explicit-import-export.md) — its
  pull-based groundwork is the foundation this builds on; the add-on itself is now removed.

## Context

ADR 0002 made capture pull-based and global, but kept hooks as an *optional real-time
add-on* and shipped rendered agent assets (skill/prompt/steering) generated by
`tools/skillgen`/`tools/docgen`. Two facts made that residual hook surface a net
liability rather than a bonus:

1. **A dead hook is indistinguishable from cage being absent.** A wiring artifact
   written before a verb was renamed still names the old verb, exits 1, and — because
   hook/shim output goes nowhere and both shims fail open to `exit 0` — silently captures
   nothing while `cage doctor` reports OK. A real machine's `bin/graphify` did exactly
   this for 9 days (the F1 root cause). The liveness detector (`wiringscan`) mitigates it,
   but the whole failure class only exists because hooks exist.
2. **The hook surface carried disproportionate complexity for capture it rarely added.**
   `hooks.py` spanned four subsystems (token capture, provenance buffering, git-hook
   resolution, freshness notes); the rendered assets needed two build-time generators
   (`skillgen`/`docgen`) with their own `--check` CI gates and drift rules. All of it sat
   on top of a pull path that already captured every agent, always — hooks only ever
   *front-ran* the next import, and only under a CLI client.

The decision (2026-07-25, Arpit): remove **all** hook machinery and **all** rendered
agent assets. Capture is pull-only; MCP is the only wired surface. Rebuild hooks/assets
later, if at all, on the cleaner base.

## Decision

**Capture is pull-only (`cage import` + capture-on-read). MCP is the only surface cage
wires. No hook writer, no OS scheduler, no rendered skill/prompt/steering asset.**

- **The pull path is the whole contract.** `cage import` (and capture-on-read before a
  read) sweeps each agent's on-disk usage log into the one resolved ledger. Nothing
  depends on which client wrote the log — the VS-Code-vs-CLI distinction that made hooks
  unreliable is irrelevant to an import.
- **`cage setup` wires MCP and heals; it never writes a hook.** It scaffolds `.cage/`,
  writes the MCP entry (referencing the committed shim on committed files), installs the
  `bin/graphify` interceptor, and *strips* any pre-removal cage hook artifacts (foreign
  hooks untouched). A dead `cage hook-*` verb prints a direction and exits 1
  (`verbmap.REMOVED`).
- **The dead-wiring mitigations stay.** `verbmap.REMOVED` hook-`*` entries,
  wire-module heal-by-removal, and `wiringscan` leftover/dead-verb detection remain —
  real machines still carry pre-removal wiring, and it must surface and heal, not fire.
- **The import path is the one place to make capture loud** (the reason this pays off):
  with every captured row passing through one door, `cage import` prints a per-agent×
  surface token/cost rollup that flags UNPRICED rows, and a single `imports.jsonl`
  manifest records what was captured, when, from where, and how much. Neither was
  buildable when capture could also arrive via a hook.

## Reference

The 9-day silent-capture failure (F1, `docs/regression/`) is the grounding example: a
wired-but-dead hook is worse than no hook, because it reads as installed. Plan of record
for the pull-only rebuild + the import ledger it enables:
[docs/cage-import-ledger-plan.md](../cage-import-ledger-plan.md); the executing
handoff/prompt pair is archived at `docs/archive/v0.36-hookless-rebuild.*`.

## Veto condition (when to revisit)

**Contingent (auto-revisits on evidence).** Real-time capture returns **only** on a
measured need, and lands as a *new, additive* surface — never by resurrecting the old
`hooks.py`. The trigger is a **named latency figure**: a workflow where a read must
reflect a turn that a capture-on-read sweep hasn't yet picked up, and where the staleness
is shown to matter (e.g. "a live dashboard needs sub-`N`-second freshness that
capture-on-read cannot meet"). Absent such a number, the pull path is sufficient by
construction. Any real-time addition must **not** reintroduce the dead-verb failure class:
it may not fail open to `exit 0` in a way `cage doctor` reports as healthy.

**Invariant (product value, moves only by ratified reversal).** "MCP is the only wired
surface" and "cage renders no agent-facing skill/prompt/steering asset" are product
decisions, not volume-gated. Rebuilding those is a deliberate future project, ratified on
its own merits — not something a future agent re-adds to "fix" a perceived gap.

**Deliberately not taken.** Keeping a *thinned* hook (token capture only, provenance and
git-hooks dropped) was considered and declined: any hook at all keeps the dead-verb
failure class alive and the wiring surface non-trivial, for capture the pull path already
does. If it ever returns, it returns under the contingent trigger above, as a new surface
with its own liveness guarantee — not as a `# v2:` half-build of the removed one.
