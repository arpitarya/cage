## The three changes

**1. Retention 30 → 90 days.** `constants.CLEANUP_DEFAULT_DAYS`, **and its justifying
comment** (which currently argues for 30 — leaving it makes the constant disagree with
its own rationale), **and** the bundle's `[cleanup] days`, or a scaffolded project keeps
the old window. `policy.cleanup_days` still wins.

**2. The auto sweep warns and deletes nothing.** `cleanup.maybe_run` computes what
*would* go and prints a reminder; only `cage data cleanup --apply` deletes.

- **stderr, never stdout** — stdout is the deterministic table surface.
- **Silent when zero items are eligible.** A "0 items" reminder trains people to ignore
  it.
- **Honour `CLEANUP_THROTTLE_HOURS`** or it prints on every command.
- **Actionable:** count, window, reclaimable size, and the runnable fix
  (`cage data cleanup` to preview, `--apply` to act).
- **Fail-open** — a broken reminder must never break an import.
- New switch `[cleanup] warn`, **default true**, env `CAGE_CLEANUP_WARN`, via the
  existing `policy._flag` pattern so precedence matches every other switch.

**3. Tool savings can never be cleaned.** `ledger/savings/<tool>/` is already covered by
`NEVER`'s `"ledger/"` — but **only because of where the directory sits**. Add a test that
a `ledger/savings/graphify/savings-2026-07.jsonl` **survives** `prune` even at `days=0`,
and a comment at `NEVER` saying savings are covered via `ledger/` and that a per-tool
cleanup class must never be added.

## Decide and state

**What `[cleanup] enabled = false` means now** that auto never deletes. Either a full off
switch (no reminder, `--apply` refuses) or no-automatic-anything but an explicit
`--apply` still works. **The second is the safer reading** — someone typing `--apply` has
asked plainly — but choose, document it, and make `cage query` agree.

## Hard constraints

- **Do not change the cleanable allowlist.** Only the schedule, the window, and who
  pulls the trigger change.
- **Nothing advisory on stdout.** Derived views must stay byte-identical — prove it.
- Fail-open write paths stay fail-open; typed `CageError` only at the CLI boundary.
- stdlib only; no commits in `cage`; don't touch `docs/regression/**`.

## Known trade-off (accept, don't solve)

With auto-delete gone, `state/` grows unbounded for anyone who ignores the reminder.
That is accepted — unrecoverable deletion is the worse failure. Mitigate by keeping the
reminder recurring (every throttle interval, while items remain) and by including the
reclaimable size so it escalates naturally. **Do not reintroduce automatic deletion.**
