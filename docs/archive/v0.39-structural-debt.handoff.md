# Handoff — the two debt items

**Two halves, different natures.** Part 1 is a **rule** with nothing to build beyond
writing it down. Part 2 is a small feature — **and my proposal was wrong about what it
needs.** Corrected below.

---

## Part 1 — `paths.py` split-on-contact (a rule, ~15 min)

`paths.py` is 1,204 lines and has become the junk drawer: root resolvers · `Footprint` ·
log-source registry · kiro routing · agent homes · shim/bin paths · bundled-data access.
A wholesale split is high-risk (everything imports it) for **zero user value**.

**Write this into CLAUDE.md beside the other fix-on-contact rules:**

> **`paths.py` splits on contact, never wholesale.** The next change that touches one of
> its concerns moves that concern out *with* it. Named seams: `routing.py`
> (`kiro_routed` + `canonical_ledger` + `resolve_root` precedence) · `logsources.py`
> (registry + `resolve_log_sources` + drift) · `agenthomes.py` (`claude_home` /
> `copilot_home` / `kiro_home` + the doctor-bundle env allowlist) · `footprint.py`.
> Pure moves with re-exports from `paths` — no behaviour change, no import breakage.
> **A deletion and a move never share a diff** (CODEX-OUT's verdict): if the touching
> change is a removal, do the removal, and leave the seam for the next one.

That last clause is the lesson from CODEX-OUT, which touches `agenthomes` and correctly
declined to move it. **No OPEN-WORK item after this** — the rule fires on its own.

## Part 2 — bare `cage` needs *state*, not a landing screen

**⚠️ Correction to [the proposal](proposals/structural-debt.md).** It claims *"`cage` with
no args today prints argparse usage."* **That is false.** `cli._ROOT_HELP` is already a
hand-written one-screen brief — daily verbs, grouped subcommands, five worked examples —
and `build_parser`'s formatter returns it instead of argparse's dump. The help is good;
building a "landing flow" would replace something that already works.

**What is actually missing is the answer to "is this thing on?"** A user runs `cage`,
reads a fine menu, and still doesn't know whether a ledger exists, whether capture has
run recently, or whether anything is unpriced.

**Build a one-line state header above `_ROOT_HELP`:**

```
ledger ~/.cage · 1,204 calls · last import 3h ago · ⚠ 12 unpriced
```

Requirements — each load-bearing:

- **One line, above the existing help.** `_ROOT_HELP` is unchanged.
- **Cheap.** Bare `cage` must stay instant; if the state read is not trivially fast,
  degrade to the ledger path alone rather than slowing the command.
- **Honest when empty:** no ledger ⇒ `no ledger yet — run cage setup` (that is the whole
  line; do not fabricate zeros).
- **stdout, and it is a read surface** — determinism applies, and **capture-on-read
  stays OFF here** (bare `cage` must never mutate anything).
- **Fail-open:** an unreadable ledger prints the help without the state line, never an
  error.
- No pager, exit 0.
