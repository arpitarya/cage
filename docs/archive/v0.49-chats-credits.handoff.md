# Handoff: chats-credits — kiro-CLI conversations as chat rows

**One-liner:** `cage insights chats` renders kiro-CLI credit conversations as chat rows
(credits column filled, token cells refuse with `—`) instead of refusing the whole view —
and the false "`cage report` counts it" claim dies with the refusal.
**Owner / executor:** Claude Code (Sonnet — additive, fully specced, decisions locked).
**Status:** Ready to build.
**Stress-tested:** Challenged: token-ranked table pins credit rows to the bottom (survives —
blending axes for rank would violate the never-blended law; bottom + footnote is honest) ·
`ledger.credits` docstring promises "read by no call-based view" (survives — the promise is
re-worded to what it actually protects: credit rows never perturb a token/cost cell; update
in same change) · pricing kiro credits at all (survives — reuse the existing
`[billing.<agent>] usd_per_credit` rung verbatim; rate unset ⇒ count only, never a dollar).
Residual risk: golden churn (re-bless is expected and legal per repo law).

## 1. Context & background

- Chats derives purely from **call** rows. Kiro CLI's SQLite store (`conversations_v2`)
  reports **no token counts** (proven null in the §0 probe), so cage records those
  conversations as **credits** rows (`schema.make_credit`) — a distinct row shape in
  `credits-YYYY-MM.jsonl` shards. Chats' docstring marks them "out of scope for v1".
- **Defect found during triage:** `grep -rn "ledger.credits" cage/*.py` → the ONLY reader
  is `chats._credit_agents`, which powers the refusal text. That text says "next:
  `cage report` — where that usage IS counted". **No view counts it.** The refusal's fix
  pointer is false for the only agent that can trigger it.
- The second bullet in the user-visible refusal (kiro IDE rows route to `~/.cage`,
  ADR 0006; constant session id collapses them) is **correct and out of scope** — that is
  Kiro's store, not cage.

## 2. Definition of done

- [ ] A kiro-CLI conversation renders as one chat row: `credits` filled, `calls` and all
      four token cells `—` in text, **empty** (never `0`) in CSV.
- [ ] Rank key becomes `(-tokens_in, -(credits or 0.0), session)` — deterministic; credit
      rows order among themselves by credits, still below any token-bearing chat.
- [ ] Cost: `creditprice.rate_for`-style lookup (`[billing.kiro] usd_per_credit`) →
      `credits × rate`, basis `credits-rate`, aggregate method degrades to `modeled`.
      Rate unset ⇒ cost `—`, credits render as a **count** (rate unset ≠ rate zero);
      rate `0.0` ⇒ `$0.0000`. Chat-row `method` in CSV: `estimated` when unpriced
      (the row's own recorded method — weaker tag wins), `modeled` when rate-priced.
- [ ] The credits structural refusal (`_structural_reasons` first bullet + the
      `credit_agents` footer gap in `render_chats`) is **removed/replaced** — those
      conversations now render, and no surviving text claims `cage report` counts them.
- [ ] New footer caveat on any view showing credit-row chats, one phrasing:
      `· kiro CLI reports credits only — its store carries no token counts, so token
      cells are '—' (`cage query copilot-credits`)`.
- [ ] `--since` works (`ledger.credits(root, since=…)` + row-level cutoff, same as calls).
- [ ] `--all` / top-20 cut / CSV-never-truncated behave identically for credit rows.
- [ ] agent% for kiro refuses `—` via the existing `COVERAGE_GAPS` path (kiro persists no
      edit payload) — no new authorship logic.
- [ ] Goldens re-blessed; new tests green; **full suite green**.
- [ ] Every doc in §9.5 updated in the same change; handoff/prompt pair archived on
      implement per the lifecycle rule.

## 5. Technical approach (decided — do not re-litigate)

- In `summarize()`: read `ledger.credits(root, since=…)`, apply the same `ledger.since`
  row filter, bucket by the existing `_bucket_key` (with `agents.row_surface`
  normalization), one bucket per conversation. Mark the bucket (e.g. `from_credits: True`)
  so renderers can refuse token cells; never fabricate `calls`/token zeros into cells.
- Title: same `names.get((agent, session))` manifest join as calls; fallback = shortened
  session id. (See OPEN QUESTION on a store-side title.)
- `credit_agents`/refusal machinery: agents whose credit rows now render must not appear
  in a structural refusal. If the shape is fully covered, delete `_credit_agents`'s role
  in `_structural_reasons` rather than keeping dead text.
- Sorting, pricing, method, CSV emptiness: exactly as pinned in §2.

## 6. Non-negotiables / constraints

- **Determinism:** no clocks/random in the derive; same ledger + policy ⇒ same table.
- **Method law:** never `measured`; `estimated` (row) / `modeled` (rate-priced aggregate);
  the weaker tag always wins.
- **Absence ≠ zero:** `—` in text, empty cell in CSV; a recorded `0.0` credits renders
  `0.00` — they are different facts. `$0.0000` only from a real `0.0` rate.
- **Never blended silently:** credits never enter `tokens_in`/`unpriced_tokens`/any token
  aggregate; the rank key change is the only place both axes meet, and it is ordering, not
  arithmetic.
- **No silent caps; CSV never gates or truncates.**
- **$0 / stdlib only; fail-open write paths untouched (this is a pure read change).**
- **Do not touch:** `schema.py` row contracts, any ledger writer, `importcmd`,
  `report.py` money paths, `mcpserver.py`, wiring modules.
- **tests/test_floor.py must stay green untouched** — this is derive-only; if floor
  reddens, the change is wrong, not the test.

## 8. Edge cases & risks

- Credit row with empty `session` → existing `(no session)` label path; still one bucket.
- An agent with BOTH call chats and credit chats (future copilot shape): distinct
  sessions ⇒ distinct rows; if ever the same session, the bucket must not mix — keep
  credit buckets keyed apart (the `from_credits` mark is part of identity if needed).
- Resumed conversation: `ledger.credits` already collapsed it — do not re-collapse or sum.
- `--agent kiro` with only credit rows: view is now non-empty — the golden that pins
  today's refusal changes; re-bless deliberately.
- Empty credits shard / no shard: byte-identical to today (minus removed refusal text).
