## Step 1 — Copilot delta-id fix (HIGH, blocks Phase 2)

`transcript.parse_copilot_calls` (~345–388). Copilot's `session.shutdown` metrics
are **cumulative**; the id `c_cop{sid[:12]}{i:03d}` has no shutdown ordinal, so
shutdown #2 collides with #1 and is dedup-dropped → 16–18% undercount.

1. Put the shutdown **ordinal** in the id.
2. **Ordinal 0 must produce byte-identical ids to today's scheme.**
3. Store the **delta** per shutdown (`cumulative_n − cumulative_{n−1}`).

Why (2) is load-bearing — history self-heals instead of double-counting:

```
legacy row      c_cop{sid}000 = 70,071
re-import       c_cop{sid}000 → same id, same value → dedupes (no change)
                c_cop{sid}<ord1> = 37,510 → appends      total 107,581 ✅
import again    0 new rows                                ✅ idempotent
```

A fresh id for ord 0 adds 70,071 twice. **Review this hardest.**

Also determine whether `totalPremiumRequests` is cumulative; if so it needs the
same delta treatment.

**Tests (all four):** grown two-shutdown session totals exactly the cumulative ·
re-import adds 0 · an already-imported **legacy** session re-imports to the exact
total with no double count · premium not multi-counted.

**Do not** mutate a ledger row to achieve this. Append-only is not negotiable, and
delta rows are *more* precise anyway — they keep the per-turn breakdown a mutating
row would destroy.

## Step 2 — Kiro CLI (only if Step 0 says tokens are unavailable)

- **SQLite parser**, stdlib `sqlite3`, opened **read-only**
  (`file:…?mode=ro`; never write, never migrate the DB). Store:
  `~/Library/Application Support/kiro-cli/data.sqlite3`, table
  `conversations_v2(key=cwd, conversation_id, value, created_at, updated_at)`.
  Yields session ids, ms timestamps (kiro's first real `gap_ms` source), model id.
- **Counts-never-content guard:** never read the `value` transcript body, never
  touch `auth_kv`. A test must assert no prompt/response text can reach a ledger
  row. This is the hardest place in cage to hold that law — content and metadata
  share a row.
- **Credits are not a call row.** `tokens_in=0` would be a lie that poisons every
  average. Use a distinct row shape / `unit="credits"`, tagged `estimated`.
  **Default: record credits, do not price them** — an unattested credit rate is a
  guess wearing a number. Ask before pricing.

## Step 3 — the two smaller fixes

- **Surface-restamp collision:** a declared `[sources] surface` is silently lost
  when rows collide by derived id with a built-in source. Make the declared value
  win, or make the loss loud. Silence is the bug.
- **Graphify shim recursion:** stacked shims (fresh + a stale `cage adopt` one)
  each strip only their own dir and resolve to each other → hang. Break the loop.

## Step 4 — Directive A: ADDITIVE PARTS ONLY (scoped 2026-07-28)

**Scope decision — read this before writing anything here.** Arpit scoped this
step down after you flagged the test-harness cost. **Land only the additive
parts; change no resolution semantics.** The exclusive-authority flip and the env
rule move to their own cycle (`docs/config-authority.plan.md` Part 2).

**In scope now:**

- `cage setup` / `initcmd` materialize the built-in defaults as an **active
  `[sources]` table** — project **and** global `~/.cage`.
- `cage doctor` **diffs the project's table against the bundled defaults** and
  reports drift (missing new defaults, paths cage no longer ships).
- `cage setup --sync-sources` refreshes explicitly, without clobbering
  user-added entries.

**Explicitly OUT of scope this cycle — do not do these:**

- Making `[sources]` the exclusive runtime authority.
- Removing env from path resolution.
- Migrating the ~25 test files off home-env redirection.

**Why:** the re-run in Step 6 exists to answer one question — did the Copilot
delta-id fix work? A resolution change in the same run makes a red cell
ambiguous, and would put the V1/V2 byte-identical gate at risk. Everything here
must be additive enough that **V1/V2 stay byte-identical by construction**.

## Step 6 — RE-RUN Phase 1 and prove it — **FAILURES FIRST**

Run the cells the fixes targeted **before** the ones that already passed. Fast
verdict, and no wasted calls if a fix didn't land.

**Order — and it is a gate, not a preference:**

| order | cells | expected |
|---|---|---|
| **1st** | **V3 / V4 copilot** | **8/8**; tokens_in exactly **227,298** and **233,675** |
| **2nd** | **V5 / V5b kiro** | rows present if Step 2 landed; token fields honestly absent/`estimated`; check 2 stays `◻ n/a` |
| **3rd** | **V1 / V2 claude** | **8/8, byte-identical numbers** — the regression check |
| all | — | config provenance shows the active `[sources]` table from `cage.toml` |

**Between groups: if a previously-failing cell still fails, STOP and report.**
Re-running the green cells proves nothing while the fix is still broken, and
these are real paid calls. Only continue past a red if the failure is provably
unrelated to the fix (protocol or environment) — say which, explicitly.

The claude cells run **last** and their bar is **byte-identical to baseline**.
Anything else means a fix leaked into a path it had no business touching — treat
that as a regression, not a curiosity.

Plus the **self-heal proof** (do not skip): re-import an already-captured Copilot
session against the fixed parser → exact cumulative total, no double count →
a third import adds zero rows.

**If a cell doesn't go green, report it.** Never adjust a check to pass.

## Constraints (hard)

  tests keep their shape.

- **DO NOT COMMIT in `cage/`** (commit in `cage-lab/`); append a
