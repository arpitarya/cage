# Proposal — "Measured on itself", as a snapshot the README never has to chase

**The README's demo is seeded; cage's own ledger is real.** Publish it as a **dated
snapshot doc**, link it from the README **once — version-free and date-free**, and guard
its freshness with a **test**, not a release-checklist line. Needs your accept on two
things: the `docs/dogfood/` home and the 60-day gate.

**Changed from the 2026-08-01 draft:** it pasted numbers *into* the README, stamped
`as of v0.37.1`, refreshed by a checklist line. All three are replaced — see *Why the
first draft was wrong*.

## The shape

| piece | what | who touches it |
|---|---|---|
| `docs/dogfood/<date>.md` | one snapshot per refresh, append-only, never edited after | dev machine, ~1h |
| `docs/dogfood/latest.md` | mirror of the newest (the `regression/latest-*` pattern) | same run |
| README pointer | one line → `latest.md`, replacing `▶ Demo GIF coming soon.` (line 16) | **written once, never again** |
| freshness guard | a test failing when `latest.md`'s `snapshot_date` is >60 days old | CI, every run |

## Rules (standing law, restated because marketing is where it dies)

- **ZERO dummy data** — the real ledger, dev machine only (the Cowork sandbox cannot).
- Method tags survive into the snapshot: a `modeled` stays labelled.
- Gross keeps its gross note; UNPRICED is shown, not trimmed.
- PII: counts-only by construction — still read it before publishing.
- **The window is absolute, never relative.** `report`/`attrib`/`adoption` all take
  `--since`; a *relative* window measures something different each refresh, so snapshots
  stop being comparable **and a stale number can move down**. Fix the start date, or go
  all-time — then staleness only ever understates, which fails safe.

## Why a date gate, not a version gate

- **Version was never the freshness axis.** A ledger spanning v0.12→v0.43 belongs to no
  single version; the stamp records only *which build took the snapshot*. Keep it as
  provenance, don't gate on it.
- **Version-distance is a broken clock here** — v0.37→v0.43 shipped inside ~two days, and
  `__version__` is deliberately *not* bumped for in-tree work (v0.44 sits unreleased at
  `0.43.0` today). A 3-release gate could fire in a day, or never.
- **The gate must run with no ledger present**, so it reads frontmatter, not numbers.
  That is the only reason it can be a test at all.

## Why the first draft was wrong

- A refresh-per-release **checklist line** is the exact pattern `[meta] cage_version`
  already burned this repo with — it drifted **eleven releases** because the checklist
  item was missing. The repo's own verdict is *derive or guard, never remind*.
- **Its own stamp was stale on read** — written `v0.37.1`, read at `v0.43.0`. The failure
  mode demonstrated itself inside the document.
- A README-inline block invites an edit every release; a `latest.md` link needs zero.

## Deliberately not taken

**The README-inline block, numbers in the front door.** It reads stronger — evidence
without a click — and that is a real loss, named not buried. Declined because it puts a
hand-maintained number in the one file each release already edits three other things in.
**Reopen trigger:** once two consecutive snapshots agree in *shape*, inline the single
headline figure and keep the link for the rest.
