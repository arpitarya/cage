# Handoff: graphify-chats — `cage insights graphify`, per-chat usage & saving

**One-liner:** a new view answering "which chat used graphify, and what did it save
there" — one row per chat: recorded tokens (the with-graphify world), the modeled
without-graphify counterfactual, and the gross saved share.
**Owner / executor:** Claude Code (Sonnet — additive view, decisions locked below).
**Status:** Ready to build. Sequencing gate already satisfied — CHATS-CREDITS landed
2026-08-13 (its `from_credits` bucket mark is a dependency of the change map below).
**Stress-tested:** "total token" vs "with graphify" are the same number — merged into one
column, both meanings footnoted (two identical columns would fake a distinction) ·
"% saved" from an estimator counterfactual survives only as `modeled` + `GROSS_NOTE`
verbatim (netsaved owns the phrasing) · per-chat NET is impossible today (calls carry no
tool-use mark; netsaved proves task-window netting is the floor) — this view is
explicitly GROSS and says so, never "savings minus cost". Residual risk: the view may
render empty on Arpit's real ledger (receipts were zero at last audit) — the empty state
must diagnose, not shrug.

## 1. Context & background

- Savings rows (`schema.make_savings`) carry `session` + `saved`/`raw_alternative`/
  `actual`, and every graphify transcript route stamps the REAL chat id: claude
  (cli+vscode), copilot-cli (events.jsonl), copilot-vscode (chatSessions), kiro-cli
  (conversation_id). The native shim stamps an honest-empty `session=""` (GC3 — it
  cannot know). So per-chat grouping is a pure derive; **no view does it today** (roi =
  per tool, attribution/netsaved = per task, why = per call).
- Savings rows carry **no agent field**; agent falls out of joining the session to the
  chat universe (calls ∪ kiro-cli credits), the same bucketing chats uses.
- `saved` is GROSS (netsaved.py): the avoided read cost, excluding the cost of *using*
  graphify. Per-chat net is not computable (no tool-use mark on calls) — out of scope.

## 2. Definition of done

- [ ] `cage insights graphify` renders, one row per chat that has ≥1 graphify savings
      row OR appears in the chat universe with `--all-chats` (default: receipt-bearing
      chats only — the focused table Arpit sketched).
- [ ] Text columns: `chat · agent · surface · gfx uses · tokens · without gfx · saved ·
      saved%`. `tokens` = the chat's recorded `tokens_in + tokens_out` (this IS the
      with-graphify world — footnote states the identity and that cached/cache-write are
      excluded from the comparison). `without gfx` = `tokens + Σsaved` (modeled
      counterfactual). `saved%` = `100 × Σsaved / (tokens + Σsaved)`, whole percent.
- [ ] Flags: `--since`, `--agent`, `--csv`, `--all` / `--all-chats`. No `--usd` in v1 —
      tokens-only view, the v0.36 no-blend law.
- [ ] Refusals are distinct facts, never 0%: chat with no receipts → gfx cells `—`
      (only with `--all-chats`); kiro-cli credit chat (no token counts) → `saved` shown,
      `tokens`/`without gfx`/`saved%` `—` with its own footnote; a measured
      `saved == 0` renders `0%`.
- [ ] Nothing dropped silently: shim rows (`session=""`) → one "unassignable" footer
      line (count + Σsaved); savings sessions matching no chat bucket → one "unmatched"
      footer line. Neither ever redistributes into a chat row.
- [ ] Footer carries, verbatim: `netsaved.GROSS_NOTE`; the estimator caveat (counterfactual
      tokens are `graphifymeter.toks` estimates, recorded tokens are provider-metered —
      the % mixes the two and is `modeled`); worst-case method/confidence over the rows
      (attribution's precedent); kiro coverage line(s) from `graphifytx.GRAPHIFY_COVERAGE`
      when a kiro row/refusal is present (one phrasing, never re-worded).
- [ ] Empty state diagnoses: no graphify savings rows at all → point at
      `cage query graphify-coverage`, `cage doctor` (shim/coverage checks), and
      `cage insights roi`; a filter-caused empty blames the filter only when true
      (the chats `_render_empty` discipline).
- [ ] CSV: same rows untruncated; refused cells empty (never 0); adds `session`,
      `raw_alternative`, `actual`, `receipts`, `method`, `confidence` columns.
- [ ] Deterministic; goldens blessed; new tests green; full suite green; docs in §9.5.

## 3. Scope

**In:** new `cage/graphifychat.py` (summarize + text/CSV render), CLI wiring under
`insights`, tests, goldens, docs.
**Out (explicit — do NOT add):** per-chat NET (structurally impossible — netsaved §
"attributable-cost rule"); USD anywhere in this view; changes to savings writers,
routes, or `receipt_id`; fux or any other tool (graphify only in v1 — but key the
summarize on a `tool: str = "graphify"` param so v2 is a flag, not a rewrite); MCP
tool; changes to chats.py beyond importing its helpers.

## 4. Change map (researched 2026-08-13 against post-CHATS-CREDITS code — follow it;
## re-verify only what looks stale)

**The zap decision:** do NOT build a chat universe. `chats.summarize(root, pol, since,
agent)` already returns every chat row with title, normalized `agent`+`surface`,
`session`, token sums, and `from_credits` marks (kiro-CLI conversations included since
2026-08-13). The new module calls it and joins savings onto its rows. One new file
(~150 lines), one CLI block, one handler, one test file, docs.

**NEW `cage/graphifychat.py`** — the whole feature lives here:
- `summarize(root, pol, since=None, agent=None, tool="graphify") -> dict`
  1. `base = chats.summarize(root, pol, since=since, agent=agent)` — reuse verbatim.
  2. `sav = [r for r in ledger.since(ledger.savings(root, since=since), since) if
     r.get("tool") == tool]` (shard-skip + row cutoff, the same double filter
     `chats.summarize` applies to calls).
  3. Savings rows carry **no agent** — join by `session` alone: build
     `by_session: dict[str, list[dict]]`, skipping `session == ""` into an
     `unassignable = {"receipts": n, "saved": Σ}` tally (shim rows, GC3).
  4. For each `base` row: attach `receipts` (count), `saved`, `raw_alternative`,
     `actual` (sums), worst `method` via `constants.METHOD_TRUST` (min trust wins) and
     `min(confidence)` — the exact `attribution.receipts_by_tool` aggregation, inlined.
     A session matching >1 chat bucket (surface split) attaches to each and sets
     `gfx_split=True` — the `auth_split` precedent, footnoted at render.
  5. Cells per row: `tokens = tokens_in + tokens_out` (`None` when `from_credits` —
     absence, not zero), `without = tokens + saved`, `pct = 100·saved/without` (`None`
     when `tokens is None` or `without <= 0`), `has_gfx = receipts > 0`.
  6. Sessions in `by_session` joined to NO base row → `unmatched = {"receipts", "saved"}`.
  7. Return `{"since", "agent", "rows", "unassignable", "unmatched",
     "any_savings": bool(sav)}` — untruncated; ranking/filtering is render-time.
- `render_view(data, show_all=False, all_chats=False, kiro_route="") -> str` —
  default rows = `has_gfx` only (`--all-chats` lifts); rank `(-saved, session)`;
  top-20 (`constants.CHATS_DEFAULT_ROWS` precedent — add `GRAPHIFY_CHATS_DEFAULT_ROWS
  = 20` beside it) with counted cut + `--all`. Table via `render.table(head, rows,
  rights=…)`; cells via `render.tok`/`render.pct`; refusals via `display.DASH`.
  Footer via `display.Footer`: `netsaved.GROSS_NOTE` verbatim (footnote) · estimator
  caveat (`graphifymeter.toks` estimates vs metered tokens — the % is `modeled`) ·
  worst method/confidence line · `graphifytx.coverage_lines()` rows when a kiro row or
  kiro refusal is shown · split footnote when any `gfx_split` ·
  unassignable/unmatched gap lines (counts + Σsaved — never dropped silently).
  Empty states: no savings at all → diagnose (`cage query graphify-coverage`,
  `cage doctor`, `cage insights roi`); filter-empty blames the filter only when
  `any_savings` is true (the `chats._render_empty` discipline).
- `render_csv(data) -> str` — `csvout.table`; untruncated, every row (CSV never gates,
  no `has_gfx` filter); refused cells empty; columns: `chat agent surface session
  receipts tokens without_graphify saved raw_alternative actual pct method confidence`.

## 5. Technical approach (decided — do not re-litigate)

- Reuse `chats.summarize` — never re-derive buckets, titles, or normalization; if a
  needed field is missing from its rows, STOP (that's a design conflict, not a gap to
  bridge with a second bucketing).
- Join by `session` only (savings rows carry no agent); split-attach + footnote, the
  `auth_split` precedent. Rank `(-saved, session)`; agent spelling stays the existing
  `agent` + `surface` pair; `gfx uses` = receipts count, never mixed with tokens.

## 6. Non-negotiables / constraints

- Determinism (no clock/random) · method law (`modeled` everywhere here, worst-case
  surfaced; never `measured`) · absence ≠ zero (`—`/empty vs a real 0/0%) · GROSS_NOTE
  verbatim, never re-worded · tokens never × USD in this view · no silent caps · CSV
  never gates · $0 stdlib · counts-never-content (session ids and counts only — never a
  query, path, or answer body).
- **Do not touch:** savings/receipt writers, graphify routes, `receipt_id`, chats.py
  internals (imports only), report/verdict/roi/netsaved numbers.
- `test_floor.py` and `test_cli_reference` stay green; CLI.md gains the new command
  (that IS a CLI change — unlike chats-credits, this one updates `docs/CLI.md`).

## 8. Edge cases & risks

- Same content captured by shim (`session=""`) AND transcript route: `ledger.receipts`'
  id-dedup/deferral already collapses cross-route duplicates — never re-dedupe here.
- A chat whose every savings row is `report-read`: lower confidence rides the worst-case
  footnote; nothing special-cased.
- `saved` can be ≤ 0 on a real row (answer cost ≥ read cost) — render the negative
  honestly; `without gfx` may then be below `tokens`. Never clamp.
- Zero-token chat with receipts (all calls cached?): denominator `0 + Σsaved` — pct is
  100%; render it, footnote the shape if it appears in goldens.
