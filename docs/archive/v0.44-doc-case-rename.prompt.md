## The problem in one line

The tracked file is `docs/formulas.md`; 120 citations across 49 files spell it
`docs/FORMULAS.md`. macOS (`core.ignorecase = true`) hides this completely — every link
opens locally and dies on the renderer.

## Context to load first

- `git ls-files docs/*.md` — see that every other tracker doc is ALL-CAPS.
- `head -3 docs/formulas.md` — its own H1 is `# FORMULAS`, no frontmatter. ALL-CAPS was
  always the intent.
- The handoff's §4 change-map: the rename plus exactly **two** code docstrings.

## Task

1. **Re-verify nothing reads the filename** before touching it: no `docs/` glob in
   `tests/` or `tools/`, no reference in `MANIFEST.in` or `pyproject.toml`. Report what
   you find. If anything does read it, **stop**.
2. **Rename in two steps** — `core.ignorecase = true` makes a direct case-only `git mv`
   a silent no-op:
   ```
   git mv docs/formulas.md docs/_formulas.tmp
   git mv docs/_formulas.tmp docs/FORMULAS.md
   ```
   **Verify with `git ls-files docs/ | grep -i formulas`, not `ls`.** `ls` cannot tell
   you what git recorded, and a silent no-op is the main failure mode here.
3. **Fix the two live code citations** — `cage/roi.py:85` and `cage/report.py:682`
   docstrings. These are the only lowercase citations in shipping code.
4. **Doc sweep** — handoff §9.5.

## Leave these lowercase — they are correct

`CHANGELOG.md` · everything under `docs/archive/` · `docs/IMPLEMENTATION.md:1051` ·
`docs/graphify-out/` · and specifically `docs/WORKLOG.md:39` and `:213` plus

A deliberately historical citation is correct and must read as past tense. Do not
"helpfully" normalise them.
