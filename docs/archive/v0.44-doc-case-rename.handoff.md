# Handoff — DOC-CASE: the tracked file is `formulas.md`, 120 citations say `FORMULAS.md`

**One-liner:** rename `docs/formulas.md` to `docs/FORMULAS.md` and repair the two live
code citations that spell it lowercase — turning ~120 links that dangle on GitHub and
every case-sensitive checkout into working ones.

**Executor:** Claude Code. Small, bounded, reversible.

**Stress-tested:** four challenges. **Held:** net effect is measured, not assumed — 120
uppercase citations become correct and exactly **2 live code citations** break, both
docstrings (§4); nothing reads the filename programmatically (verified: no glob of
`docs/`, no MANIFEST/pyproject reference); `git mv` preserves history. **Residual:**
`core.ignorecase = true` on this machine makes a naive one-step `git mv` a silent no-op
— §5 D1 is not optional. **Not blocking.**

Filed as **DOC-CASE** in [OPEN-WORK.md](OPEN-WORK.md).

## 1. Context

- Every other maintained tracker doc is ALL-CAPS: `CLI.md` `DOC-REGISTRY.md`
  `GLOSSARY.md` `IMPLEMENTATION.md` `INTERVIEW.md` `OPEN-WORK.md` `PLAN.md` `README.md`
  `WORKLOG.md`. `formulas.md` is the only lowercase one.
- Its own H1 is `# FORMULAS` and it carries no frontmatter — the ALL-CAPS convention was
  always the intent. Only the filename missed.
- **Measured:** 120 occurrences of `FORMULAS.md` across 49 files, including CLAUDE.md,
  `docs/README.md`, `DOC-REGISTRY.md`, and four `cage/*.py` modules. On macOS
  (`core.ignorecase = true`) every one resolves; on GitHub's renderer and any
  case-sensitive checkout every one is a dead link.
- **This is the second sighting.** `WORKLOG.md:213` records a 2026-08-02 Cowork session
  spotting it and explicitly leaving it alone — and never filing it. That is the exact
  defect the OPEN-WORK discipline names: *discovering work and not filing it is the same
  defect as finishing work and not removing it.* Worth naming in the WORKLOG entry.

## 5. Technical approach (decided)

- **D1 — the rename is two steps, because `core.ignorecase = true`.** A direct
  `git mv docs/formulas.md docs/FORMULAS.md` can no-op or error on this machine. Use a
  temp name:
  `git mv docs/formulas.md docs/_formulas.tmp && git mv docs/_formulas.tmp docs/FORMULAS.md`
  Then **verify with `git ls-files docs/ | grep -i formulas`**, not with `ls` — `ls`
  cannot tell you what git recorded.
- **D2 — verify, don't assume, that nothing reads the name.** Already checked (no
  `docs/` glob in `tests/`/`tools/`, no MANIFEST or pyproject reference), but re-confirm
  before renaming. This repo's standing lesson: verify a shape against real data before
  coding to a claim.
- **D3 — CLAUDE.md's ALL-CAPS list omits FORMULAS**, so it should gain it. That is a
  steering-file edit ⇒ **propose, never apply** (§6).

## 6. Non-negotiables

- **Do not edit `docs/FORMULAS.md`'s contents.** This change is a filename and two
  docstrings. Content drift here would be invisible inside a rename diff.
- **Do not rewrite history-class citations** — §3's out-of-scope list is binding. A
  deliberately historical citation is correct and must read as past tense.
- **CLAUDE.md is not edited by you.** Write `docs/claude-md-doc-case.proposed.md`
  containing the proposed one-line addition (`FORMULAS.md` into the ALL-CAPS
  entry-point/tracker list), add it to `docs/README.md`'s *Active work*, file the review
  as an OPEN-WORK row, and stop — the HR-CLAUDEMD / CC-CLAUDEMD precedent.
- **Do not touch:** any other file under `cage/` · tests · goldens · `data/`.

## 7. Prerequisites

None. No env, no network, no upstream work.

## 8. Edge cases & risks

- **The silent no-op.** The whole change can appear to succeed and record nothing.
  `git ls-files` is the only check that counts (§5 D1).
- **A stale in-flight branch or worktree** could re-introduce the lowercase name on
  merge. Note it in the WORKLOG entry so the next session recognises a regression.
- **Case-only renames confuse some editors' file watchers.** Harmless; re-open the file
  if it looks empty.

## 9. Testing
