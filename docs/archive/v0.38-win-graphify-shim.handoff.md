# Handoff — a `.cmd` twin of the graphify interceptor

**The gap:** `cage/data/shims/graphify` is an extensionless bash script. Windows resolves
a bare `graphify` only through PATHEXT (`.COM;.EXE;.BAT;.CMD;…`), so cage's interceptor
**can never be found** on Windows. The shim capture route is structurally absent there.

**The artifact: `graphify.cmd`.** No `.exe`, nothing compiled — plain text bundled data,
same install path as the bash shim.

**Why not PowerShell:** **`.ps1` is not in default PATHEXT**, so `graphify.ps1` would
never be found by bare-name invocation — the exact failure being fixed. It also drags in
execution-policy variance on locked-down endpoints. `.cmd` is the only artifact that
both (a) resolves by bare name and (b) ships as text.
([PATHEXT reference](https://www.renenyffenegger.ch/notes/Windows/development/environment-variables/PATHEXT))

---

## Phase 1 — write the behaviour contract (do this first, it is reusable)

Extract what `data/shims/graphify` *does* into a written contract both twins are tested
against. **This document is also the [tool-integration-contract](../proposals/tool-integration-contract.md)'s
first artifact** — the Windows fix is not a detour from the paved road, it lays the first
paver.

The observed contract, from the bash source:

| # | behaviour | detail |
|---|---|---|
| 1 | **re-entry guard** | `CAGE_GRAPHIFY_SHIM=1` ⇒ skip metering, go straight to the real binary |
| 2 | **PATH scan skipping ALL interceptors** | not just own dir — two stacked shims used to resolve to each other and recurse forever |
| 3 | **interceptor self-identification** | contains `cage data graphify` / `graphify metering interceptor`; `pathshim._INTERCEPTOR` greps for exactly this |
| 4 | **no real binary ⇒ exit 127**, never fall back to the bare name (that re-enters a shim) |
| 5 | **meter only if cage is present** and `cage data graphify --help` succeeds; else exec the real binary unchanged |
| 6 | **transparent passthrough** — stdout, stderr and exit code identical to running graphify directly |

## Phase 2 — `graphify.cmd`

Implement 1–6 in batch. **The traps, all real:**

- **cmd has no `exec`.** The bash shim replaces its process; `.cmd` cannot. Use
  `call "%REAL%" %* & exit /b %ERRORLEVEL%`. This is a **genuine behavioural
  difference** — a nested process, and Ctrl-C prompts `Terminate batch job (Y/N)?`.
  **Record it in the contract as a known divergence**; do not pretend parity.
- **npm's graphify on Windows is itself `graphify.cmd`** — the twin has the same
  filename as its target. The PATH scan must skip cage's own copy by *content*
  (`findstr` for the self-identifying strings, mirroring rule 3), never by filename.
- **`pathshim._INTERCEPTOR` must match the twin.** Keep the identical marker strings, or
  liveness detection silently fails and stacked shims recurse.
- Quoting: paths with spaces (`C:\Program Files\…`) must survive `%*` passthrough.
- Both shims may coexist (Git Bash / WSL alongside native cmd) — each must skip the other.

## Phase 3 — wire it

`adoptcmd._install_shim` copies the bundled shim to `<root>/bin/graphify` and chmods it.
On Windows: install `graphify.cmd` instead (chmod is a no-op there). Also
`agents.install` refresh path · `refresh_shim`'s byte-compare heal · `--python-launcher`
mode · `paths.cage_command_tail` recognition.

## Phase 4 — liveness (before the flip, not after)

`pathshim.executables`/`classify` and `wiringscan` must learn PATHEXT resolution and
report `live`/`dead`/`shadowed`/`foreign` for the twin; `doctor` names it. **A twin
without liveness detection recreates F1's nine-day silent unmetering on a new OS** —
that is why this precedes Phase 5.

## Phase 5 — flip the CI assertion

CI-GF's Windows `present` leg asserts today's truth (bare `graphify` does *not* reach
cage). Shipping this **flips** it to assert interception works. Then the README
Platforms line loses its "planned" clause.

## Does CI-GF test this? **Yes — it is the harness.**

`python-package.yml` already runs `windows-latest`. CI-GF's `present` leg installs real
graphify (npm ⇒ `graphify.cmd`), runs `cage setup`, puts `bin/` first on PATH and invokes
**bare `graphify`** — which is precisely the WIN-GF acceptance test, on the only Windows
the dev machine has. **Build CI-GF first**: it proves the gap exists before the fix, then
proves the fix after, and the Phase 3–4 wiring changes land under a green harness.
