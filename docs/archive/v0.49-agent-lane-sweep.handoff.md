## P1 · CIGF-HERMETIC — the lab that adopts the developer's real `~/.cage`

**Confirmed, mechanism exactly as filed.** `tools/cigraphify.py:273` builds the sandbox
as a sibling of the repo (`REPO_ROOT.parent`), so on a dev box it sits under `$HOME`.

**The irony worth understanding before fixing it:** the hermeticity mechanism *is* the
bug. `_env` (`:95-105`) sets `HOME`/`USERPROFILE`/`CAGE_HOME` to `sandbox/home`, so both
members of `paths.py:163`'s `excluded` set collapse to `sandbox/home/.cage` — the real
`~/.cage` stops being excluded and the upward walk adopts it.

**⚠️ Correction 1 — the resolver named in the tracker is the wrong one.** The path that
bites is `cliutil.root()` (`cage/cliutil.py:10-14` → `paths.find_project_root()`), reached
from `clicmds.py:538`/`:627-637`. `resolve_root` shares the walk but is the *read* path.

**⚠️ Correction 2 — BOTH fixes the tracker proposes are wrong. Do not implement either.**

| candidate | verdict |
|---|---|
| pin the root in `_env` (e.g. `CAGE_BASE`) | **impossible** — `cliutil.root()` has no `CAGE_BASE` branch; only `resolve_root` does. Fixes `report`'s ledger, leaves `setup`, `doctor-dead` and every home write intact |
| build under `tempfile.gettempdir()` | **holed on Windows** — `gettempdir()` is `C:\Users\<u>\AppData\Local\Temp`, under `USERPROFILE`, so an ancestor `.cage` is adopted again. Wrong fix to stop at, for a runner whose reason to exist is Windows parity |

**The fix that works** — one line beside `project.mkdir(parents=True)` at `:275`:

```python
(project / ".cage").mkdir(parents=True)
```

`find_project_root` returns on the **first** hit (`paths.py:164-167`), so `cur == project`
short-circuits before the walk leaves the sandbox — wherever the sandbox lives, including
under `--path ~`. Combine with a `gettempdir()` default for defence in depth.

**The cost, state it in the commit:** it gives up the "`.cage` scaffolded from nothing"
property. No check ever asserted it (`:140` asserts only the two `bin/` twins), and
`initcmd.run` is explicitly idempotent over an existing dir.

**⚠️ Correction 3 — the home writes are broader than the tracker records.** All additive,
none destructive, ledger untouched — but two are unrecorded:

- `~/CLAUDE.md` **is written** (`initcmd.py:186`, `238-248`; `pointer=True` by default).
- `~/bin/graphify` + `~/bin/graphify.cmd` **are installed** (`adoptcmd.py:52-61`).
- `~/.cage/cage.toml`'s `# cage:sources-start…end` region is rewritten in place
  (`initcmd.py:194-208`); `cage.toml`/`prices.toml` themselves only written if absent.
- Correctly contained: the shell-rc append lands in `sandbox/home/.bashrc`
  (`adoptcmd.py:94`) — though the PATH line it writes points at the *real* `~/bin`.

**Which checks fail today (the 3-of-7 claim is exact):** `setup` (`:140` — the twins never
exist), `intercept` (`:152` — real graphify runs unmetered), `doctor-dead` (`:217` —
`FileNotFoundError`). `passthrough` and `doctor-live` pass *vacuously*, which is its own
small finding worth a comment.

**Tests:** `tests/test_cigraphify.py` covers only the corpus-sizing assertions. A
regression test can't be written against `main()` as-is — extract the sandbox placement
into a helper (`_sandbox_parent()`) or assert on the seeded `project/.cage`.

**Risk:** low. Build-time only, never imported at runtime, not in the wheel.

## P4 · REV-HARDEN P4 — the judgment half

Do **not** batch these with P3. Each changes numbers that are already on disk.

### 4.1 (item 5, second half) rename syntax
`git show --numstat` prints `old => new` (and the `dir/{a => b}` brace form) as the
numstat name, which can never key-match a `+++ b/` path. Changes which paths `added` and
`numstat` agree on ⇒ can shift persisted provenance counts. Its own change.

### 4.2 (item 6) Edit context lines counted as `suggested`
`transcript.py:238-247` takes the whole `new_string`; `old_string` is **never read**
anywhere in the module. Unchanged context lines therefore enter `suggested` and land in
`kept_modified` via `modified = suggested - kept` (`linematch.py:198`).

**⚠️ The harm is narrower than the proposal claims.** Inflation of
`suggested`/`kept_modified` is certain. False *agent credit* requires a context line to
coincidentally match a genuinely-human-added line, and `MIN_MATCH_CHARS` plus the 1:1
multiset consumption blunt the common cases — possible, not routine. Say so; do not
oversell the fix.

- Fix: subtract a multiset intersection with `old_string` lines — computed **after** the
  same `_norm`/gate the matcher uses, or the subtraction will not line up.
- **The real design call:** `linematch._norm` is documented as the single normalizer and
  `transcript.py` sits on the other side of that boundary. Decide where the subtraction
  happens and write it down.
- Historical rows and new rows will disagree — footnote or version the method. State the
  opposite-error trade (undercounting when an agent legitimately re-adds an `old_string`
  line) in the docstring.

### 4.3 (item 1) full shas + prefix-match — **LAST**
Real at six sites: `commitjoin.py:157` (`%h`), `tasks.py:34` (`rev-parse --short`),
`commitjoin.py:346` (exact set membership), `commitview.py:201,222` (provenance),
`commitview.py:230,268` (attested minutes — this is the *"an attestation always wins"*
break, silently falling through to the `~` estimate), `originrecord.py:96,101,106`.

Both sides are `--short` so they agree **today**; they diverge when git's auto-abbreviation
grows and old rows keep the old length. Silent in all three families.

**⚠️ The proposal's symptom is backwards.** It says `cage insights commit <prefix>`
renders "the newest of several matches". Prefix matching already exists and is
bidirectional (`commitview.py:209`), and `render_commit` takes `rows[0]` where `windows`
is sorted **oldest-first** (`commitjoin.py:167`) — so it renders the **oldest** match. The
missing *ambiguity refusal* is the real defect.

- Fix: `%H` / `rev-parse HEAD` at all three write sites; read through a shared
  `prefix_match(stored, probe)` that returns a distinct `AMBIGUOUS` reason on >1 hit.
- **Back-compat is the whole difficulty:** already-written short-sha rows must still join,
  so the helper must stay prefix-symmetric (as `commitview.py:209` already is).
- Tests: `tests/test_commitjoin.py` (mixed short/full ledger), `tests/test_commitview.py`
  (ambiguous prefix refuses), `tests/test_task_time.py` (attestation still wins across a
  length change).

## P5 · HR-COPILOT-JOIN — every copilot call is `unconfirmable`

**Claims (1) and (2) confirmed.** `transcript.py:604-609` builds copilot/vscode rows with
no `project=`; the only two stamping sites in the package are `transcript.py:94` (claude)
and `:743` (kiro-CLI). The exclusion is `commitjoin.py:356-358`:

```python
stamped = c.get("project", "")
if not stamped:
    _drop(NO_PROJECT, c)
    continue
```

copilot/vscode is *already* whitelisted for window-joining (`commitjoin.py:228-232`), so
`ts_fidelity` passes and the row falls straight through to the `project` gate. The join
really is built and really cannot fire.

**⚠️ Correction — the tracker's framing is wrong in both directions, and this is the
finding that matters most:**

- The store **does** carry a cwd (the fear that it does not is unfounded). Two carriers,
  both evidenced by this repo's own probe of 1,132 real parts across 157 files
  ([research](research/2026-08-07-graphify-store-evidence.md), `:57`, `:64-66`):
  `toolSpecificData.cwd.path` on `run_in_terminal` parts (present 1,114/1,132, **exact but
  partial** — only requests that ran a terminal command) and
  `workspaceStorage/<hash>/workspace.json` → `{"folder": "file:///…"}` (**one read, covers
  every request**). `graphifytx.py:403,424-427` already consumes the former.
- But **"following the claude `cwd` precedent … it window-joins for free" is false.** The
  claude precedent (`transcript.py:91-94`) works because the cwd sits on the very record
  the call row is built from. Here it does not — the per-request serialized fields
  ([research](research/copilot-vscode-token-sources.md), `:44-50`) contain no cwd at all.
  The closer precedent is **kiro CLI** (`transcript.py:743`): a *store-level* cwd, which is
  structurally what this needs.

**Recommended shape:** resolve **one** project per file before the row loop —
`workspace.json` first (full coverage, single read), falling back to the first
`toolSpecificData.cwd.path` in the file, else `""`. **Basename only**, same PII guard as
`scope`/`tasks` (`schema.py:84-88`).

**Decisions the executor must make and record** (this is why it is Opus):
- multi-root workspaces store a `"workspace"` key (a `.code-workspace` path), not
  `"folder"`.
- a `--path` override run relocates the file so `parents[1]` no longer names the
  `workspaceStorage/<hash>` dir (`importcmd.py:340-348`) — must **fail open to `""`**,
  never guess.
- URI percent-decoding for paths with spaces.
