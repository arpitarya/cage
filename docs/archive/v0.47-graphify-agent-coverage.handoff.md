**One-liner:** make the graphify savings ledger file receipts from copilot VS Code
and kiro — unskip `chatSessions`, add a kiro route, backfill cursor-missed sessions —
with automated tests for every route.
**Owner / executor:** Claude Code (**Opus** — probe + law-adjacent changes; see prompt).
**Status:** Ready to build — P0 is a blocking evidence gate, not a formality.

## 1. Context & background

- Diagnosed 2026-08-07 (WORKLOG entry; OPEN-WORK **GF-AGENT-FIELD**): graphify
  receipts file from claude transcripts + copilot **CLI** only. Three causes, all
  verified: `_detect_graphify_copilot` skips every `chatSessions/` file (the "F2"
  no-result assumption); kiro has **no detection path at all** (`import_kiro` takes no
  savings snapshot; its token log carries no commands/results); the import cursor
  **never backfills** — an already-ingested `events.jsonl` is never rescanned (verified
  E2E: a deleted receipt is not refiled).
- Arpit's directive (2026-08-07): copilot in VS Code must not be skipped; the graphify
  ledger must work with copilot **and** kiro. The three-agents product invariant
  (CLAUDE.md) backs this: a capture surface dark on two of three agents is a gap, not
  a feature.
- Bears directly on **NET-1**: today any "does graphify pay" reading is structurally
  claude + copilot-CLI only.

## 5. Technical approach (decided)

- **One counterfactual, never forked:** every new route detects (command, answer,
  cwd) and hands off to `_file_query` / `_file_report_read`. No new formula, no new
  method tag, confidence constants unchanged.
- **P0 probes decide feasibility per route** (the REV-TS Phase-0 gate is the model —
  INTERVIEW praises it; verify independently, don't trust this doc's assumptions):
  (a) chatSessions: run one real terminal graphify query in VS Code copilot, then pin
  whether the stored request's response parts persist the command AND result text
  (`toolInvocationSerialized`/terminal tool data — name the exact keys), plus
  truncation markers; (b) confirm cwd resolution via the sibling
  `workspaceStorage/<hash>/workspace.json`; (c) kiro CLI: run one real graphify query
  through kiro-cli, dump that conversation's `value` JSON, pin where tool commands
  and results live in `history[]`; (d) survey kiro IDE globalStorage for any
  command-bearing store. Output: `docs/research/<date>-graphify-store-evidence.md`
  + redacted fixtures under `tests/fixtures/transcripts/`. **A route whose evidence
  is absent is not built — it gets the P3 loud-gap treatment instead.**
- **VS Code (P1):** new `detect_and_file_copilot_vscode` in `graphifytx.py`; session
  = sessionId, cwd from `workspace.json`; report-read fires on view/Read tool parts
  citing the report/wiki (needs no result text); query fires only on a complete
  stored result — any truncation/elision marker ⇒ skip, debug-logged. Remove the
  chatSessions `continue` in `_detect_graphify_copilot` and dispatch by store.
- **kiro CLI (P2):** detection reads `history[]` **transiently** — commands + result
  text are hashed/counted, never persisted (identical discipline to the claude
  transcript route). This amends the "parser touches only whitelisted keys" law:
  **ADR required** (carve-out #2 after the chats-title amendment), and the whitelist
  comment in `transcript.py` updated to name the carve-out and its boundary.
  Detection keys off the same store read the credits sweep already does; receipts
  land in the sweep's own sink (project tree via `kiro_cli_workspace` scoping, or
  the machine ledger on an unscoped sweep) — never a second resolver.
- **Backfill (P3):** `cage import --rescan-graphify` — walks each agent's **full
  match set** (ignores the cursor), runs graphify detection ONLY (no call/credit
  re-ingest), idempotent by receipt id + deferral. One flag, documented in CLI.md.
- **Deferral extended per route:** each new route computes the shim's
  empty-session id and defers exactly as the claude/copilot-CLI routes do.
- **Gap surfacing (P3):** doctor gains a graphify-coverage line per agent/surface
  (fed by the same evidence constants, not re-derived); a `cage query`
  explainer entry states which surfaces file and why the rest can't.

## 6. Non-negotiables / constraints

- **$0 / stdlib only** — `dependencies = []`; no new imports beyond stdlib.
- **Fail-open write path** — detection errors are debug-logged and swallowed; the
  import never breaks over graphify. Every new swallow site is `CAGE_DEBUG`-visible
  (`tests/test_debug_coverage.py` will enforce).
- **Determinism** — no clocks/random; ids via `receipt_id` only; same store + same
  policy ⇒ same receipts.
- **Method law** — everything filed here is `modeled`, never `measured`; a parse
  miss or truncation is *unmeasurable* ⇒ **nothing filed**, never a fabricated or
  partial saving.
- **Counts-never-content** — only hashes/counts/paths-validated fields persist; the
  kiro carve-out ships with its ADR in the same change or not at all.
- **Three agents stay first-class** — no route may regress claude or copilot-CLI
  behavior; existing receipts/ids must be byte-stable (no id-scheme change).
- **Do not touch:** the shim twins + `pathshim._INTERCEPTOR` marker set,
  `shim-contract.md`, `receiptprice`/pricing, `mergeutil`, the floor test's
  assertions (add artifacts only if a wiring artifact is added — none should be).
- **CLI change = doc change:** the new flag lands in `docs/CLI.md` in the same
  change (`tests/test_cli_reference.py` gates it).

## 8. Edge cases & risks

- Stored result truncated/elided → skip, debug-log (`skip_reason`), test pinned.
- chatSessions rewrites the requests array mid-session → detection must be
  idempotent across rewrites (deterministic ids + `existing_ids`; cursor re-scan is
  expected, not a bug).
- Resumed kiro conversation (history grows) → same run must not refile (id from
  content signature, not turn count).
- Cited `src=` files missing on disk / cwd unresolvable → unmeasurable, nothing
  filed (existing `_raw_alternative` behavior — keep it).
- Same query seen by shim AND a store → exactly one receipt (deferral test per route).
- VS Code stand-in fixture shapes that P0 could not confirm on a real store are
  labeled `UNVERIFIED-FORMAT` (existing corpus convention), never silently trusted.
- Risk: P0 finds nothing usable for VS Code queries → ship report-read + doctor gap
  (OPEN QUESTION 1); for kiro IDE → documented gap (expected).

## 9. Testing & validation (automated — the point of this pair)

- **Unit, per route** (`tests/test_graphify_vscode.py`, `tests/test_graphify_kiro.py`,
  extend `test_graphify_copilot.py`): detection from fixtures → expected receipt
  fields (op, saved, method=modeled, confidence, session); false-positive guards
  (`grep graphify`, `echo graphify` never fire — reuse the GC2 cases).
- **E2E import**: tmp HOME + real-shape stores → `cage import --agent copilot|kiro`
  files expected rows; re-import files zero (idempotency); `--rescan-graphify`
  backfills a cursor-consumed session and is itself idempotent.
- **Cross-route dedupe**: pre-seed the shim's empty-session receipt → store route
  defers (counts show `deferred`, ledger unchanged) — one test per new route.
- **Truncation guard**: fixture with truncation marker → zero receipts + debug event.
- **PII**: grep every command/answer string from fixtures against all ledger bytes.
- **Determinism**: run detection twice on the same fixture → identical ids/rows.
- **Regression**: full `just test` green; goldens re-blessed only if a rendered
  shape legitimately changed (`CAGE_BLESS_GOLDENS=1` on `test_output_spec.py`).
- Manual (one-time, post-build): on Arpit's machine, one real graphify run through
  VS Code copilot and kiro-cli each, then `cage import` → receipt visible in
  `cage insights attrib` / `roi`. Record the result in `docs/regression/`.
