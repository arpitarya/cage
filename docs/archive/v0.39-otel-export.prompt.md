## The finding that shapes this

**OTel's GenAI conventions are pre-stable.** As of semconv v1.42.0 (June 2026) they live
in a dedicated repo, have no 1.0, are labelled *Development*, and **attribute names can
still change between versions**. Cage's determinism law says the same ledger must always
produce the same output — so:

- **Pin the targeted semconv version in `constants.py` and stamp it in the emitted
  document.** Cage never silently follows upstream.
- A spec bump is a **deliberate, changelog'd change**, exactly like `prices_version`.
- **The help text and docs say "pre-stable"** — a user piping this to a vendor deserves
  to know the shape can move.

## Task

Add `--otel` to `cage data export`, beside `--csv` / `--study`.

- **Calls →** `gen_ai.system` · `gen_ai.request.model` · `gen_ai.usage.input_tokens` /
  `output_tokens` · duration where `latency_ms` exists.
- **Omit, never zero.** No honest value ⇒ leave the attribute out. A fabricated `0`
  reads as measured.
- **Receipts/savings have no GenAI equivalent.** Either omit them, or carry them under
  cage-namespaced keys (`cage.saved_tokens_gross`, …). **Decide, state it, and never
  invent a `gen_ai.*` name upstream doesn't define.**
- **Method tags survive** — a `modeled` number must not reach a vendor looking measured.
- Deterministic: stable key order, LF pinned, no clock, no randomness.
- **One-way REPORTING**, like CSV. Never an import source; `--study` stays jsonl.

## Hard constraints

- **stdlib only.** No `opentelemetry-*`, no HTTP, no SDK. `dependencies = []` is the
  product; adding a dep to emit a file would end the `$0` guarantee.
- Not an OTLP client — cage writes a file, the user's collector ingests it.
- Determinism: same ledger + policy ⇒ byte-identical output.
- No commits in `cage`; don't touch `docs/regression/**`.
