# Proposal — four layers, each optional, each strictly additive

**Designed from nothing.** Nothing built before is assumed, and anything surviving from
an older version is **removed, not extended**. The floor is hookless; every layer above
it is opt-in and adds capability without being required by anything below.

**Why the old proposal is void:** `cage-skills.md` opened with *"cage already ships one
skill (`/cage`)"*. It does not — the hookless rebuild deleted the skill/steering
machinery, and no code writes a skill file anywhere. Its whole premise was pre-rebuild.

## The ladder

| | layer | optional | what it is | if absent |
|---|---|---|---|---|
| **L0** | **Hookless** | **no — the floor** | pull capture (transcript import, capture-on-read) · PATH interceptor · every CLI view | nothing works; this *is* cage |
| **L1** | **Hooks + steering** | yes | agent lifecycle events; passive text the agent reads | L0 works, just staler and blinder |
| **L2** | **MCP** | yes | the agent *pulls* cage mid-session | the agent can't see its own cost |
| **L3** | **Skills** | yes | procedural knowledge — when and why, not just what | tools without judgement |

**Binding rule: L0 must work perfectly, alone, forever.** Every layer above degrades to
"absent" without breaking capture, determinism, or any number. No layer may become a
dependency of a lower one.

## What each layer uniquely unlocks

| capability | L0 | +L1 | +L2 | +L3 |
|---|---|---|---|---|
| Token capture | ✅ at import/read | ✅ **real-time** | — | — |
| Savings receipts | ✅ shim + transcript | ✅ **agent identity at capture** | — | — |
| Task open/close | ⚠️ manual | ✅ **auto on session boundary** | ✅ agent closes its own | ✅ closes *with a label* |
| Provenance | ⚠️ transcript only | ✅ post-commit | — | — |
| Budget | ⚠️ advisory | ✅ **blocks before a paid call** | ✅ agent self-checks | ✅ re-plans under budget |
| Tool awareness | ❌ | ✅ steering text | — | ✅ **knows when it's worth it** |
| Agent reads its numbers | ❌ | ❌ | ✅ read tools | ✅ interprets them |
| Method-tag honesty relayed | ❌ | ❌ | ⚠️ raw JSON | ✅ **refusals relayed, never smoothed** |
| Proactive behaviour | ❌ | ⚠️ passive nudge | ❌ | ✅ "check the graph first" |
| Multi-step workflows | ❌ | ❌ | ❌ | ✅ triage · release · lab-run |

## Committed and multi-user — a constraint on every layer (Arpit, 2026-08-02)

**Every layer's wiring is committed to git and must work for every teammate, on every
machine.** This is not a preference; it is the acceptance test for all four phases.

### The distinction that must stay explicit

| | committed, shared | machine-local, gitignored |
|---|---|---|
| **what** | hook files · MCP config · steering · skills · `.cage/bin/cage-run` · `cage.toml` · `prices.toml` — **all wiring** | **the ledger records** (`ledger/`) · `out/` · `state/` |
| **why** | a teammate clones and it works | the ledger is *their* usage; `state/` holds machine-local buffers |

**So "multi-user" means two different things and they must never be conflated:**
**every piece of wiring is committed; only the *records* are not.** Team-level numbers are a *separate* mechanism —
`refs/notes/cage-ledger` ([ADR 0001](../adr/0001-ledger-team-aggregation-notes-not-external-sink.md)),
CI-written — not a committed ledger. Nothing in this program may commit **ledger records** — wiring, always.

### ✅ RESOLVED 2026-08-02 — Kiro's MCP config can be committed after all

**Arpit asked: can the path be repo-relative rather than from `~`?** **Relative: no** —
Kiro resolves a relative `command` against its **install directory**, not the workspace
(kirodotdev/Kiro #6525), so `.cage/bin/cage-run` would be looked up in the wrong place.
`${workspaceFolder}` fails too (#5659, no substitution).

**But path-free works, and cage already ships it.** `kirowire.install` has a second form,
today gated behind `--python-launcher`:

```json
{"command": "python3", "args": ["-m", "cage", "mcp"]}   // no path of any kind
{"command": "py", "args": ["-3", "-m", "cage", "mcp"]}  // Windows
```

`python3` resolves through **PATH**, like any interpreter — no absolute path, no relative
path, no variable substitution. **It is committable and machine-portable as-is.**

**Proposal: make the path-free form the committed default for Kiro's MCP**, not a
launcher-mode special case. The absolute `cage_bin()` form stays available for the
environment where it is genuinely needed.

**The honest trade, which must be stated not buried:**

| form | portable? | exact? | fails when |
|---|---|---|---|
| `python3 -m cage mcp` | ✅ committable | ⚠️ depends on which `python3` | cage lives in a venv the resolved `python3` isn't in |
| absolute `cage_bin()` | ❌ machine-specific | ✅ exact install | any other machine |

**So the committed form needs a doctor check:** does the `python3` that Kiro will resolve
actually import cage? If not, say so with the fix — that converts a silent no-MCP into a
named, fixable condition, which is the whole point.

**Same question applies to the other two** — `.mcp.json` and `.vscode/mcp.json` are
already portable via the shim, so they need no change; but the venv caveat is worth
checking there too if they ever move to an interpreter form.

### Multi-user hygiene the build owes

- **Writes must be idempotent and byte-identical**, or two teammates running `cage setup`
  produce a churning diff on every commit. Cage already byte-compares before writing;
  under this requirement that stops being an optimisation and becomes a **rule**.
- **Foreign entries are never touched** — a committed hook/MCP file is shared with
  whatever else the team put there.
- **A teammate without cage installed gets silence, not breakage** — the committed shim
  already exits 0 when cage is absent; every layer must preserve that.

## Three agents, every layer — the parity table

**Product invariant: Claude Code · Copilot · Kiro are all first-class at every tier.**
A layer ships only when all three have it, or when the gap is *named as a limit*.

| | **Claude Code** | **Copilot** | **Kiro** |
|---|---|---|---|
| **L0** capture | transcript (CLI + VS Code share one store) | transcript, CLI + VS Code **separate** stores | IDE token log → **machine ledger** (ADR 0006); CLI store keyed by cwd |
| **L0** shim | twin pair, PATH | twin pair, PATH | twin pair, PATH |
| **L1** hook file | `.claude/settings.json`, `hooks[]` container, **committed** | **`.github/hooks/*.json` — repo-level, COMMITTED, portable** (user-level `~/.copilot/hooks` also supported; both load and **combine**) | `.kiro/hooks/*.kiro.hook`, **one hook per file**, committed |
| **L1** session-start | ✅ | ✅ | ❌ **none** — `agentStop` self-backfills each turn |
| **L1** steering | skill/context file | prompt + pointer | steering doc |
| **L2** MCP config | `.mcp.json` (committed, portable) | `.vscode/mcp.json` (committed, portable) | `.kiro/settings/mcp.json` — **committed via the path-free `python3 -m cage mcp` form** |
| **L3** delivery | Claude skill | Copilot prompt | Kiro steering |
| **committed?** | ✅ all | ✅ all (use repo-level hooks) | ✅ all — MCP via the path-free form |

### ⚠️ Correction 2026-08-02 — Copilot hooks CAN be committed

An earlier draft of this table said Copilot's hooks are *"user-level, per-machine, never
committed"*. **That was wrong**, and cage's own code disproves it: `copilotwire.
_strip_legacy_hooks` cleans **two** locations, one of which is repo-level
`.github/hooks/cage.json` — which cage itself wrote in v0.10.0, with foreign-hook
preservation, the signature of a shared committed file.

GitHub documents both: **repo-level `.github/hooks/*.json`** applies whenever Copilot
agents run in that repository, **user-level `~/.copilot/hooks/*.json`** applies to your
CLI everywhere, and hooks are **loaded from multiple sources and combined** — policy,
user, project, plugins — with *all* matching entries running.

**So Copilot is the best-placed of the three for L1, not the worst:** repo-level hooks
are committed and portable, so they can reference `.cage/bin/cage-run` and give a
teammate working capture on clone — the same property Claude has.

Two consequences the build must handle:

- **Combining is a double-capture risk.** Wire *both* locations and both fire on the
  same event. Pick one, or dedupe by id and prove it — P2 already owes that proof.
- **Repo hooks must be on the default branch** to apply for the coding agent. A
  feature-branch wiring will not fire until merged; say so, or someone debugs a silent
  gap.

### The limit that shrinks L1's promise — state it, don't discover it

**Hooks are CLI-only. They do not fire under a VS Code extension.** So L1's headline
wins — agent identity at capture, auto task-close — apply to **CLI sessions only**; a
VS Code session silently falls back to L0 behaviour.

That is not a defect to fix, it is the platform. But it means **L1 must never be
described as "cage now knows which agent ran"** — it is *"cage knows, for CLI
sessions"*. Any view built on it inherits the caveat, exactly as `surface` does for
Claude today.

**Kiro's missing session-start** likewise means auto task-close cannot key off an open
event there; the single `agentStop` hook must close what it can infer, or decline.

## Three findings that shaped this

1. **L1 mostly fixes problems that already exist.** Automatic task-close feeds *every*
   starved surface — `compare`, `estimate`, `calibration` and NET-1 are all blocked on
   nobody running `cage task outcome`. And a hook **knows which agent fired it**, which
   is exactly the attribution [ADOPT-COV](../OPEN-WORK.md) cannot get from a shim
   subprocess. These are not new features; they are shipped features that don't work.
2. **L2 exists and is under-used.** Six read tools ship — but **`verdict` and `compare`,
   the two that answer "is this tool worth it", are not among them.** The product
   question is invisible to agents.
3. **Only L3 can carry the honesty discipline.** MCP hands an agent a JSON number;
   nothing makes it say *"that's `modeled`, not measured"*. A skill can be instructed to
   relay method tags verbatim and never smooth a refusal. Without L3 the discipline stops
   at the CLI boundary.

## Sequencing

**L0 → L2 → L1 → L3.** Finish L0 (nearly there), then close the L2 gap (cheap, and it is
the product question). L1 before L3 because hooks unblock the evidence pipeline that
makes L3's advice worth taking. L3 last — a skill interpreting numbers you cannot yet
trust is premature.

## Deliberately not proposed

Making any layer mandatory · reviving the deleted skill machinery as-is (rebuild from
this design, or not at all) · a fourth agent · anything that puts a network or a
dependency in L0.
