**Model:** **Opus** — this is the document that will be cited as "what cage
proves". Overstating one cell (calling UNPROVEN "good", or blurring a permanent
limit with a pending one) is the failure mode, and it is a judgment call per row,
not a transcription.

**Where to run:** Claude Code with `cage/` and `../cage-lab/`. Commit in
`cage-lab/` only. **The `cage/` tree stays uncommitted.** **No paid calls** — the
benchmark is *derived* from existing runs; it observes nothing new.

## What this artifact is — and is not

`report-per-run` established two artifact types. This is the third:

| artifact | answers | spans |
|---|---|---|
| run report | what happened in this run | one run |
| finding doc | this defect's status now | one defect, many runs |
| **phase benchmark** | **what does cage capture, and how correct is it?** | **one phase, all runs** |

**It is derived, never observed.** Every cell cites a run report or finding doc.
It introduces **no new numbers**. If you find yourself computing something,
stop — that means a run report is missing the data, which is itself the finding.

## Produce: `findings/PHASE-1-BENCHMARK.md`

**1 — Headline verdict, three lines.** Per agent: exact / honest-limit /
unproven. No hedging, no prose paragraph before it.

**2 — The matrix: agent × surface × field.** For each of claude/copilot/kiro ×
CLI/VS Code, for each field (tokens_in, tokens_out, cached_in, cache_write_in,
model, gap_ms, session id, session name, surface, premium, credits):

- **captured?** with the method tag (`measured` / `estimated` / absent)
- **accuracy verdict** — exactly one of:
  - **EXACT** — reconciled three ways (log = cage = independent recount); cite
    run id + figures
  - **HONEST-LIMIT** — the source carries no such number; cage records what
    exists, tagged, and says so
  - **UNPROVEN** — not yet tested
  - **WRONG** — a known open defect; link the finding doc
- **evidence** — run id + figures, or finding doc link

**3 — Permanence column, and do not blur it.** A limit is either:

- **FINAL** — vendor design, closed by evidence (Kiro tokens: null in store,
  proxy route closed by the P2 probe), or
- **PENDING** — merely untested (every VS Code cell until P3).

Conflating these is the single most damaging error available in this document.
"Kiro has no tokens" and "we haven't tested VS Code" are not the same class of
statement.

**4 — Coverage, stated plainly.** Phase 1 ran **6 of 12 cells — scripted CLI
only**. Say so up front. List which cells did not run and which questions P3
will answer (graphify under extensions · claude CLI-vs-VS-Code store
distinguishability).

**5 — The accuracy summary that answers Arpit's actual question:**

**6 — Open defects**, one line each with status and link (note the shim-recursion

**7 — Publish** hashed into `cage/docs/regression/` (dated,

## Guardrails

- **STOP and ask if:** a cell's accuracy can't be established from existing
  evidence (say which, and what run would settle it) · a run report lacks a
  figure the benchmark needs · you're tempted to mark an untested cell as
  passing.
- **Never upgrade a verdict for tidiness.** UNPROVEN cells staying UNPROVEN is
  what makes the EXACT cells worth believing.
