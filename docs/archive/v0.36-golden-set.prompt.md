## Step 1 — setup

- Scaffold `../cage-lab/golden/` per plan §1 (`git init` if needed). Stdlib-only;
  **never `import cage`**; drive the installed `cage` binary and the agent CLIs
  as subprocesses.
- Implement the plan §2 protocol in `drive.py`: pre-snapshot (listing +
  size/mtime/sha) → run in the frozen `golden/workspace/` → ask each question
  honoring `pause_before` → **settle-and-retry**, then post-snapshot → diff →
  **copy new/changed logs verbatim** → import into `captures/<run-id>/ledger/` →
  write `manifest.json` + `transcript-map.json` (question id → session id → the
  log records it produced). `--list` works with zero agent calls.
- Commit a small frozen `golden/workspace/` repo (include one deliberately large
  module so Q2 creates cache).
- `questions/core.toml`: at minimum **Q1** (floor), **Q2 → Q3** (cache create,
  then read) and one **§4 architecture question** for the graphify-ON cells.
- **Wire graphify and verify it is LIVE** — `cage setup`, then `cage doctor`
  must report the interceptor healthy. Presence is not liveness: a dead shim
  silently exec's the real binary (that was F1's root cause).
- **Record the config baseline** — `cage.toml` is the config file as of v0.36
  (`policy.toml` still read as a fallback). Never hard-code `policy.toml`. Every
  manifest records which config file was active and flags a coexisting legacy
  one; a capture whose numbers depend on an unnoticed legacy config is a trap.

## Step 2 — scripted cells

| cell | agent | surface | graphify |
|---|---|---|---|
| V1 / V2 | claude | CLI | off / on |
| V3 / V4 | copilot | CLI | off / on |
| V5 / V5b | kiro | CLI | off / on |

**Confirm each CLI's non-interactive invocation from its own `--help` at run
time** — don't trust any table (flags move). Documented starting points:
`claude -p "<q>"`, `kiro-cli chat --no-interactive "<q>"`, and Copilot CLI's own
non-interactive form. A CLI genuinely absent ⇒ `NOT AVAILABLE — <agent> CLI not
installed`; never simulate.

**V5 is discovery, and it's the most valuable cell** (plan §2.6). Kiro CLI is
real, but cage only knows the IDE token log. In order:

1. `kiro-cli --version` / `whoami`.
2. Snapshot before/after across `~/.kiro/**`, the IDE globalStorage path, **and**
   `$TMPDIR/kiro-log/`. Find every file the run touches.
3. Record the written shape verbatim: token counts? session id? model?
   timestamps?
4. `cage import --agent kiro` — does cage see any of it?
5. **Try the config fix immediately.** In the run's `cage.toml`:
   ```toml
   [sources.kiro]
   paths   = ["<the path discovered in step 2>"]
   surface = "cli"      # v0.36; without this the row would inherit "ide"
   ```
   Re-import; verify with `cage doctor --paths` (prints
   `surface=<declared|parser>`). **Rows landing with `surface="cli"` and correct
   tokens ⇒ the whole gap was configuration** — put the working stanza in the
   report as *the fix*.
6. **If rows don't parse**, that's the fourth-parser finding: capture the shape,
   file it, and **do not write a parser in this task.**

## Step 3 — the eight checks, per cell

1. Snapshot diff is exact (no misses, no unrelated churn).
2. Copy faithful: copy sha == source sha, and source sha unchanged from before.
3. `transcript-map.json` points each question at the records it produced.
4. Import complete: row count matches a **hand count** from the log.
5. **Values reconcile three ways** — log · cage's ledger row · your own
   independent recount. Any drift stops everything.
6. Derived signals where expected: `cache_write_in` (Q2), `cached_in` (Q3),
   `session_uid` + session name or an honest `""`, and on graphify-ON cells a
   real row in `savings/graphify/`.
7. Nothing outside `captures/<run-id>/` written; real `~/.cage` untouched.
8. Config provenance recorded (active config file + any legacy leftover).

## Guardrails

- STOP and ask if: a check fails in a way you can't attribute (protocol bug vs
  cage bug); a CLI needs interactive auth; a log appears only after a long delay
  (report the buffering — it changes the protocol before Phase 2); or anything
  would require editing a captured file or committing in `cage/`.
- A capture defect in **cage** is a finding — write it up; never patch cage
  source in this task, and never write a Kiro parser here.
