## Task 2 — B-fix-1: doctor must check the PATH-WINNING graphify

**Why:** the shim that actually runs is whichever `graphify` PATH resolves first — it
can live in **another project's** `bin/`, outside every scanned root. That is exactly
how a dead shim ran unmetered and silent while `cage doctor` reported OK.

- Resolve **the way the shell does**: walk `PATH`, **first executable wins**.
- If the winner is a **cage interceptor**, apply the existing liveness test — is its
  embedded verb still live per `cli.build_parser()`?
- Report four states, distinctly:

  | state | meaning | severity |
  |---|---|---|
  | `live` | cage interceptor, verb live | ok |
  | `dead` | cage interceptor, **dead verb** — capture is silently off | **doctor FAILURE** + runnable fix line naming the exact file |
  | `shadowed` | this root has a shim but a **different** one wins | advisory; name **both** paths |
  | `foreign` | not cage-written | reported, **never touched** |

- **Read-only and side-effect-free**: never execute the resolved binary, never trigger
  an import. Same constraint `wiringscan` already carries.
- **The live parser is the detector, never `REMOVED`** — a verb deleted outright
  (`cage adopt`) is absent from `REMOVED`, so a grep would miss the very artifact this
  fix exists for.
- Keep the two severity tiers distinct: a dead **wired command** fails; a stale
  **asset** (prose naming an old verb) stays advisory and never gates a footer.

## Task 4 — B-fix-3: warn when a graphify hook bypasses the interceptor

**The mirror image of Task 2.** There the wrong shim wins; here **no shim is consulted**.
graphify ≥0.9.30 writes its claude PreToolUse hook with an **absolute** exe path, so it
never traverses PATH — cage's interceptor can't see it, and a hook isn't a Bash tool
call so the transcript route can't either. Evidence: [OPEN-WORK.md](OPEN-WORK.md) §J.

- **Detect:** hook artifacts whose command references `graphify` by a path that is not
  the cage interceptor — `.claude/settings.json` PreToolUse blocks and `*.kiro.hook`
  files. Include **foreign** (non-cage-written) hooks, which `wiringscan` currently skips.
- **Severity: ADVISORY, never a failure.** Do not blur this with Task 2:
  a dead cage shim means **cage's wiring is broken** (failure); an absolute-path graphify
  hook means **graphify is working as designed and cage just can't observe it**
  (advisory). Crying failure on a correctly-functioning third-party integration is how a
  check gets ignored.
- **Message must be accurate, not alarming:** *"graphify's hook invokes `<path>`
  directly — cage's PATH interceptor is bypassed, so any saving on that path is
  invisible. Savings from an explicit `graphify query` are unaffected."*
- **Escalate on `--strict`:** if the command contains `--strict` (or
  `GRAPHIFY_HOOK_STRICT` is set), the read hook *denies* the first raw read per session —
  the avoided read is a saving that may never produce a metered query. Say so:
  *"strict mode — savings on this path are unmeterable by any current route."*
- **Never modify the hook.** graphify owns it. Report, explain, stop.
- Extend `cage query stale-wiring` to cover this case alongside the PATH-winning one.
