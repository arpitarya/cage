# Handoff: set up cage-lab (fresh sibling repo) + run the correctness matrix

**One-liner:** Create `../cage-lab` from scratch per `docs/cage-lab-plan.md` (v3):
the agent × surface correctness matrix with automatic verification AND the
side-by-side eyeball surface, graphify combinations, Arpit's playground — then run
the whole thing and publish the baseline into `docs/regression/`.
**Owner / executor:** Claude Code
**Model:** **Opus** — the independently-derived references are the suite's
entire value (a wrong reference silently blesses wrong behavior), and deriving
them from real logs is judgment work.
**Status:** Ready to build
**Stress-tested:** Challenged: reuse the old cage-lab tree → rejected by Arpit
(fresh setup; if a checkout exists, replace its tree in one commit — history
kept, never rewritten). Challenged: one verifier is enough → no; the matrix
demands three independent readbacks (lab recount · cage's three surfaces
cross-checked · lab-priced USD) because a single reader shares failure modes
with the thing it checks. **Arpit's directive (2026-07-25): ZERO mock data —
the real files, used as they are, uncopied.** Riskiest remaining assumption: the
lab's own parser is correct — mitigated by writing each derivation into
`reference/` BEFORE cage runs, and by showing every addend with its source line
so a human can check the recount itself. Residual: claude
CLI-vs-VSCode is genuinely indistinguishable (shared store) — the matrix
encodes it as an honest blank, not a gap to fake.
**Standing constraint: DO NOT COMMIT in `cage/`.** cage-lab is its own repo —
commit freely THERE (checkpoint per milestone); the cage tree stays uncommitted.
