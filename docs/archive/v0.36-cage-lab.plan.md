# cage-lab — sibling verification lab (plan of record, v3)

**Summary in PLAN.md §11** (long-term home); this file is the detail. v3
supersedes v2's "rebuild in place": cage-lab is **set up fresh** as a sibling
repo (`../cage-lab`), built around Arpit's four requirements (2026-07-25):

1. **Values absolutely correct** — automatic verification AND a manual eyeball
   surface: source file, ledger, and the arithmetic side by side.
2. **The agent × surface matrix** — claude / kiro / copilot solo, each CLI
   surface individually, each VS Code surface individually, then kiro+copilot
   combined.
3. **Graphify** — solo and in combination with agents.
4. **A playground** — a persistent sandbox just for Arpit, never touched by the
   runner.

**Executor: Opus** — hand-derived reference numbers are the suite's value; a
wrong reference silently blesses wrong behavior.

---

## 1. Laws (unchanged from v1/v2 — the constitution)

- **Black-box.** Install the shipped artifact (wheel via `uv build` from
  `../cage`; pyz for the smoke subset) into a fresh venv; drive the `cage`
  binary only. **Never `import cage`** in lab code.
- **Hand-derived reference.** Every asserted number is computed independently —
  checked-in `reference/` files with the derivation shown, or a stdlib script
  reading the *real input files*. Never cage grading itself; never copied from
  cage's `samples/**/derived-rows.json`.
- **ZERO mock data** (§2.1). Scenarios run against Arpit's real files **in
  place** — no copies, no edits, no fake binaries, no synthetic edge cases; real
  graphify or the cell is uncovered. Independence comes from the lab computing
  references with its *own* parser. A missing case is reported
  `NO REAL DATA — cell not covered`, never fabricated.
- **Real-ledger labs are read-only** (`CAGE_REAL_LEDGER`); scenario runs are
  hermetic (scratch `$HOME` + pinned `CAGE_BASE` per run — the real `~/.cage`
  is never touched).
- **Publish into cage.** Run summaries + findings land dated in
  `cage/docs/regression/` with `latest-*` copies and a README index row.
- **A cage defect is a finding**, reported — never patched in-flight; never fix
  a red by bending its reference.

### 2.1 ZERO mock data — the real files, used as they are (Arpit, 2026-07-25)

**Nothing in this lab is fabricated. No mock logs, no authored numbers, no fake
binaries, no synthetic edge cases.** Every scenario runs against real files on
Arpit's machine, unmodified — and the lab does not even copy them: it points
cage at the originals.

**The files (read in place, never written to):**

```
~/my_programs/cage/samples/agent-artifacts/claude/logs/real/session-real{1,2,3}.jsonl
~/my_programs/cage/samples/agent-artifacts/copilot/logs/real-cli/copilot-real{1,2,3}/events.jsonl
~/my_programs/cage/samples/agent-artifacts/copilot/logs/real-vscode/copvsc-real{1,2,3}.jsonl
~/my_programs/cage/samples/agent-artifacts/kiro/logs/real/tokens_generated.jsonl
```

Genuine sessions from this machine (README: "preserving real timestamps/models/
token counts" — only message *content* was stripped). Real values, e.g. copilot
CLI `inputTokens: 11845 / outputTokens: 170`; kiro `promptTokens: 7, 12, 27`.
Live agent logs (`~/.claude/projects/**`, `~/.copilot/session-state/**`, VS Code
`chatSessions/**`, kiro's `tokens_generated.jsonl`) are equally valid inputs and
are also read in place.

Rules:

1. **No `fixtures/` directory. No copies.** Scenarios run
   `cage import --path <absolute path to the real file>`, which reads a
   transcript file or dir in place. Where a scenario must exercise agent
   auto-discovery (no `--path`), the scratch `$HOME` gets **read-only symlinks**
   to the real files — same bytes, same inode, provably not a doctored copy.
   The lab **never opens a source file for writing**; a write-mode open on any
   path under `samples/` or a live agent log is an assertion failure.
2. **References are the lab's own parser reading those same real files** —
   an independent second implementation. Never cage's output, never cage's
   `derived-rows.json`. Independence comes from *who computes*, not from fake
   inputs.
3. **Real graphify, not a stand-in.** G-scenarios run the actual installed
   `graphify` binary against a real repo (cage itself has `graphify-out/`). If
   graphify is not installed, the G-scenarios report
   `NOT COVERED — graphify not installed` and the run says so. **A fake graphify
   binary is not permitted.**
4. **No synthetic edge cases.** The truncated-tail case is *not* manufactured:
   the lab scans the real logs and ledger for a genuinely short/truncated final
   line and uses it if one exists; otherwise the case reports `NOT COVERED — no
   truncated file present`. Same for an untitled Copilot VS Code session: use one
   if the machine has one (~38% do), else report it uncovered.
5. **A gap is reported, never filled.** Any matrix cell without real data prints
   `NO REAL DATA — cell not covered` and is listed in the run summary. An
   uncovered cell is honest; a fabricated one is a lie that goes green.

**Net:** the inputs are Arpit's actual files, untouched and uncopied; the lab
supplies only an independent recount. The L-labs (§8) additionally read the live
`~/.cage`.

**Migration precision (rides G-series):** seed legacy graphify rows in
`receipts.jsonl`, `cage data migrate-savings` dry-run (totals reconcile) →
`--apply`: `receipts.jsonl` byte-identical, original ids in the tree,
attrib/report byte-identical before/after (lab recomputes Σ`saved`
independently), second `--apply` copies 0. A duplicate-counted or shifted
dollar is a **high-severity finding** (NOT WRONG, NOT DUPLICATED).

## 4. Automatic verification (per scenario)

Three independent readbacks, all compared to the `reference/` file:

1. **Raw recount** — `lab/reference.py` recomputes tokens_in / tokens_out /
   cached / cache_write / premium / row count / session count from the real
   log files (stdlib JSON, its own parser — an intentional second implementation).
2. **cage's own surfaces** — `cage report --json`, `cage data export --csv
   calls`, and the import rollup stdout, parsed and cross-checked against each
   other (three cage surfaces must agree with themselves AND the reference).
3. **Money** — expected USD computed by the lab from the installed bundle's
   price table (read as data from the venv's bundled `cage.toml` — renamed from
   `policy.toml` in v0.36; read it as data, never import cage);
   UNPRICED rows asserted as UNPRICED, never $0.

Any mismatch: scenario red, exact metric + delta printed, eyeball report
generated anyway (that's the debugging surface). Determinism rider: every
scenario runs its reads twice — byte-identical or red.

## 5. The eyeball surface (manual verification — Arpit's #1)

`python -m lab eyeball <scenario>` (also auto-written to
`runs/<scenario>/eyeball.md` after every run) prints, per scenario:

```
ORIGINAL  /Users/arpitarya/my_programs/cage/samples/agent-artifacts/copilot/
            logs/real-cli/copilot-real1/events.jsonl     ← YOUR REAL FILE
            read in place · never copied, never modified · sha256 3f9a…c21
            (re-hashed after the run: unchanged ✓)
IMPORTED  cage import --path <ORIGINAL>          (the exact command run)
LEDGER    /Users/arpitarya/my_programs/cage-lab/runs/M4b/home/.cage/ledger/calls-2026-07.jsonl
MANIFEST  /Users/arpitarya/my_programs/cage-lab/runs/M4b/home/.cage/ledger/imports.jsonl
REFERENCE /Users/arpitarya/my_programs/cage-lab/reference/M4b.json  (lab's own recount)

metric        derivation (real values, source line refs)     ref      cage    ✓
tokens_in     11,845(L4) + …                              <real>   <real>    ✓
tokens_out    170(L4) + …                                  <real>   <real>    ✓
cached_in     0(L4) + …                                    <real>   <real>    ✓
premium       session total, stamped once (L2)             <real>   <real>    ✓
cost ($)      tokens × the bundled price row               <real>   <real>    ✓

SOURCE LINES CITED ABOVE (verbatim from your file — nothing to hunt)
  L2  {"type":"session.start", …}
  L4  {… "inputTokens": 11845, "outputTokens": 170, "cacheReadTokens": 0 …}

LEDGER ROWS CAGE WROTE (the same three, trimmed to the asserted fields)
  1 {"id":"c_…","tokens_in":4120,"tokens_out":88,"cached_in":0,"surface":"cli",…}
  …

OPEN SIDE BY SIDE (paste either)
  code -d <ORIGINAL> <LEDGER>
  python -m lab source M4b --open        # opens the pair in $EDITOR / code -d
```

`python -m lab source <scenario>` prints just the paths (ORIGINAL · LEDGER ·
MANIFEST · REFERENCE, absolute, plus the before/after sha of the original
proving the lab never touched it) — the quickest way to get from a scenario
name to your real file.

Two rules that make this actually eyeball-able:

- **Cited lines are quoted inline** (trimmed to the asserted fields) — check
  without opening anything; the paths are there when you want the original.
- **Real numbers, so the lab does the arithmetic.** Inputs are your actual
  files (§2.1), so totals are whatever those sessions really contained — every
  addend is shown with its source line and a running sum, so each step stays
  checkable without mental math.

Paths are absolute in terminal output (clickable), tilde-relative in anything
published.

**One stop for the whole run: `runs/EYEBALL-INDEX.md`** — written by every
`lab run`, it is the single file to open after a run:

```
scenario  what it proves                       verdict  eyeball
M1        claude solo (shared store)           ✓ pass   runs/M1/eyeball.md
M2        copilot solo (cli+vscode split)      ✓ pass   runs/M2/eyeball.md
…
G5        graphify + kiro + copilot combined   ✗ FAIL   runs/G5/eyeball.md   ← tokens_in off by 12
```

Failures sort to the top with the failing metric and delta inline, so the
first thing seen is what to look at. The run summary's last line is this file's
absolute path.

## 6. Runner UX

```bash
python -m lab setup                      # once (idempotent)
python -m lab run --all                  # full matrix M+G, auto-verify, exit 1 on red
python -m lab run M2 G5                  # named scenarios
python -m lab run --matrix cli|vscode|solo|combined|graphify
python -m lab eyeball M2                 # the side-by-side surface (one scenario)
python -m lab eyeball --all              # rewrite every eyeball.md + the index
python -m lab source M2 [--open]         # print (or open) the REAL original file paths
python -m lab inputs --list              # every scenario → the REAL file it reads (§2.1)
python -m lab playground                 # create/refresh Arpit's sandbox (§7)
python -m lab publish                    # dated summary → ../cage/docs/regression/
```

Every `lab run` ends with two lines: the pass/fail table, then the absolute
path of `runs/EYEBALL-INDEX.md` — the manual-verification entry point.

## 7. The playground (Arpit's #4)

`python -m lab playground` creates/refreshes `../cage-lab/playground/`: a real
git repo with cage installed (own venv), MCP wired via `cage setup --all`, all
read-only symlinks to the real logs in its private scratch HOME, real graphify on PATH, and
a `PLAYGROUND.md` cheat-sheet (try: `cage import` → `cage report` →
`cage insights attrib` → `cage data migrate-savings` dry-run → eyeball paths).
Own `CAGE_BASE` (`playground/.cage`); the automated runner **never reads or
writes anything under `playground/`** (enforced: runner asserts its cwd/paths
never resolve there). Refresh only on explicit command — Arpit's mess persists
between sessions by design.

  append-only byte-check) · R11 doctor + `--wiring` inventory + `--bundle` PII
  grep · R12 CSV contracts · R13 taskcorr stays caged (off by default; min-n
  blocks; enabled+gated output tagged estimated; ledger byte-identical).
  (v2's R5/R6/R7 are absorbed into the §3 matrix.)
- **L-labs (real ledger, read-only):** L1 spend per agent × surface · L2
  savings reality (legacy store vs tree, real vs demo) · L3 health vs ledger
  contradictions · L4 UNPRICED population (fix lines runnable) · L5 manifest
  coverage + the taskcorr field gate (reports "gate unreachable" if `tasks.jsonl`

- **Finding taxonomy:** `savings-empty` · `health-contradiction` ·
  `unpriced-population` · `manifest-orphans` · `dead-wiring-leftovers` ·
