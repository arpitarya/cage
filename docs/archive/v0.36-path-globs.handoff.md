# Handoff: `path_globs` — move `--path` discovery patterns into `cage.toml`

**One-liner:** `cage import --path` currently uses glob literals hardcoded per agent in
`importcmd.py` — and copilot's can never reach its VS Code store. Replace them with a
declared **`path_globs`** key that follows the existing `[sources]` seed → materialize →
authority pattern, so the operative patterns live in `cage.toml`.

**Owner / executor:** Claude Code — **Model: Opus.** This touches the source-resolution
contract (`paths.resolve_log_sources`, the materializer, all three import branches) and
introduces a behaviour change on an unmaterialized project. Not a one-line fix.

**Status:** Ready to build. **No paid LLM calls.** **Cage tree stays uncommitted.**

**Stress-tested:** three challenges, two changed the design.

1. **"Just reuse the existing `[sources] glob` for `--path`."** Rejected — it is
   **anchored** to its declared root (`*/chatSessions/*.jsonl` under `workspaceStorage`),
   so pointing `--path` at a `chatSessions` directory still matches nothing. That is
   precisely the reported bug, relocated. **A second, root-agnostic key is required.**
2. **"One-line fix: copilot `*/events.jsonl` → `**/*.jsonl`."** Works, and is only
   *incidentally* safe — a foreign `.jsonl` under `--path` happens to parse to zero rows.
   Rejected in favour of naming both copilot shapes explicitly (Arpit's option B), which
   is safe by construction and states its intent.
3. **"Keep a code fallback when `path_globs` is absent."** Rejected by Arpit's
   directive (values live in `cage.toml`, not in Python) — **but** the seed stays in code
   so patterns upgrade with the package, exactly as `[sources]` already does. The
   distinction: code holds the **seed**, `cage.toml` holds the **authority**.

**Residual risk:** `--path` stops working in a project whose `cage.toml` has no
`[sources]`. That is deliberate and consistent with the existing "empty `[sources]`
captures NOTHING" law, but it is a **behaviour change** and must fail **loudly**, never
silently.

**Evidence:** leg D cell record `cage-lab/reports/cells/D3-copilot-vscode-off.md`;
`docs/OPEN-WORK.md`.

## 1. Context

`importcmd.py` has three `--path` branches, each with a hardcoded glob:

| agent | current `--path` glob | status |
|---|---|---|
| claude | `**/*.jsonl` | works |
| **copilot** | `*/events.jsonl` | **broken** — CLI shape only, cannot reach `chatSessions/*.jsonl` |
| kiro | `*` | works |

`_parse_copilot_any` **already dispatches on shape** (`f.parent.name == "chatSessions"`),
and `_detect_graphify_copilot` uses the same test — both stores are fully supported
downstream. Only the glob can't reach one of them.

Symptom: `⚠ copilot: <path> matched 0 files — capture is off for this agent`, while the
files sit there and parse fine. Cost ~20 minutes during leg D because the message never
said *what it was looking for*.

## 5. Technical approach (decided)

- **Two keys, two jobs.** `glob` = anchored to its declared root, for normal imports.
  `path_globs` = **root-agnostic**, used only when `--path` overrides the location.
  Overloading one key reintroduces the bug in a new place.
- **Seed → materialize → authority**, identical to `[sources]`: the code seed exists so a
  new agent store ships in a *release* rather than in everyone's hand-edited toml; `cage
  setup` writes it into the project file; the project file is what import reads.
- **Explicit shapes over recursion.** Copilot declares both known shapes rather than
  `**/*.jsonl`, so only copilot-shaped files can match — safe by construction, not by the
  accident of a foreign file parsing to zero rows.
- **Loud absence.** Consistent with `⚠ no [sources] in cage.toml — cage is capturing
  nothing`. A silent code fallback would recreate the two-places problem this change
  exists to close.

## 6. Non-negotiables

- stdlib only; `dependencies = []`.
- **No glob literal in `importcmd.py`'s `--path` branches** — grep-gated.
- Fail-open on the write path; typed `CageError` only at the CLI boundary.
- Absent/empty `[sources]` ⇒ no capture, stated loudly — never a silent default.
- Byte-identical behaviour when `--path` is **not** used.
- Do not touch: parsers, `schema.py`, receipt/ledger semantics, `docs/regression/**`.
- No commits in the cage tree.

## 7. Dependencies

None. Fixtures can be built from the leg-D shapes (`<sid>/events.jsonl`,
`ws/chatSessions/*.jsonl`).

## 8. Edge cases & risks

- **`path_globs` absent** (unmaterialized project) → loud no-op naming the fix. **Test
  this**; it is the behaviour change.
- **A user's hand-written `path_globs`** → honoured verbatim; never merged with the seed
  behind their back.
- **Overlapping patterns** matching one file twice → dedupe the file set before ingest;
  a file must not be parsed twice.
- **`--project` (claude)** shares the branch — must keep working.
- **Windows separators** in declared globs — normalise or document; don't guess silently.
- **`replace = true`** on a `[sources.<agent>]` — decide and state whether it also
  replaces `path_globs` (recommend: yes, same table, same semantics).

## 9. Testing

1. `--path` at `<dir>/<sid>/events.jsonl` → imports; CLI parser's surface.
2. `--path` at `<dir>/ws/chatSessions/*.jsonl` → imports; **`surface = "vscode"`**.
   *This is the test that pins the actual fix* — D3 only showed `vscode` because the
   `[sources]` override declared it; under `--path` the parser's own value must be right,
   and that is untested today.
3. Both shapes under one `--path` → both import, no double-count.
4. A foreign `.jsonl` under `--path` → **not matched** (not merely "parses to zero").
5. No `--path` → registry behaviour byte-identical.
6. Absent `path_globs` → zero files **and** the loud message.
7. **Grep-gate:** no glob string literal in `importcmd.py`'s `--path` branches.
8. Materializer round-trip: `cage setup --sync-sources` writes `path_globs`; re-running is
   idempotent; a hand-edited value survives.
