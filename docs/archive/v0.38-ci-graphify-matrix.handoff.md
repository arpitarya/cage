# Handoff — a graphify axis in CI

**Goal:** CI proves cage behaves correctly **with graphify present and absent** — today
both CI workflows run without graphify installed, so the entire integration surface
(shim interception, receipt push, transcript detection, doctor's liveness checks) is
tested only by mocks, and WIN-GF-class bugs surface at *release*, not PR.

**What made this cheap:** graphify is AST-only — `graphify update/query` makes **no
LLM call**. Installing the real binary in CI and running real queries against a
fixture repo costs $0. The only thing CI can never do is drive a real *agent* (paid);
that stays cage-lab's job. The boundary: **CI proves capture and derivation; the lab
proves agent adoption.**

## The matrix

Extend `python-package.yml` (3 OS × Python versions) with a `graphify: [absent,
present]` axis — six-ish jobs, keep the pairing pruned (e.g. `present` only on the
newest Python per OS) to hold CI time.

| leg | proves |
|---|---|
| **absent** (today's suite, unchanged) | cage never *requires* graphify: no import error, no receipt, doctor reports not-installed honestly, derived views identical to goldens |
| **present** (new) | the integration surface, against the real binary |

## The `present` leg — what it actually runs

1. **Install real graphify** (npm) + build a scratch project from the fixture corpus
   (`tests/fixtures/`, or a minimal committed one — **never** cage-lab's frozen
   `tinyshop`, which stays lab-only; a CI corpus is a *new named corpus* per the
   frozen-corpus decision).
2. **Shim interception (POSIX legs):** `cage setup` installs `bin/graphify`; invoke
   bare `graphify query` with the shim PATH-winning; assert a savings row lands and
   `usage rows ≥ receipts`. This is the F1 path, currently only lab-tested.
3. **Windows leg = the WIN-GF regression test — and its acceptance harness.**
   Install real graphify (npm ⇒ `graphify.cmd`), run `cage setup`, put `bin/` first on
   PATH, invoke **bare `graphify`**. Assert the *current truth*: it does **not** resolve
   to cage's shim (PATHEXT has no extensionless entry), while the direct
   `cage data graphify` path works post-v0.37.1.
   **[WIN-GF](v0.38-win-graphify-shim.handoff.md) depends on this leg** — that invocation *is*
   its acceptance test, on the only Windows the dev machine has. Build this first, so the
   `.cmd` twin lands under a green harness; shipping it **flips** this assertion, and the
   test is written to make the flip loud rather than silent.
4. **Doctor liveness:** `cage doctor` reports the shim `live` where wired; `dead` when
   the test breaks it deliberately (the 9-day silent-unmetered class, F1's root cause).
5. **Determinism cross-check:** the same recorded transcripts imported on both legs ⇒
   **byte-identical calls tables**; the `present` leg differs only by savings/receipt
   rows it genuinely produced.

## Constraints

- **No paid calls in CI, ever.** Any test needing real agent traffic is lab-scope.
- npm/network is release-CI-acceptable (publish.yml already builds cross-OS), but the
  `present` leg must **skip cleanly** (not fail) if npm install flakes — flake-immunity
  over coverage; the absent leg is the gate that always runs.
- Pin the graphify version in the workflow; bump deliberately (a floating latest makes
  CI red on *their* release day).
- cage-lab remains the authority on capture *fidelity* (real agents, real stores); CI
  asserts *mechanics*. Don't duplicate lab scenarios into CI.
