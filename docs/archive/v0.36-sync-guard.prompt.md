# Claude Code prompt — guard the sync tests' borrowed table

**Model: Sonnet.** One small test plus a comment. No handoff doc — the change is too
small to warrant one (CLAUDE.md's pair rule); the decision behind it is in
`docs/proposals/policysync-synthetic-bundle.proposal.md`.

**No paid LLM calls. The cage tree stays uncommitted.**

## The problem this prevents

Five `test_policysync` tests exercise **generic sync mechanics** (keep-customized,
update-stale-default, confirm-bucket, orphan-warning) using whatever live bundle table
happens to be scalar-keyed as their worked example — `[budgets]` before, `[quality]
signal` now (SUITE, 2026-08-01).

When BUD-V made `[budgets]` opt-in, those five went red. **The cost was diagnosis, not
repair**: the re-point took minutes, but five budget-unrelated failures with no obvious
connection took far longer to understand.

## Task

Add **one** test asserting the borrowed table/key still exists in the bundle, failing
with a message that says exactly what to do:

```
test_policysync borrows [quality] signal as its worked example for generic sync
mechanics. That key is no longer in the bundled cage.toml, so those tests are
testing nothing. Re-point them at another actively-shipped scalar key (it must
also survive _strip_to_v016, which removes [meta], [cleanup] and
import_before_export). See docs/proposals/policysync-synthetic-bundle.proposal.md.
```

Requirements:

- Derive the borrowed table/key from **one named constant** at the top of
  `test_policysync.py` (e.g. `_EXAMPLE_TABLE, _EXAMPLE_KEY = "quality", "signal"`), and
  have the five tests use it. Re-pointing then becomes a one-line edit instead of a
  five-test rewrite — that is most of the value here.
- The guard asserts against `policy.bundled_raw()`, the same source `policysync` reads.
- Add a short comment at the constant explaining *why* it exists, pointing at the
  proposal.

## Explicitly not in scope

The synthetic bundle fixture. It is filed as a proposal with a trigger (a **third**
occurrence). Building it now is a half-day refactor on a green 956/0 suite immediately
before a release — good engineering, wrong timing.

## Constraints

- **Do not change what the five tests assert.** Only how they name the example table.
- Do not touch `test_already_in_sync_message_on_current_file` — it is the real-bundle
  smoke test and must keep running against the actual shipped bundle.
- stdlib only; no commits in `cage`; don't touch `docs/regression/**`.

## Acceptance criteria

- [ ] `just test` green; count refreshed in README + CLAUDE.md if it moved
- [ ] The five tests take their table/key from one constant
- [ ] Removing that key from the bundle produces **one** clear failure naming the fix —
      verify by temporarily editing a copy, not the shipped bundle
- [ ] Real-bundle smoke test untouched
- [ ] `SYNC-GUARD` removed from `OPEN-WORK.md` (record the outcome in
      `IMPLEMENTATION.md` first — that is the removal precondition); the proposal is
      linked from the decisions section
- [ ] IMPLEMENTATION / WORKLOG / DOC-REGISTRY updated

## Handback

The guard's failure message (paste it) · confirmation the five tests assert exactly what
they did before · whether anything else in the suite borrows a live bundle table the same
way.
