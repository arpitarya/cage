# Claude Code prompt: split model prices into `.cage/prices.toml`

**Model:** **Opus** — this is the money path. A dropped or mis-resolved price row
doesn't crash: it silently reprices calls to UNPRICED, or worse to a family match
that looks plausible. Getting it right once is far cheaper than diagnosing it
later.

**Standing constraint: DO NOT COMMIT in `cage/`.** Leave the tree dirty.

---

You are moving the model price table out of `cage.toml` into its own
`.cage/prices.toml`. Spec: `docs/prices-toml.plan.md`. Definition of done:
`docs/prices-toml.handoff.md`. Both binding.

## The one rule that settles every border case

> **Vendor facts move. Routing decisions stay.**

A vendor rate card moves to `prices.toml`. Anything describing *this user's
setup* stays in `cage.toml` — because a wholesale price sync must never wipe it.

## What moves, exactly

**→ `prices.toml`:** every `[prices.<provider>.<model>]` table · `[credits]` ·
from `[meta]`, **only** `prices_version` + `prices_date`.

**Stays in `cage.toml`:** everything else, and specifically:

- **`[alias]`** — an alias says "*this* router id in *my* setup means that
  model". It describes your environment, not a vendor's rate card. Do **not**
  move it (an earlier draft did; that was corrected).
- **`[tools.<tool>] price_at`** — routes *your tool's* receipts to a model.
- **`cage_version` + `policy_version`** from `[meta]`.

**`[meta]` splits per key, not wholesale.** It carries two provenance counters:
`prices_version`/`prices_date` (price research date → the staleness nag and
`cage prices sync`) and `cage_version`/`policy_version` (non-pricing tunables →
`cage policy sync`). Mis-split it and a staleness check **silently stops
firing** — no error, just a warning that never appears again.

## Task

1. **Baseline first, before touching anything.** On a real ledger, capture
   `cage report`, `cage insights attrib`, `cage insights roi` output and the
   UNPRICED row count. This is what you will diff against. Also count the
   `[prices.*]` tables in the bundled config — you will assert the same count
   resolves afterwards.
2. **One resolution point** — `Footprint.prices`: `prices.toml` → legacy
   in-`cage.toml` tables → bundled default. Both present ⇒ `prices.toml` wins
   plus a one-line warning naming the ignored legacy block (mirror
   `shadowed_config`). **No second filename literal anywhere.**
3. **`policy.load` keeps returning ONE merged dict.** This is a *file* change,
   not an API change — `prices.call_usd`, `policy.price_match`, `convert`,
   `receiptprice` must all read exactly the shape they read today. This is what
   makes byte-identity achievable; if you find yourself changing a consumer,
   stop and reconsider.
4. **Split the bundled data** — `cage/data/cage.toml` → `+ cage/data/prices.toml`;
   update `pyproject.toml` package-data; verify the **zipapp** still resolves both
   through `paths.bundled_data()`.
5. **Migrate on `cage setup`** — move the tables out of `cage.toml` into
   `prices.toml`, leave a pointer comment. Idempotent, non-destructive when both
   exist, fail-open. Same for the **global `~/.cage`** config.
6. **`cleanup.NEVER`** protects `prices.toml` alongside `cage.toml` and legacy
   `policy.toml`.
7. **Command surfaces** — `cage prices set` writes `prices.toml`; **`alias` and
   `route-tool` write `cage.toml`** (routing decisions); `cage prices sync`
   replaces the cage-managed region of `prices.toml` while `# cage:custom` rows
   survive; `cage policy sync` becomes unambiguously `cage.toml`-only;
   `cage doctor` names the active prices file and flags a shadowed legacy block.

## Verify — numerically, not structurally

The bar is **the money does not move**:

- [ ] `report` / `insights attrib` / `insights roi` **byte-identical** to the
      step-1 baseline
- [ ] UNPRICED row count **unchanged by one row**
- [ ] The `[prices.*]` table count resolves to the same number — count, don't
      eyeball
- [ ] `policy.price_match` returns the same kind (`exact|alias|family|none`) for
      a sampled set of **real** model ids from the ledger. A silent
      `exact`→`family` degradation is a wrong number wearing a plausible tag —
      check for it deliberately
- [ ] A legacy project (prices still in `cage.toml`) reads identically via the
      fallback
- [ ] Both-present ⇒ `prices.toml` wins, warning shown
- [ ] `cage setup` migration run twice changes nothing
- [ ] zipapp (`cage.pyz`) finds both bundled files
- [ ] `pytest -q` green; determinism tests unchanged in shape

## Constraints (hard)

## Guardrails

- **STOP and ask if:** a money view differs by even one cent and you can't
  attribute it · a fourth border-case table appears that the vendor-fact/routing-
  decision rule doesn't cleanly settle · the split appears to require changing a
  pricing consumer's expected dict shape.
- A price row that resolves differently after the split is a **defect in the
  split**, not an acceptable variance. Never adjust the baseline to match.
