# Handoff: copilot-metrics — `.cage/ledger/copilot/`, the per-chat Copilot metrics ledger

**What's next:** build a new append-only ledger kind — `.cage/ledger/copilot/chats-YYYY-MM.jsonl`
— capturing, for every Copilot chat, the vendor's own recorded numbers: tokens in/out,
cached (read) tokens, per-request credits, session credits, nano-AIU, and timing —
from **all five** on-disk stores (Arpit's scope call, 2026-08-13). Capture-only: no
derived view reads it in this build, so **no reported number moves and no golden
re-blesses**. The change map in §4 names every file and function — follow it and the
build is a zap.

**Grounding:** [research/2026-08-13-copilot-per-chat-usage-fetch-spec.md](../research/2026-08-13-copilot-per-chat-usage-fetch-spec.md)
(the five stores: dir · file · row · prop, verified against upstream `main` 2026-08-13).
Where this handoff names a store prop, that doc is the evidence.

---

## 1. Context & background

- Cage's `calls` rows keep tokens in/out + `credits` for Copilot, but **drop** the rest
  of what the stores persist: `modelTotals` (per-model cached tokens — durable, ungated,
  new upstream), `sessionCopilotCredits`, `elapsedMs`/`timeSpentWaiting`, the sidecar's
  per-call cached + nano-AIU, and the OTel db's per-call cached tokens.
- Widening the closed call schema again is the wrong tool — these are copilot-native
  facts at three different grains (request / session / model-call). They get their own
  kind, the way kiro-CLI got `credits-YYYY-MM.jsonl` and tool savings got
  `savings/<tool>/`.
- Precedents to mirror, not reinvent: `_ingest_credits` (own kind, own id namespace,
  own seen-set, fail-open per file) · `Footprint.savings_shard` (ledger sub-dir) ·
  `ledger.credits` (append-only + last-write-wins collapse read) ·
  `parse_kiro_cli_credits` (read-only SQLite with a key whitelist, ADR 0009).

## 2. Definition of done

- [ ] `cage import --agent copilot` (and the all-agent sweep / capture-on-read) writes
      `.cage/ledger/copilot/chats-YYYY-MM.jsonl` rows from every source present on the
      machine; a re-run appends **zero** rows (idempotent by id).
- [ ] Rows exist for: chatSessions requests · CLI shutdowns · sidecar model-calls ·
      debug-log model-calls · OTel-db model-calls — each stamped with its `source`.
- [ ] A grown chatSessions request / resumed CLI session appends a fresh row;
      `ledger.copilot_metrics()` collapses to the latest per key.
- [ ] **No derived view reads the new kind**: `cage report` and `cage insights chats`
      stdout byte-identical with the `copilot/` tree present vs deleted (tested).
- [ ] `cage doctor` gains an advisory `copilot-metrics` line (per-source found/absent;
      gated sources name their enabling setting) — advisory, never a failure.
- [ ] Counts-never-content holds on every new read path (see §6 — two stores carry
      prompt bodies next to the numbers).
- [ ] Full suite green; `test_floor`, goldens, `test_cli_reference` untouched.

## 3. Scope

**In:** new kind (schema + paths + ledger reader) · five parsers · import wiring ·
two new chatSessions roots (+ the dispatch fix they force) · doctor advisory ·
`cage query copilot-metrics` explainer · tests · docs.

**Out (each a one-line OPEN-WORK item on completion, not silently dropped):**
read surface (chats-view columns / a `cage insights copilot` view) · `cage data export
--csv copilot` · pricing changes (`creditprice` ladder untouched) · fixing the v0.44
CLI credit-delta bug in the *calls* parser (separate defect; the metrics CLI parser
records cumulative verbatim and structurally dodges it).

## 4. Change map (researched 2026-08-13 against HEAD — follow it; re-verify only what looks stale)

### 4.1 `cage/schema.py` — the row (substrate change ⇒ PLAN §3 update in same change)

- `COPILOT_METRIC_SOURCES = ("chat", "cli", "sidecar", "debuglog", "otel")` — closed enum.
- `make_copilot_metric(*, source, session, surface="", request="", call="", model="",
  tokens_in=0, tokens_out=0, cached_in=0, model_totals=None, credits=None,
  session_credits=None, nano_aiu=None, elapsed_ms=0, waiting_ms=0, ttft_ms=0,
  ts=None, project="", metric_id=None) -> dict`
  - `agent` fixed `"copilot"`. `source` validated against the enum.
  - Counts (`tokens_*`, `cached_in`, `elapsed_ms`, `waiting_ms`, `ttft_ms`)
    **omit-at-zero** (house idiom).
  - `credits` / `session_credits` / `nano_aiu` are **None-sentinel** — written only when
    the store recorded them; absence ≠ 0 (the same law `make_call.credits` already
    breaks the omit-at-zero pattern for, and for the same reason).
  - `model_totals`: list of `{model, tokens_in, cached_in, tokens_out}` (keys
    whitelisted, renamed from the store's `inputTokens`/`cachedTokens`/`outputTokens`);
    omitted when empty.
  - id default `ids.new_id("cm")`; parsers always pass a deterministic `metric_id`.

### 4.2 `cage/paths.py` — shard routing + sources

- `Footprint.copilot_shard(ts)` → `copilot/chats-<YYYY-MM>.jsonl` (no-month fallback

- `Footprint.shard()`: route plain kind `"copilot"` → `copilot_shard` (beside the

- `Footprint.copilot_shards()` → `sorted(copilot_dir.glob("chats*.jsonl"))`

- `_builtin_sources` copilot entry: **+2 tuples** (calls capture gains these chats too):
  `(vscode_user_dir()/"globalStorage"/"emptyWindowChatSessions", "*.jsonl",
  ("**/emptyWindowChatSessions/*.jsonl",))` and the same for `transferredChatSessions`.
  (`no-workspace/chatSessions/` is already matched by the existing

- New module-level `copilot_metric_sources() -> list[tuple[Path, str, str]]`

### 4.3 `cage/ledger.py` — the readers

- `copilot_metrics_raw(root)` — glob `Footprint.copilot_shards()`, concatenated read
  (feeds the import seen-set; mirror the `savings()` shape incl. `_month_entirely_below`).
- `copilot_metrics(root, since=None)` — raw rows collapsed **last-write-wins per
  `(source, session, surface, request, call)`**, winner = max by
  `(tokens_in + tokens_out, credits or -1, id)` — the `credits()` collapse, generalized.
  Call-grain keys are unique so collapse is a no-op for them; it bites only on grown
  chatSessions requests and resumed CLI sessions. Docstring states **never sum**
  `session_credits`/CLI cumulative rows across a session's rows.

### 4.4 `cage/transcript.py` — five parsers (one per store)

- **Refactor first**: extract the request-merge loop of `parse_copilot_vscode_calls`
  (lines ~695–711: read, `kind:0` session lift, `kind:2 k==["requests"]` last-write-wins
  merge) into `_vscode_chat_requests(path, session) -> tuple[str, dict[str, dict]]`;
  both the calls parser and the new metrics parser call it. Pure move — the existing
  vscode fixture test pins byte-identical calls output.
- `_COPILOT_SESSION_CREDIT_KEYS = ("sessionCopilotCredits", "session_copilot_credits")`
  beside the existing key tables (~l. 379).
- `parse_copilot_vscode_metrics(path, session="")` — per merged request carrying any
  signal (tokens, credits, `modelTotals`): `source="chat"`, `surface="vscode"`,
  `request=requestId`, `model=modelId`, tokens from the existing key tables,
  `cached_in=Σ modelTotals[].cachedTokens`, `model_totals` mapped per §4.1,
  `credits=_first_float(req, _COPILOT_CREDIT_KEYS)`,
  `session_credits=_first_float(req, _COPILOT_SESSION_CREDIT_KEYS)`,
  `elapsed_ms`/`waiting_ms` from `elapsedMs`/`timeSpentWaiting`,
  `project=_vscode_project(...)` (reuse), `ts=_epoch_ms_iso(timestamp)`,
  `metric_id="cm_" + sha1(source|session|requestId|<sorted payload json>)[:16]` —
  **values folded into the id** so a grown request appends a fresh row (the
  `make_credit` turns-fold idea, generalized).
- `parse_copilot_cli_metrics(events_path, session="")` — one row per
  `session.shutdown`: `source="cli"`, `surface="cli"`, `request=""`,
  `model_totals` = the per-model **cumulative** usage map verbatim (`inputTokens`
  already includes cache r+w — never add `cacheReadTokens` to it),
  `credits=totalPremiumRequests` (float, verbatim — never `int()`),
  `nano_aiu=totalNanoAiu`, ts from the event. Cumulative-verbatim + collapse replaces
  delta math entirely (and dodges the v0.44 delta-loss bug by construction).
- `parse_copilot_sidecar_metrics(path, session="")` — session = file stem (the
  sanitized session id, recorded verbatim); one row per line:
  `source="sidecar"`, `call=turnId`, `model`, tokens from
  `inputTokens`/`outputTokens`/`cacheReadTokens`, `nano_aiu=totalNanoAiu`, `ts` from
  the line; id folds the line payload. Record `nano_aiu` verbatim — **never derive
  `credits = nano_aiu/1e9` at capture** (division is derive-time; the research doc
  records the 1e9 relationship).
- `parse_copilot_debuglog_metrics(path)` — session = the session-dir name
  (`debug-logs/<sessionId>/`); **only** `type == "llm_request"` lines; **whitelist
  read**: `attrs.model`, `attrs.inputTokens`, `attrs.outputTokens`, `attrs.ttft`,
  `ts`, `spanId` → `source="debuglog"`, `call=spanId`. The same lines carry
  `attrs.userRequest` and `attrs.inputMessages` — **prompt bodies; never read them
  into anything** (ADR-0009 discipline: transient whitelist, counts only).
- `parse_copilot_otel_metrics(db_path)` — stdlib `sqlite3`, URI `mode=ro`, read-only
  by construction: `SELECT span_id, COALESCE(conversation_id, chat_session_id),
  COALESCE(response_model, request_model), input_tokens, output_tokens, cached_tokens,
  ttft_ms, start_time_ms FROM spans WHERE operation_name='chat'`. **Never** touch
  `span_attributes` / `span_events` (they can carry message content under
  `otel.captureContent`). `source="otel"`, `call=span_id`, ts from `start_time_ms`
  (epoch ms → the `_epoch_ms_iso` helper). Any `sqlite3.Error` ⇒ return `[]`
  (fail-open; WAL tail not yet checkpointed is acceptably missed — never checkpoint,
  that mutates).

## 5. Technical approach (decided — do not re-litigate)

- **Record facts verbatim, per store grain; derive later.** Per-request (chat),
  per-session-cumulative (cli), per-model-call (sidecar/debuglog/otel). No deltas, no
  unit conversions, no cross-store joins at capture.
- **Own kind, own id namespace (`cm_`), own seen-set** — metrics rows can never
  collide with or leak into call views (the `credits` precedent).
- **Grown-source correctness = id-folds-values + collapse-on-read** — append-only past
  never rewritten, latest state wins at read.
- **Ledger sub-dir via the savings mechanism**, not a generalization of `shard()` —
  smallest diff, precedent already tested.
- **Gated stores get their own registry** (`copilot_metric_sources`), never
  `agent_log_sources` — the calls sweep must not start parsing sidecar/debuglog/otel
  files.

## 6. Non-negotiables / constraints

- **Counts-never-content, enforced by whitelist** on the two stores that interleave
  prompt bodies with numbers (debuglog `userRequest`/`inputMessages`; otel
  `span_attributes`/`span_events`). No chat titles anywhere (ids + counts + model ids
  + project basename only).
- **Absence ≠ zero** for `credits`/`session_credits`/`nano_aiu` (None-sentinel).
  **Never sum** `session_credits` or CLI cumulative rows. **Never derive** credits
  from nano-AIU or tokens at capture.
- **Fail-open everywhere** on the write path; per-file/per-db try-except with
  `CAGE_DEBUG` trace (test_debug_coverage will check the swallow sites).
- **No derived view reads the kind in this build** — determinism, goldens, and
  `test_floor` must pass untouched; the byte-identity test in §9 is the gate.
- **$0 stdlib** — `sqlite3` is stdlib; no new deps. Idempotent re-import. Cleanup can
  never touch it (`ledger/` is protected by construction — add no cleanup class).

## 8. Edge cases & risks

- **Mid-session import** records partial request numbers → healed by id-fold + collapse
  on the next sweep. Test it.
- **Sidecar files die with their session** (deletion is not gated on the setting) —
  capture-on-read makes prompt import the default posture; nothing else to do.
- **debuglog session id may not equal the chatSessions session id** (extension-internal
  id) — record verbatim; joining is a read-surface problem, out of scope. Same for the
  sidecar's *sanitized* session id (file stem recorded as-is).
- **OTel schema drift** (pre-1.0 store): missing column ⇒ `sqlite3.Error` ⇒ `[]`,
  fail-open; never assert the schema.
- **Volume**: three per-call stores appended monthly — `LEDGER_WARN_BYTES` already
  covers runaway growth; no new mechanism.
- **Foreign chat providers** share the chatSessions store — the metrics parser must
  apply the same `_copilot_chat_extension` guard the calls parser does.
