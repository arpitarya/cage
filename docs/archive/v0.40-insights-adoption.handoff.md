# Handoff — `cage insights adoption`

**The question:** you installed graphify for three agents. Do they *use* it? Leg D found
claude invoked it unprompted while copilot and kiro never did — a differentiating
finding no cost dashboard can produce. It currently lives in a regression doc, not a
command.

---

## ⚠️ Review finding: the proposal's headline is only half-derivable

[The proposal](v0.40-insights-adoption.proposal.md) promises **"per agent × tool:
invocations · receipted · missed · never invoked"**. Verified against the substrate:

**Usage rows have no `agent` field.** `usagelog.record` writes
`ts · op · args_hash · exit · ms · outcome · route` — that is the whole row. So
per-agent adoption **cannot** come from the usage log.

**And the shim doesn't know the session.** `graphifymeter` says so explicitly (the
receipt-id deferral exists *because* "the shim … does not know the session"). So:

| route | session | agent derivable? |
|---|---|---|
| **transcript** | real | **yes** — join `savings.session` → `calls.session` → `calls.agent` |
| **shim / native** | empty | **no** — a subprocess cannot know which agent spawned it |

**This is structural, not a gap to fix.** Leg D's own finding was *route: transcript* for
exactly this reason. Note the uncomfortable corollary: **leg D's per-agent claim was
operator-attributed** (one agent per lab cell), not data-attributed.

## The view, as it can honestly be built

**Two halves, different sources, different precision — never blended into one number.**

**A. Invocation totals + outcomes** — from usage rows. Exact, no join.
`OUTCOMES = ("receipt", "unmeasurable", "empty", "non-measured", "error")` **already
encodes** the distinction the proposal celebrates: "ran and cage missed it" is
`outcome != "receipt"`, a recorded field, not a derivation. Break down by `op` and by
`route` (shim / native / transcript).

**B. Per-agent attribution** — from savings rows carrying a session, joined to
`calls.agent`. **Transcript route only.** Shim/native rows are **agent-unknown by
construction** and must render as such — never folded into an "other" bucket, never
attributed by a timestamp guess.

**"Never invoked"** = an agent with calls in the window and zero joined savings rows.
State it as *no evidence of invocation*, not as proof of non-use — absence of evidence,
in a view whose whole point is honesty about what capture saw.

## Constraints that will bite

- **Usage rows stay diagnostic-only.** CLAUDE.md: never priced, never read by a derived
  *money* view, tested byte-identical. This view **counts** them and prints **no
  currency at all** — keep it that way, and say so in the docstring, or the invariant's
  next reader will think it was broken.
- **K4 inherits:** claude's CLI and VS Code share one store, so `surface` stays
  unknowable there; `project` is the discriminator that works. Reuse the existing
  `Footer` caveat machinery rather than inventing new wording.
- Derived view only — **no new capture, no schema change**. If per-agent coverage
  proves too thin to be useful, that is a **finding**, not a reason to add an `agent`
  field mid-flight.
- Determinism, CSV parity (§3.9), MCP mirror — same as report/attrib/roi.
