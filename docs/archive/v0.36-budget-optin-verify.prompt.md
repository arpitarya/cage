## What changed and why

`cage/data/cage.toml` shipped budget ceilings **on**:

```toml
[budgets]
session_usd = 2.00
daily_usd = 25.00
on_exceed = "warn"
```

Every scaffolded project inherited a cap nobody chose. **Decision (Arpit, 2026-08-01):
budgets are opt-in — no key ⇒ no ceiling.** The table is now shipped commented out,
following the `[ledger] warn_mb` precedent, with **no constant fallback** (unlike
`warn_mb`) — there is no defensible default spend for someone else's project.

**No code change was made**, because the code already behaves correctly:
`policy.budgets` returns `None` for a missing key · `budget.check` computes
`over = bool(cap and …)` so `None` can't trip · `proceed` stays `True` ·
`render_budget` prints `—`.

**It was never validated.** It was authored in Cowork, whose sandbox runs Python 3.10
(cage needs 3.11+ for `tomllib`), so the suite could not run. A before/after baseline on
eight bundle-touching test files was identical (47F/39P/21E both ways) — no *new*
breakage visible there, but that is not a green suite.
