# Proposal — `cage insights chats`: one row per chat, titled where the store has a title

**Verdict up front: YES, buildable now, derive-time only — no substrate change.** Call
rows already carry every numeric column per chat: `session`, `agent`, `surface`,
`tokens_in`, `tokens_out`, `cached_in` (cache reads), `cache_write_in` (cache writes —
the closest real thing to "cached out"), `premium`. Titles exist for claude
(`summary`) and copilot-VS Code (`customTitle`/`generatedTitle`) and are already
lifted into the import manifest. NOT buildable honestly: titles for
copilot-CLI/kiro, per-chat rows for kiro-IDE (no session identity in its log), and
**"lines suggested" anywhere in v1** (no agent store persists it — see
*Deliberately not taken*).

## How it works — the whole mechanism in five steps

1. **Read** the ledger's calls (`ledger.read_kind(root, "calls")`), honor `--since`
   (month-partition skip, like report), drop legacy-human rows
   (`report._is_legacy_human` — counted, footnoted).
2. **Group** by `(agent, surface, session)` — the same bucket key the import manifest
   uses. Sum `calls · tokens_in · cached_in · cache_write_in · tokens_out · premium`;
   reprice per call via `prices.call_usd_match` (UNPRICED counted per row, never $0).
3. **Label** — join `session → session_name` from `imports.jsonl`
   (`manifest`-read carve-out below): last-write-wins per `(agent, session)` across
   the append-only file. No name ⇒ display the session id (short form). Never a
   fabricated name.
4. **Rank & bound** — sort `tokens_in` desc, then session id (deterministic). Default
   **top 20** rows; the footer counts what was cut (`… 143 more chats — --all to show`)
   — the no-silent-caps rule; `--all` lifts it.
5. **Render** — text table through `display.Display`/`Footer` (usd opt-in, gross note
   where savings appear, kiro-absence line reused from `report.kiro_routed_line`);
   `--csv` from the same data structure (`render_csv` beside `render_chats`, LF, RFC-4180,
   `—` never enters CSV).

```
ledger calls ──group (agent,surface,session)──► totals ──rank──► top-N table
imports.jsonl ──(labels ONLY, never money)──────► title column
```

## What each agent honestly shows

| agent · surface | chat identity | title | in/out | cached_in | cache_write | notes |
|---|---|---|---|---|---|---|
| claude (cli+vscode) | transcript file = session | `summary` ✅ | ✅ | ✅ | ✅ | the full-support case |
| copilot · vscode | chatSessions file | `customTitle`/`generatedTitle` ✅ | ✅ | ❌ store doesn't persist it | ❌ | credits/cached land via COPILOT-CREDITS; view then shows them free |
| copilot · cli | session-state dir | ❌ none in store | ✅ per-shutdown delta | ✅ | ❌ | id shown as the chat |
| kiro · ide | **none** — one global log | ❌ | ✅ (coarse) | ❌ | ❌ | ONE `kiro (no session identity)` row + footnote, never per-chat; absent under routing → `kiro_routed_line` |
| kiro · cli | conversation per cwd | ❌ (cwd label) | ❌ credits only | ❌ | ❌ | row per conversation, credits column, tokens honest-empty |

Empty cells render `—` in text and stay absent in CSV — *cannot say* must never read
as *zero* (the adoption discipline).

## The one law amendment: the manifest-label carve-out (option A — decided)

Names live ONLY in `imports.jsonl`, whose contract says **"never read by any derived
view."** The amendment is one scoped sentence, not a weakening:

> `imports.jsonl` is never read by a derived **money** view; `cage insights chats`
> joins `session_name` for **display labels only** — every numeric cell derives from
> ledger + policy alone.

- Pinned by test: **deleting `imports.jsonl` changes zero numeric cells** — only
  labels fall back to ids (byte-compare the number columns).
- Determinism restated: same ledger + same policy + same manifest ⇒ same table.
- PII surface unchanged: the name already lives in that local audit file; the view
  moves it to a screen, never onto a row, never into `--team`/ledger-sync (the view
  is **local-only by construction** — no `--team` flag, stated in help).
- Options B (re-parse stores at render: slow, breaks on rotated logs, duplicates
  `_lift_names`) and C (ids only: fails the ask) considered and declined.

## Known honesty limits (stated, not fixed)

- **Stale titles.** A manifest row is written only when a sweep *appends* rows for
  that session — a chat renamed after its last new call keeps its old title until it
  produces new rows. Label-grade staleness; acceptable, footnoted in `cage query
  chats-view`.
- **Legacy sessions.** Rows imported before the manifest feature have no name row at
  all → id display. Never backfilled (the ledger is never rewritten; a re-import
  dedupes to zero appended rows, so no manifest row appears).
- **A shared session id across agents** cannot collide: the join key is
  `(agent, session)`, same as the manifest bucket.

## Deliberately not taken (v1) — with triggers

- **"Lines suggested/accepted"** — no agent store persists it. Copilot's
  accepted-lines metrics are org-level API telemetry; kiro has nothing; claude
  transcripts could yield counts only by parsing Edit/Write content bodies — a PII
  widening (`counts-never-content` holds today because the parser touches only
  `usage`). **Trigger:** if agent-vs-human-v2's git-side suggested-vs-accepted counts
  ship, join them at **task** level (±120s window), labelled `modeled`, never
  per-chat-exact.
- **MCP mirror (`cage_chats`)** — after the CLI renderer settles; byte-identical rule
  applies when it comes.
- **Credits/cached columns for copilot-vscode** — arrive via COPILOT-CREDITS
  ([research](../research/copilot-vscode-token-sources.md) §4), not here.
