# Handoff: one report per run (split the layered validation report)

**One-liner:** Restructure cage-lab reporting so **every run emits its own
self-contained report** — no report ever accumulates a later run's numbers —
with cross-run movement in a history index and each defect's status owned by its
own finding doc.
**Owner / executor:** Claude Code
**Model:** **Opus** — the retro-split partitions published, hashed evidence; the
risk is silently attributing a number to the wrong run, which would poison the
corpus's credibility rather than merely confuse a reader.
**Status:** ✅ Implemented 2026-07-28 (cage tree uncommitted per directive; code in
cage-lab). Note on phase-4 status: the **shim-recursion** finding is filed OPEN (the
cage shim was hardened in capture-precision-fixes §MED, but a stale dead-verb foreign
shim on a real machine's PATH remains a wiring-hygiene hazard) — the finding doc states
both, which is the finding doc's job; no run-attribution was ambiguous, so no STOP was
triggered.
**Stress-tested:** Challenged: banners already fixed the misread → **no.** They
label the problem instead of removing it; a reader landing mid-file still sees
`227,298 · 189,788 ❌` and must scroll up to know which world they're in. The
shape is wrong: one document is answering three questions. Challenged: delete or
rewrite the old layered file → **rejected**, it is published hashed evidence;
it stays, marked SUPERSEDED. Riskiest step: the retro-split (phase 5) — mitigated
by taking numbers *only* from the existing published text, never recomputing or
"tidying" them. Residual: if the two split reports don't reproduce every number
in the original, the split is wrong — that's an acceptance check, not a footnote.
**Standing constraint: DO NOT COMMIT in `cage/`.** Commit in `cage-lab/` only.

## 1. Context

Plan: [report-per-run.plan.md](report-per-run.plan.md) (phase index at top).
Current layered artifact: `../cage-lab/golden/findings/VALIDATION-REPORT.md`,
published as `cage/docs/regression/2026-07-28-validation-report-4.md`.

The split, in one line each:

- **Run report** — what happened in *this* run. Immutable once published.
- **Finding doc** — a defect's status *now*, across runs. Mutable status.
- **History index** — one row per run, showing movement.

**The rule that follows: a run report never mentions a later run.**

## 3. Scope

**In:** phases 2–6 above (lab code + the retro-split + the published index).
**Out:** re-running any cell (this is a documentation restructure — **no paid
calls**) · changing any captured number · the manual sweep (its own future run
report) · cage source changes · committing in `cage/`.

## 5. Non-negotiables

- **Never rewrite or delete published evidence.** The layered file is marked
  superseded, not removed.
- **Transcribe, don't recompute**, during the retro-split.
- Append-only publishing; hashes verified, not just written.
- A run report is **immutable** once published — a correction is a new dated
  doc, not an edit.
- No paid agent calls in this task.
- **DO NOT COMMIT in `cage/`.**
