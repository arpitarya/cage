# Handoff — DOGFOOD: cage's own ledger, published so it cannot rot

**One-liner:** publish cage's real `~/.cage` numbers as a dated snapshot doc, link it
from the README once (version-free), and guard its freshness with a test instead of a
release-checklist line.

**Executor:** **P0 is Arpit's hands** (the real ledger lives on the dev machine and ZERO
dummy data is law). **P1–P3 are Claude Code**, built on top of P0's output.
**Order matters — P0 first**, so the suite is never deliberately red.

**Stress-tested:** four challenges beyond the session's own debate. **Held:** the
fakeable-guard problem (hardened — see §5 D3), the invented-numbers risk (killed by
sequencing, §6), the PII leak through project names and chat titles (killed by the
command allowlist, §6). **Residual, named not solved:** a date-based test is
calendar-triggered, so `git bisect` and re-running an old tag's CI can go red for a
reason unrelated to the commit — see §8 R1. Accepted with an escape hatch, this repo's
"stated limit, never half-fixed" pattern.

Design of record: [proposals/dogfood-report.md](proposals/dogfood-report.md)
(revised 2026-08-02).

## 5. Technical approach (decided — do not re-litigate)

- **D1 — dated snapshots, not a README block.** The filename is the stamp; a snapshot is
  never edited after publishing. The README link points at `latest.md` forever.
- **D2 — date is the freshness axis, version is provenance.** A cumulative ledger
  belongs to no single version. Record `snapshot_version` in frontmatter; **never gate
  on it** — v0.37→v0.43 shipped in ~two days and `__version__` is deliberately not
  bumped for in-tree work, so version-distance is a broken clock here.
- **D3 — the guard reads metadata, never numbers.** That is the only reason it can run
  in CI with no ledger. Two assertions, both required:
  1. `latest.md`'s `snapshot_date` is ≤ **60 days** old.
  2. `snapshot_date` **equals the date in the newest `docs/dogfood/<date>.md`
     filename.** Without (2) the guard is satisfiable by editing one frontmatter line;
     with it, satisfying the guard requires producing a new snapshot file.
- **D4 — the window is absolute, never relative.** A relative `--since` re-measures a
  different window each refresh, so comparability dies and a stale number can move
  *down*. Absolute ⇒ staleness only ever understates, which fails safe. Record the
  window in frontmatter.
- **D5 — an empty view is published as a finding, never faked and never padded.**
  Resolved 2026-08-02 mid-P0: `cage insights attrib` has **no real task-tagged data on
  this machine** — its only output is the `cage demo` seed. So the snapshot **omits
  attrib and says why**. Closing a task now to manufacture one would be an n=1 datum
  created in order to produce a number, which is the overclaim cage exists to refuse.
  **The absence is the headline, not the gap:** every starved surface
  (`compare`/`estimate`/`calibration`/net — and NET-1 itself) is starved for the same
  single reason, nobody runs `cage task outcome`. Write it as a finding with that
  pointer, in README line 53's voice — not as a footnote apology. A later snapshot
  re-adds attrib once real tasks are closed; NET-1 produces the first ten.

## 6. Non-negotiables

- **ZERO dummy data. The executing agent never runs a ledger command and never authors
  a number.** Every figure in a snapshot comes from P0's real output, pasted verbatim.
  If P0's output is missing, **STOP and ask** — do not seed a ledger, do not
  approximate, do not write a placeholder that the guard would accept.
- **Method tags survive verbatim.** A `modeled` stays labelled; gross keeps its gross
  note; `UNPRICED` is shown, not trimmed. Relay refusals unsmoothed — the refusals are
  the product.
- **Command allowlist for a snapshot: `cage report`, `cage insights attrib`,
  `cage insights adoption`.** Nothing else. Specifically **not** `cage insights chats`
  (chat titles) and **not** `cage report --project` (working-dir basenames) — this repo
  is public and both leak private project names.
  **Per D5, `attrib` is additionally omitted from this snapshot** — the allowlist is a
  maximum, not a requirement, and a view with no real data is published as a stated
  absence rather than a seeded table.
- **`$0` / stdlib-only.** The guard test parses frontmatter with stdlib string handling
  or the existing helpers; no YAML dependency, no new import.
- **Determinism:** nothing here is read by a derived view. The guard lives in its own
  test module and must not touch golden or determinism suites.
- **Do not touch:** `cage/` (any module), `data/`, the goldens, README line 53.
- **Steering files:** if CLAUDE.md needs a line, write
  `docs/claude-md-dogfood.proposed.md` and stop — never edit CLAUDE.md silently
  (the HR-CLAUDEMD / CC-CLAUDEMD precedent).

## 8. Edge cases & risks

- **R1 — the calendar time bomb (residual, accepted).** A date-based assertion fails on
  a boundary with no code change: `git bisect` and CI on an old tag both go red for a
  reason unrelated to the commit. **Mitigation, required:** the failure message must say
  so in plain words — *"this is a calendar-triggered freshness reminder, not a code
  regression; if you are bisecting or building an old tag, set
  `CAGE_SKIP_DOGFOOD_FRESHNESS=1`"* — and the env escape must work. This is a stated
  limit, in the GF-LAUNCHER tradition; do not attempt a clever fix.
- **R2 — an empty or missing `docs/dogfood/`.** The guard must **fail**, not skip. A
  green check that asserts nothing is worse than a red one (INTERVIEW, CI-GF lesson).
  This is why P0 runs first.
- **R3 — a future snapshot with a different table shape.** The guard reads frontmatter
  only, so shape drift is fine by construction. Do not parse the body.
- **R4 — two snapshots on the same date.** Reject at review time; one file per date.
