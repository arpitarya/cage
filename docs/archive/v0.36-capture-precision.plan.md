# Capture precision — fix cycle after Phase 1, then re-validate

**Plan of record** for the fixes Phase 1 surfaced, plus two standing directives
from Arpit (2026-07-28). Detail doc; the validation harness it feeds is
[cage-lab-golden-set.plan.md](cage-lab-golden-set.plan.md).

**Why this exists.** Phase 1 of the golden set ran real agents against real logs
and found cage's numbers wrong in two places and unobtainable in a third. Cage's
entire claim is that its numbers are exact where the source carries them and
honestly tagged where it doesn't. Every item below serves that claim.

**The governing principle, and the ceiling:** *cage can never be more precise
than its source.* Where a source carries real counts, cage must match it **to the
token**. Where it doesn't, the answer is `estimated`/UNPRICED **loudly** — never a
number dressed as measured. "Absolutely precise" is achievable as *never wrong*,
not as *always a number*.

## 2. What must not change

The fixes must not cost cage its existing guarantees:

- **Append-only.** No ledger row is ever mutated. (§3.1 is designed *around* this,
  not against it — see the reasoning in the ADR, #9.)
- **Determinism.** Same ledger + same policy ⇒ byte-identical output.
- **Idempotency.** Re-importing the same source adds zero rows.
- **`method` law.** A reconstructed or credit-derived number is never `measured`.
- **Counts never content.** Especially §3.2, where content and metadata share a
  row.
- **$0 / stdlib only.** `sqlite3` is stdlib — #2 does not break this.

## 3. The changes, specced

### 3.1 Copilot delta-id fix — HIGH

**Bug.** Copilot writes a *cumulative* `session.shutdown` per shutdown.
`parse_copilot_calls` derives the id as `c_cop{sid[:12]}{i:03d}` — session +
model index, no shutdown ordinal — so the second shutdown collides with the first
and is dedup-dropped. Measured: **16.5–18% undercount** (V3: 189,788 recorded vs
227,298 true).

**Fix.**

1. Id gains the shutdown ordinal.
2. **Ordinal 0 must produce byte-identical ids to today's scheme.**
3. Each row stores the **delta**: `cumulative_n − cumulative_{n−1}` per model.

**Why ord-0 identity is load-bearing** — it makes history self-heal:

```
already imported (legacy):  c_cop{sid}000 = 70,071
re-import after fix:        c_cop{sid}000 → same id, same value → dedupes, no change
                            c_cop{sid}<ord1> = 37,510 → appends
                            total 107,581 ✅ exact
import again:               0 new rows ✅ idempotent
```

A fresh id for ord 0 would add 70,071 twice. This is the part to review hardest.

**Also check:** whether `totalPremiumRequests` is cumulative — if so it needs the
same delta treatment (today it is stamped on the first model row only).

### 3.2 Kiro CLI SQLite parser — HIGH, gated on #0

Store: `~/Library/Application Support/kiro-cli/data.sqlite3`, table
`conversations_v2(key=cwd, conversation_id, value TEXT, created_at, updated_at)`.
Read with stdlib `sqlite3`, **read-only** (`file:…?mode=ro`, never write, never
migrate the DB).

Yields: real session ids (`conversation_id`), ms timestamps (a genuine `gap_ms`
source — kiro's first), `model_info.model_id`. Does **not** yield token counts —
`request_metadata.*` is null; usage is credits + `context_usage_percentage`.

### 3.3 Counts-never-content guard — HIGH, rides #2

The DB co-locates an `auth_kv` credentials table and every directory's full
conversation text with the metadata. The parser must read ids, timestamps, model
and numeric metadata **only** — never the `value` transcript body, never
`auth_kv`. A test must assert no prompt/response text can reach a ledger row.

### 3.4 Kiro credits as a non-call row — MED, rides #2

Kiro CLI reports **credits + context %**, not tokens. A call row with
`tokens_in=0` would be a lie that also poisons every average and cost-per-call.
Options, decided on **schema** grounds (this is the "separate by schema, not by
source" principle in action): a distinct row kind, or a receipt-style row with
`unit="credits"`, tagged `estimated` with its own confidence. Cost, if produced
at all, is credit-derived and **never `measured`**.

### 3.5 Surface-restamp collision fix — MED

A declared `[sources] surface` is silently lost when a declared source's rows
collide by derived id with a built-in source's. Silent loss of an explicit config
value, in the feature shipped to *stop* mislabeling. At minimum it must be loud;
better, the declared value should win.

### 3.6 `cage.toml` is the ONLY source of log paths — HIGH (new directive)

> **SCOPED 2026-07-28 (Arpit's call, plan §6):** this cycle lands only the
> **additive** parts — materialize an active `[sources]` table, the doctor drift
> check, and `cage setup --sync-sources`. **No resolution change**, so the
> re-run's V1/V2 byte-identical gate stays meaningful and a red cell can only
> mean the Copilot fix failed. The exclusive-authority flip (and the env
> (a)/(b) rule) moves to its own cycle:
> [config-authority.plan.md](config-authority.plan.md) Part 2, together with the
> `prices.toml` split.

**Today:** precedence is **env > policy `[sources]` > built-in registry**, and the
built-in defaults are emitted into a scaffolded config as an **inert comment
block**. Three places can decide a path.

**Directive:** paths come from `cage.toml` and nowhere else.

**Design.**

- `resolve_log_sources` reads **only** `cage.toml [sources]`. The built-in
  registry becomes a *seed*, not a runtime fallback.
- `cage setup` / `initcmd` materializes the defaults as an **active `[sources]`
  table** (not comments), for both the project and the global `~/.cage` config.
- A config with no `[sources]` table captures **nothing**, and says so loudly —
  silence here would look exactly like "capture is broken".

**The cost this introduces, and its mitigation.** Freezing defaults into a user's
file means a cage upgrade that adds or corrects a default path **no longer
reaches existing users** — the same silent-staleness class as the dead-verb bug.
So the change is only safe with:

- `cage doctor` **diffs the project's `[sources]` against the bundled defaults**
  and reports drift (missing new defaults, paths cage no longer ships);
- `cage setup --sync-sources` to refresh explicitly (never silent, never
  clobbering user-added entries).

**Open decision (§6):** env overrides. "No other place" implies removing them
from path resolution; the cost is that tests/CI currently redirect agent homes by
env, and would instead write a temp `cage.toml`. Default: **remove from path
resolution**, migrate tests. If any env var survives, `cage doctor` must announce
it — an invisible override defeats the directive.

### 3.7 Validation report: hash + copy into cage — MED (new directive)

Every generated `VALIDATION-REPORT.md` becomes tamper-evident and lives with
cage:

1. Compute **sha256** of the report; write it beside as
   `VALIDATION-REPORT.md.sha256`, and print it in the report's own header (the
   header hash covers the body — define and document which bytes are hashed).
2. **Copy into `cage/docs/regression/`**, dated:
   `<YYYY-MM-DD>-validation-report.md` + `.sha256`, plus `latest-validation-report.md`.
3. Add the index row (date · phase · cells · headline · **hash prefix**).
4. Append-only, exactly like the capture corpus: a new run never overwrites a
   previous dated report; a re-run of the same day gets a `-2` suffix.

Rationale: the report is the evidence behind release-to-release claims. A hash
makes "this is the report that produced those numbers" checkable, and the copy
means any agent working on cage reads the findings without the lab checked out.

## 4. Re-validation (the point of the cycle)

After the fixes, **re-run Phase 1** and compare against the recorded baseline.

### 4.1 Run order: FAILURES FIRST (Arpit, 2026-07-28)

The re-run is ordered by what the fixes targeted, not by cell number:

| order | cells | why first / last |
|---|---|---|
| **1st** | **V3 / V4 copilot** | the delta-id fix's direct target — the fastest possible verdict on whether it worked |
| **2nd** | **V5 / V5b kiro** | the SQLite-parser target (or the honest limit, if Step 0 said tokens are unrecoverable) |
| **3rd** | **V1 / V2 claude** | untouched path — a pure **regression check** that the fixes broke nothing |

**Gate between groups:** if a previously-failing cell **still fails**, stop and
report before running the rest. Re-running the green cells proves nothing while
the fix is still broken, and the calls are real money. The one exception: if the
failure is provably unrelated to the fix (a protocol or environment fault), note
it and continue.

Corollary: the claude cells are the *last* thing run, and their bar is
**byte-identical to baseline** — anything else means a fix leaked into a path it
had no business touching.

### 4.2 Expected results

| cell | before | expected after |
|---|---|---|
| V3/V4 copilot | 7/8 (check 5 ✗) | **8/8**; tokens_in 227,298 · 233,675 exactly |
| V5/V5b kiro | 4 & 5 ✗ | **rows appear** if #2 landed; token fields honestly absent/`estimated`; check 2 stays `◻ n/a` (§2.6a) |
| V1/V2 claude | 8/8 | **8/8, byte-identical numbers** — regression check on the untouched path |
| all | — | config provenance shows the **active `[sources]` table** from `cage.toml` (§3.6) |

Plus the **self-heal proof**, which cannot be skipped: re-import an *already
captured* Copilot session against the fixed parser and assert the total is
exactly the cumulative truth with **no** double count, then a third import adds
zero rows.

## 5. Acceptance

- Every red cell from the baseline is green **or** has a written reason it
  cannot be.
- No previously-green cell regressed; claude numbers byte-identical.
- `pytest -q` green in cage; append-only, determinism and idempotency tests
  unchanged in shape.
- The new report is hashed, copied into `docs/regression/`, and indexed.
- Findings that remain unfixable (Kiro tokens) are stated as limits with their
  method tag, not silently dropped.
