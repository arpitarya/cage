# Proposal — two debt rules, no big-bang

**PICKED UP 2026-08-01** — specced as
[structural-debt.handoff.md](../structural-debt.handoff.md) ·
[structural-debt.prompt.md](../structural-debt.prompt.md). Part 1 is a CLAUDE.md rule;
part 2 was re-scoped after its premise proved false (see the correction below). This
proposal stays as rationale until the work lands, then archives per the lifecycle.

## 1. `paths.py` (1,204 lines) — split on contact, never wholesale

The junk drawer: root resolvers · Footprint · log-source registry · kiro routing ·
shim/bin paths · bundled-data access. A wholesale split is high-risk (everything
imports it) for zero user value. Instead, a standing rule:

> **The next change that touches a `paths.py` concern moves that concern out with it.**
> Target seams, in likely order of contact: `routing.py` (kiro_routed + canonical_ledger
> + resolve_root precedence) · `logsources.py` (registry + resolve_log_sources + drift)
> · `agenthomes.py` (`claude_home`/`copilot_home`/`kiro_home` + the bundle env allowlist —
> **added 2026-08-01**: CODEX-OUT touches this seam but deliberately does *not* move it,
> because mixing a deletion with a move makes both unreviewable) · `footprint.py`. Pure moves with re-exports from `paths` — no behaviour change, no
> import breakage; `paths` shrinks to the actual path helpers.

Same fix-on-contact law the docs already live under. No OPEN-WORK item until a change
actually lands in one of those seams.

## 2. A bare-`cage` landing flow

> **⚠️ CORRECTED 2026-08-01 while writing the handoff: the premise below is wrong.**
> `cage` with no args does **not** print argparse usage — `cli._ROOT_HELP` is already a
> hand-written one-screen brief (daily verbs, grouped subcommands, five worked examples)
> and the parser's formatter returns it. The help is fine. What is actually missing is
> **state**: a user reads a good menu and still can't tell whether a ledger exists,
> whether capture ran, or whether anything is unpriced. Re-scoped to a **one-line state
> header above the unchanged help** — see
> [structural-debt.handoff.md](../structural-debt.handoff.md) §2.

38 subcommands; `cage` with no args today prints argparse usage. Proposal: a tiny
landing — ledger found or not · one-line state (N calls, last import, UNPRICED?) ·
the three next commands that matter (`setup` / `report` / `query "how does cage work"`).
Determinism note: bare `cage` becomes a *read* surface — stdout discipline applies;
capture-on-read stays off for it. One screen, no pager, exit 0.

**Reviewed 2026-08-01 (alongside CODEX-OUT): sound, no changes beyond the new
`agenthomes` seam.** The rule-not-project framing holds — a wholesale split is still
high-risk for zero user value, and CODEX-OUT is the first real test of "fix on contact"
(the verdict there: *don't* move, because a deletion and a move in one diff can't be
reviewed). Part 2 is untouched by any of it.

**Not proposed:** trimming the 38. The tiering + grouped help already carries it;
removal is a product decision per verb, not hygiene.

> `[capture] on_read`, throttled, fail-open, and escapable with `--no-import`. Part 2 is
> **declined**, not built: there is no gap left to fill, and the "bare `cage` must write
> nothing" acceptance criterion in the original handoff/prompt would have been a
